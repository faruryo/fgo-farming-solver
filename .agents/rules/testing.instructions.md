# Testing and Testability

テストの追加・修正・リファクタリング前に読むこと。新規コードだけでなく、変更対象の既存コードにも適用する。

## BLOCKER: 判断とI/Oを分離する

- フィルタ、並び順、上限、検証、整形、保持期間、同期判定などのドメイン判断は、可能な限り専用ファイルのpure関数へ切り出す。
- HTTP、filesystem、Cloudflare binding、localStorage、時刻、乱数、ブラウザAPIは呼び出し側の境界に残す。
- pureにできない境界は `now`、`random`、`env`、`storage`、`fetch` などを引数で渡す。import時に実環境を捕まえない。
- 大きな既存関数を触る場合、変更箇所の近くに埋もれたpureな判断を抽出してテストする。無関係な全体リファクタまでは広げない。

悪い例:

```ts
export const isExpired = (deadline: number) => Date.now() >= deadline
```

良い例:

```ts
export const isExpired = (deadline: number, now: number) => now >= deadline
```

## MUST: 該当するケースを選ぶ

すべてを機械的に増やすのではなく、変更の失敗モードに該当するものを選ぶ。

- 正常系
- エッジケース（珍しいが妥当）
- コーナーケース（複数のエッジが同時に成立）
- 境界値（最小・最大・直前・直後・off-by-one）
- 空（空文字列・空配列・空オブジェクト）
- `null` / `undefined`
- 不正・壊れた永続データ
- 期待するエラー
- 否定（起きてはいけない副作用）
- 回帰（過去に発生した具体的な事故）

静かに誤った値を返す処理を優先する。例外で即座に失敗する処理より、1件ずれた件数、誤った日付、緩すぎるvalidation、同期方向の逆転を先に守る。

## MUST: 新規テストが本当に赤くなることを確認する

新しい回帰テストは、次のいずれかを一時的に行い、テストが失敗することを確認してから元へ戻す。

- 修正した条件を反転する
- 追加したguardを一時的に外す
- 修正前の実装へ局所的に戻す

確認後は変更を必ず復元し、対象テストを再実行する。壊した状態でも通るテストは、意図した回帰を守っていない。

## WARNING: テスト例外

- `describe` / `it` の構造上、テストファイルは関数行数とnested callbackのlint対象外。ただし複雑度、型安全、アサーションの有無は対象のまま。
- mockはI/O境界に限定し、テスト対象の判断関数そのものをmockしない。
- 時刻、ID、乱数、外部レスポンスは固定し、実行時刻やネットワークに依存させない。
