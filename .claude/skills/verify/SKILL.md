# verify

## 実行する

```bash
pnpm type-check
pnpm vitest run
```

lint は pre-commit（husky + lint-staged）が見るので、ここでは実行しない。

## UI 変更を含むとき

`app/**`・`components/**` の UI を変更したときは、型チェックとテストに加えて、ブラウザの実画面で変更箇所を確認する。手順は `.agents/rules/ui-conventions.instructions.md` の「UI動作確認」に従う。

- dev server（`pnpm dev`）はユーザーが管理する。自分では起動・再起動しない。`curl` で `http://localhost:3000` の疎通を確かめる（3000 が 500 を返すときは 3001 も見る）。
- 動いている dev server がこの作業ツリーのコードを配信していることを確かめる。worktree で作業しているときは、別のチェックアウトの server を見ていないか注意する。
- `browser-use` で対象画面を開き、変更点の表示と挙動を確かめる。AGENTS.md の UI Verification に沿って、375px 幅、ホバー、localStorage 永続（リロード後の保持）のうち変更に関わるものを見る。

dev server が落ちている、この作業ツリーを配信していない、ブラウザを操作できない、のいずれかでブラウザ確認ができないときは、確認できなかったことと理由を報告して止まる。ユーザーには `! pnpm dev` での起動を頼む。確認を飛ばしてコミットしない。

## 失敗したとき

- 直し方が機械的に一つに決まる失敗（型エラー、import 漏れ、リネームの追従漏れ）は直す。直したら型チェックとテストの両方を再実行する。
- 次の直し方はしない。
  - テストの期待値を変える
  - テストを skip・削除する
  - `any` などで型を逃がす
- 判断が要る失敗（仕様の解釈が要る、ユーザーの変更を打ち消すことになる）と、環境由来の失敗（依存パッケージ不足、Vitest の起動失敗など）は直さない。失敗したコマンドと出力を報告して止まる。
