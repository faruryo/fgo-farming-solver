# preview-isolation Specification

## Purpose
未マージのプレビューが、本番の署名シークレットと本番ユーザーの保存データに到達できないようにする。プレビューは Worker Previews の専用 KV・D1 とシークレットで動き、本番の `main` デプロイは既存のリソースを使い続ける。

## Requirements

### Requirement: プレビューは本番のユーザーデータを読み書きしない

プレビューのホストは、本番のクラウド同期ストアと本番の履歴データベースを読み書きしてはならない (MUST NOT)。許可リストに入ったアカウントであっても、その本番データをプレビューから変更できてはならない (MUST NOT)。プレビューで保存した同期データと履歴は、本番の同じユーザー ID の保存データに現れてはならない (MUST NOT)。

#### Scenario: 本番にある履歴をプレビューは返さない

- **WHEN** あるユーザーの履歴が本番にあり、同じユーザー ID のセッションでプレビューの履歴を読む
- **THEN** レスポンスに本番の履歴は含まれない

#### Scenario: プレビューで書いた同期データは本番に出ない

- **WHEN** プレビューのセッションでクラウド同期の値を保存する
- **THEN** 本番の同じユーザー ID のクラウド同期にはその値が出ない

### Requirement: 本番ホストはプレビューログインの完了を拒否する

本番ホストは、プレビューログインの完了リクエストを拒否しなければならない (MUST)。引き渡しトークンの署名が正しく、audience が本番オリジンと一致し、nonce と許可リストと未使用の `jti` を満たしていても、セッションを発行してはならない (MUST NOT)。許可されたプレビューホストでの完了は、これまでどおりそのホストのセッションだけを書いてよい。

#### Scenario: プレビューの署名鍵で作ったトークンを本番へ送る

- **WHEN** プレビューが持つ引き渡しシークレットで署名したトークンを、本番の完了ルートへ送る
- **THEN** 本番はセッションを発行しない

#### Scenario: 許可されたプレビューホストでは完了する

- **WHEN** audience がそのプレビューホストのオリジンである引き渡しトークンを、許可されたプレビューホストの完了ルートへ送る
- **THEN** そのプレビューホストにセッション Cookie を書く

### Requirement: プレビューのセッションは本番で通用しない

プレビューがセッション Cookie の署名に使うシークレットは、本番の署名シークレットと異なる値でなければならない (MUST)。プレビューの署名で作ったセッション Cookie を本番ホストへ送っても、本番はログイン済みとして扱ってはならない (MUST NOT)。

#### Scenario: プレビュー発行の Cookie を本番が拒否する

- **WHEN** プレビューホストで発行したセッション Cookie を、本番ホストの認証が必要な API へ送る
- **THEN** 本番はそのリクエストをログイン済みとして処理しない

### Requirement: Google のクライアントシークレットは本番のコード交換だけが持つ

Google のクライアントシークレットは、本番ホストの認可コード交換だけが使えなければならない (MUST)。プレビューの実行環境はその値を持ってはならない (MUST NOT)。プレビューは認可コードを Google と交換してはならない (MUST NOT)。

#### Scenario: プレビューはコードを交換しない

- **WHEN** プレビューホストが認可コードを受け取る
- **THEN** プレビューはそのコードで Google のトークンエンドポイントを呼ばない

### Requirement: プレビューは本番のマスターデータを書き換えない

プレビューからの書き込みは、本番が配信に使うマスターデータに反映されてはならない (MUST NOT)。プレビューがマスターデータの複製を読むことは許される。

#### Scenario: プレビューからの書き込みが本番のドロップ率を変えない

- **WHEN** プレビューの実行環境がマスターデータ用ストアへ値を書く
- **THEN** 本番のドロップ率とサーヴァント一覧はその値に変わらない

### Requirement: fork の PR は本番リソース付きのプレビューを作らない

このリポジトリへブランチを push できない pull request では、プレビューをビルドしてはならない (MUST NOT)。本番のシークレットまたは本番のユーザーデータストアを束縛したプレビューを、その pull request から作ってはならない (MUST NOT)。

#### Scenario: fork からの pull request

- **WHEN** このリポジトリの fork から pull request が開かれる
- **THEN** その pull request 向けのプレビューは作られない

### Requirement: 本番ブランチのデプロイは本番リソースのまま

本番ブランチのデプロイは、これまでどおり本番のクラウド同期ストア、本番の履歴データベース、本番の署名シークレットを使わなければならない (MUST)。プレビュー分離のために本番の保存先を空のストアへ付け替えてはならない (MUST NOT)。

#### Scenario: main のデプロイ後も本番データが読める

- **WHEN** 本番ブランチのデプロイが完了したあと、既存ユーザーが本番ホストで履歴を読む
- **THEN** 分離前からあるそのユーザーの履歴が返る

### Requirement: プレビューのマスターデータは本番の定期更新に追従する

マスターデータの定期更新は、本番のマスターデータ用ストアを更新したあと、アプリが読むマスターデータのキーについて、本番に今ある値をプレビュー用のマスターデータ用ストアへ写さなければならない (MUST)。プレビュー用の値が本番と同じキーは書いてはならない (MUST NOT)。本番に値の無いキーは、プレビュー用から消してはならない (MUST NOT)。写す処理は本番のストアへ書いてはならず (MUST NOT)、書き込み先が本番のストアであれば書かずに失敗しなければならない (MUST)。アプリが読むマスターデータ以外のキー（更新処理だけが使うキャッシュを含む）を写してはならない (MUST NOT)。写すのに失敗したときは、その回の定期更新を失敗として示さなければならず (MUST)、本番への書き込みを取り消してはならない (MUST NOT)。

#### Scenario: 本番の素材カタログが更新された

- **WHEN** 定期更新が本番の素材カタログを新しい値に書き換えた
- **THEN** 同じ回のうちに、プレビュー用のストアの素材カタログも同じ値になる

#### Scenario: 更新処理が値を書かなかったキー

- **WHEN** 定期更新で値が変わらず本番に書かれなかったキーがあり、プレビュー用のストアにはそのキーが無い
- **THEN** そのキーも本番の値でプレビュー用のストアに入る

#### Scenario: プレビューと本番が同じ値

- **WHEN** あるキーのプレビュー用の値が本番と同じ
- **THEN** そのキーはプレビュー用のストアに書かれない

#### Scenario: 書き込み先が本番のストアになっている

- **WHEN** 写す処理の書き込み先が本番のマスターデータ用ストアを指している
- **THEN** 写す処理は何も書かずに失敗し、本番の値は変わらない

#### Scenario: 写すのに失敗した

- **WHEN** プレビュー用のストアへの書き込みが失敗した
- **THEN** その回の定期更新は失敗として示され、本番に書いた値はそのまま残る
