## Requirements

### Requirement: 計算履歴の保存
システムは、ログインユーザーの周回計算実行時に、計算結果と対象クエストの要約を D1 の `farming_results` に保存しなければならない (SHALL)。

#### Scenario: 計算結果の保存
- **WHEN** ユーザーが周回計算を実行したとき
- **THEN** 結果 ID・目的・対象アイテム・合計AP・合計周回数・結果データ・対象クエスト要約（`quest_selection`）が保存される。

#### Scenario: 対象クエスト要約の非正規化
- **WHEN** 計算結果を保存するとき
- **THEN** `quest_selection` には全クエスト数・選択数・「選択/除外のうち少ない側」のクエスト名一覧（エリア名付き、上限あり）が短縮IDではなく**名前で**保存される。
- **THEN** 保存時に現データへ解決できない選択IDは選択数に数えない。

### Requirement: 計算履歴の一覧表示
システムは、ログインユーザー自身の有効な（削除されていない）計算履歴を新しい順に一覧表示しなければならない (SHALL)。日時は保存されている UTC 日時を正確に解釈し、閲覧端末（クライアント）のローカルタイムゾーンで整形表示しなければならない (SHALL)。

#### Scenario: 履歴一覧の取得
- **WHEN** ログインユーザーが履歴ページを開いたとき
- **THEN** 削除されていない自身の履歴のみが新しい順（上限50件）で返される。

#### Scenario: 日時のクライアントタイムゾーン表示
- **WHEN** 履歴一覧の日時を表示するとき
- **THEN** 保存された UTC 日時が確実に UTC として解釈され、クライアント端末のローカルタイムゾーンに変換された日時が表示される。

#### Scenario: 対象クエストの表示
- **WHEN** 履歴行に `quest_selection` が存在するとき
- **THEN** 「選択数/全体数」が表示され、全選択でない場合は除外（または選択）クエストの一覧を展開して確認できる。
- **WHEN** `quest_selection` が NULL（本機能導入前のデータ）のとき
- **THEN** 対象クエスト欄はプレースホルダ（`—`）を表示し、エラーにならない。

### Requirement: 計算履歴の論理削除
システムは、ユーザーが自身の計算履歴を論理削除できる手段を提供しなければならない (SHALL)。削除は物理削除ではなく `deleted_at` の設定により行い、データは復元可能な形で保持される。`batch_id` を持つ2目標ペアの削除は、batch_id 単位で目標A・目標B両方を同時に論理削除する(A/B連動削除) SHALL。

#### Scenario: ペア(batch)の連動削除
- **WHEN** ログインユーザーが `batch_id` を持つ集約カードの削除を確認ダイアログで承認したとき
- **THEN** 同一 `batch_id` を持つ目標A・目標B両行の `deleted_at` に現在時刻が設定され、片肺状態は生じない。

#### Scenario: 単独行の削除
- **WHEN** ログインユーザーが `batch_id` を持たない履歴行の削除ボタンを押し、確認ダイアログで承認したとき
- **THEN** 該当行の `deleted_at` に現在時刻が設定され、履歴一覧と全ての履歴由来グラフ(履歴ページ・結果ページ・ダッシュボード)から除外される。

#### Scenario: 共有リンクの維持
- **WHEN** 論理削除済みの結果ページ URL(`/farming/results/[id]`)に直接アクセスしたとき
- **THEN** 結果ページは引き続き閲覧できる(共有済みリンクを壊さない)。

#### Scenario: 所有者以外による削除の拒否
- **WHEN** 未ログインで削除 API を呼び出したとき
- **THEN** 401 が返される。
- **WHEN** 他ユーザーの結果 ID・存在しない ID・削除済み ID に対して削除 API を呼び出したとき
- **THEN** 404 が返され、データは変更されない。

### Requirement: ストック込み計算のフラグ記録と badge 表示

システムは周回ソルバーの計算パラメータ(`Params`)に `stockIncluded?: boolean` を保持 SHALL。余剰ストックを含めた目標で解いた計算は `stockIncluded=true` を記録する。計算履歴/結果は解いた目標(`params.items`)をそのまま(as-solved)表示し、育成目標とストック目標を並列保存・並列表示しない SHALL。`stockIncluded=true` の履歴には「ストック込み」badge を表示する SHALL。後方互換のため、`stockIncluded` 未設定の既存履歴は false(badge なし)として扱う SHALL。

#### Scenario: ストック込み履歴に badge
- **WHEN** `stockIncluded=true` で保存された計算を履歴/結果で表示する
- **THEN** 「ストック込み」badge が表示される

#### Scenario: 通常履歴は badge なし
- **WHEN** `stockIncluded` が false または未設定の計算を表示する
- **THEN** badge は表示されず、解いた目標がそのまま表示される

#### Scenario: 既存履歴の後方互換
- **WHEN** `stockIncluded` フィールドを持たない既存の保存データを表示する
- **THEN** エラーなく false 扱いとなり badge は表示されない

### Requirement: 2目標の batch 連結保存

システムは2目標(必要分/ストック込み)計算時に、目標A・目標Bを `farming_results` の**2行**として保存し、新規カラム `batch_id`(同一の UUID)で連結しなければならない (SHALL)。目標A行は `stockIncluded=false`(KPIアンカー)、目標B行は `stockIncluded=true` とする。単一目標計算(`stockEnabled=OFF` または `B==A`)では `batch_id` を NULL とし、従来どおり1行で保存 SHALL。

#### Scenario: 2目標は batch_id で連結された2行になる
- **WHEN** 2目標(必要分/ストック込み)で周回計算を実行したとき
- **THEN** 同一 `batch_id` を持つ2行が保存され、目標A行は `stockIncluded=false`、目標B行は `stockIncluded=true` を持つ。

#### Scenario: 単一目標は batch_id なしの1行
- **WHEN** `stockEnabled=OFF` または目標Bが目標Aと一致して単一目標で計算したとき
- **THEN** `batch_id` が NULL の1行のみが保存される。

#### Scenario: 着地は目標A行
- **WHEN** 2目標計算の完了後に結果ページへ遷移するとき
- **THEN** 目標A行(KPIアンカー)の結果ページに着地し、目標Bは同ページ内から参照できる。

### Requirement: batch ペアの集約表示

システムは履歴一覧および結果ページにおいて、同一 `batch_id` を持つ目標A・目標Bを**1つのカード/ビューに集約**して表示しなければならない (SHALL)。集約表示では目標A(必要分)を主、目標B(ストック込み)を従とし、両者の差分(上乗せ周回数/AP)を視認できるようにする。目標B行には「ストック込み」badge を表示 SHALL。

#### Scenario: 履歴一覧でペアを集約
- **WHEN** 同一 `batch_id` を持つ目標A・目標Bが履歴一覧に存在するとき
- **THEN** 両者は1カードに集約され、「必要分」と「+ストック(差分 +Δ)」が並べて表示され、目標B側に「ストック込み」badge が付く。

#### Scenario: 結果ページで A/B 切り替え
- **WHEN** `batch_id` を持つ結果ページを開いたとき
- **THEN** 兄弟行(目標A/目標B)を取得し、`[必要分 | +ストック]` のタブで切り替えて表示できる。

### Requirement: batch_id 後方互換

システムは `batch_id` が NULL の既存行(本機能導入前のデータ、および単一目標計算)を、エラーなく**単独カード**として表示しなければならない (SHALL)。旧 `stockEnabled=ON` で保存された既存行(buffer 焼き込み済み・`stockIncluded=true`)は、目標Aを復元せず単独のまま「ストック込み」badge付きで据え置き SHALL。

#### Scenario: batch_id NULL の単独表示
- **WHEN** `batch_id` が NULL の行を履歴一覧/結果ページで表示するとき
- **THEN** ペア集約・A/Bタブは適用されず、従来どおり単独カードとして表示され、エラーにならない。

#### Scenario: 旧ストック込み行の据え置き
- **WHEN** 本機能導入前に `stockEnabled=ON` で保存された行(`stockIncluded=true`・`batch_id=NULL`)を表示するとき
- **THEN** 目標Aへのレトロ変換は行わず、単独カードとして「ストック込み」badge付きで表示される。

### Requirement: 計算履歴推移グラフの日時とタイムゾーン処理
システムは、計算履歴推移グラフにおける期間フィルタリング、回帰直線計算、X 軸目盛り、ツールチップ表示において、各履歴の保存日時（UTC）を正確に解釈し、クライアント端末のローカルタイムゾーンに即して表示・集計しなければならない (SHALL)。

#### Scenario: グラフの日時表示とツールチップ
- **WHEN** 計算履歴推移グラフの X 軸目盛りまたはデータポイントのツールチップを表示するとき
- **THEN** 履歴の保存日時が UTC として解釈され、クライアント端末のローカルタイムゾーンに基づく日付および時刻が表示される。

#### Scenario: 期間フィルタリングと達成予想日
- **WHEN** ユーザーが期間（1ヶ月、3ヶ月等）を切り替えたとき、または目標達成予想日を算出するとき
- **THEN** 履歴の UTC タイムスタンプに基づき正確に期間内データが抽出され、クライアント端末のローカル日付で予想日が表示される。

### Requirement: 計算結果の公開・非公開設定
システムは、周回計算結果の公開・非公開（`is_public`）をユーザーごとに選択・管理できる手段を提供しなければならない (SHALL)。

#### Scenario: ログインユーザーの新規結果保存時の既定値適用
- **WHEN** ログインユーザーが周回計算を実行して結果を保存するとき
- **THEN** ユーザーの端末設定（localStorage）で選択された既定の公開設定（公開または非公開）に従って保存される。端末設定の初期値は「公開」とする。

#### Scenario: 未ログインユーザーの結果保存
- **WHEN** 未ログインユーザーが周回計算を実行して結果を保存するとき
- **THEN** 結果は常に「公開」として保存される。

#### Scenario: 未ログインユーザーによる非公開計算要求の拒絶（fail-closed）
- **WHEN** 未ログインユーザーが非公開設定（`isPublic=false`）を指定して周回計算 API を呼び出したとき
- **THEN** 401 Unauthorized エラーを返却して公開保存されるのを防止する。

#### Scenario: 認証状態読み込み中の周回計算送信抑止
- **WHEN** セッション認証状態の判定中（loading）であるとき
- **THEN** 周回計算の送信は抑止され、認証確定後に認証状態に応じた公開設定（未ログイン時は常に公開、ログイン時は端末設定値）で送信される。

#### Scenario: 2目標ペア保存時の公開設定連動
- **WHEN** 2目標（必要分/ストック込み）の計算結果（同一 `batch_id` を持つペア）を保存するとき
- **THEN** 目標A行・目標B行の両方に同一の公開設定が適用されて保存される。

#### Scenario: 結果画面での所有者による公開・非公開切り替え
- **WHEN** ログインユーザーが自身が所有する結果のページ（`/farming/results/[id]`）を開いたとき
- **THEN** 公開・非公開を切り替えるスイッチが表示され、操作によって結果の公開状態が即座に更新される。
- **WHEN** 切り替え対象の結果が `batch_id` を持つペアであるとき
- **THEN** 同一 `batch_id` を持つ両方の行の公開状態が連動して更新される。

#### Scenario: 所有者以外の結果画面での切り替え非表示
- **WHEN** 未ログインユーザーまたは所有者以外のユーザーが公開された結果のページを開いたとき
- **THEN** 公開・非公開を切り替えるスイッチは表示されない。

#### Scenario: 論理削除済みの結果における所有者の公開設定切り替え
- **WHEN** 計算履歴から論理削除された結果のページを所有者が開いて公開設定を切り替えたとき
- **THEN** 正常に公開・非公開が更新され、非公開に設定された場合は即座に第三者から閲覧不可となる。

#### Scenario: 公開結果でのツイートボタン表示
- **WHEN** 結果が公開状態（`is_public = 1`）であるとき
- **THEN** 結果画面にツイートボタンが表示され、共有が可能である。

#### Scenario: 非公開結果でのツイートボタン非表示
- **WHEN** 結果が非公開状態（`is_public = 0`）であるとき
- **THEN** 結果画面にツイートボタンは表示されない。

### Requirement: 計算結果の閲覧アクセス制御
システムは、非公開に設定された計算結果へのアクセスを所有者本人のみに制限しなければならない (SHALL)。

#### Scenario: 公開結果の閲覧
- **WHEN** 公開状態（`is_public = 1`）の結果ページ URL（`/farming/results/[id]`）にアクセスしたとき
- **THEN** ログインの有無やユーザーによらず、誰でも結果を閲覧できる。

#### Scenario: 所有者による非公開結果の閲覧
- **WHEN** 非公開状態（`is_public = 0`）の結果の所有者（ログイン中本人）が該当ページ URL にアクセスしたとき
- **THEN** 結果ページが正常に表示される。

#### Scenario: 所有者以外による非公開結果へのアクセス拒否
- **WHEN** 未ログインユーザーまたは所有者以外のログインユーザーが非公開状態（`is_public = 0`）の結果ページ URL にアクセスしたとき
- **THEN** 結果が存在しない場合と同様に 404（Not Found）が返される。

#### Scenario: 既存データの公開維持（後方互換）
- **WHEN** 本機能導入前に保存された既存の計算結果（`is_public` カラムがマイグレーション時の既定値 1 または NULL 扱い）にアクセスしたとき
- **THEN** 公開状態として扱われ、共有済みリンクは引き続き誰でも閲覧できる。

### Requirement: 未ログイン時の計算履歴の導線と取得
計算履歴はログインユーザーだけの機能なので、システムは未ログインのユーザーに計算履歴への導線を表示してはならず (SHALL NOT)、計算履歴の取得も送信してはならない (SHALL NOT)。ログイン状態の確認が終わるまでは、導線を表示せず取得も送信しない (SHALL NOT)。ログインユーザーへの表示と取得は変えない。

#### Scenario: 未ログイン時のナビゲーション
- **WHEN** 未ログインのユーザーがナビゲーションメニューを開いたとき
- **THEN** 「計算履歴」の項目は表示されない。

#### Scenario: 未ログイン時の周回結果画面
- **WHEN** 未ログインのユーザーが周回計算の結果ページを開いたとき
- **THEN** 「計算履歴」へのボタンと計算履歴の推移グラフは表示されない。
- **THEN** 計算履歴の取得は送信されない。

#### Scenario: 未ログイン時のダッシュボード
- **WHEN** 未ログインのユーザーがダッシュボードを開いたとき
- **THEN** 「計算履歴」へのリンクと計算履歴の推移グラフは表示されない。
- **THEN** 計算履歴の取得は送信されない。直近の計算結果は、この端末に記録された結果の URL があればそこから読み込む。

#### Scenario: 未ログインで計算履歴ページを直接開く
- **WHEN** 未ログインのユーザーが計算履歴ページの URL を直接開いたとき
- **THEN** 計算履歴の取得は送信されず、計算履歴はログインすると使えることと、ログイン画面（`/cloud`）への導線が表示される。

#### Scenario: ログイン状態の確認中
- **WHEN** ログイン状態の確認が終わっていないとき
- **THEN** 「計算履歴」への導線と推移グラフは表示されず、計算履歴の取得も送信されない。
- **THEN** ダッシュボードの直近の計算結果は読み込み中として扱い、確認が終わってから読み込む。
- **THEN** 確認が終わってログインユーザーと分かった時点で、導線を表示し、計算履歴を取得する。

#### Scenario: ログインから未ログインに変わる
- **WHEN** セッションの失効や別タブでのサインアウトで、表示中にログインユーザーから未ログインに変わったとき
- **THEN** 「計算履歴」への導線と推移グラフは消え、計算履歴から得た直近の結果と件数は破棄される。
- **THEN** ダッシュボードの直近の計算結果は、この端末に記録された結果の URL からだけ読み直す。

#### Scenario: ログインユーザー
- **WHEN** ログインユーザーがナビゲーション・周回結果画面・ダッシュボード・計算履歴ページを開いたとき
- **THEN** 「計算履歴」への導線と推移グラフはこれまでどおり表示され、計算履歴を取得する。
