# Proposal

## Why

ロトの無い交換所イベントの交換所の周回計算で入れた値（ドロップ増加礼装の「1ドロップにつき +N」、品目ごとの交換回数、通貨ごとの所持数）は画面を開いている間だけ持つので、ページを読み込み直すたびに 0 に戻り、利用者は会期中に何度も入れ直すことになっている（#212、2026-11-02 のオーナーの判断）。この3つをイベントごとに端末へ保存し、開き直しても残るようにする。

## What Changes

- 交換所の周回計算の3つの入力（通貨とイベントポイントの品目ごとのボーナス、品目ごとの交換回数、通貨ごとの所持数）を、イベントごとに端末に保存し、同じイベントの交換所を開き直したときに戻す。別のイベントの交換所には使わない
- 交換回数は、交換所の並びの位置ではなく、品目を見分ける組（獲得物がアイテムかサーヴァント扱いか・獲得物の番号・対価の通貨・同じ組の中での並び）で保存する。取り込み直しで並びが変わっても別の品目に当たらないようにし、今の交換所に無い品目の保存値は使わない
- 保存値が壊れているとき（形が違う、数でない、負の数など）は、その値を空（0）として読み、画面を落とさない
- 「全部交換」「不足素材のみ」の操作は今までどおり交換回数を置き換え、置き換えた結果も保存する
- 今の仕様の「交換回数は保存しない」（計画の対象外の品目の要る・要らない）と、交換所のボーナスの「保存してはならない」を書き換える
- 箱のあるイベントの箱計画の入力（ボーナスを含む）は今までどおり保存しない。この変更は交換所の周回計算だけを対象にする
- 保存は端末だけとし、クラウド同期には載せない。終わったイベントの保存値は消さない

## Capabilities

### New Capabilities

- `event-shop-saved-inputs`: 交換所の周回計算の入力（ボーナス・交換回数・通貨の所持数）を、イベントごとに端末へ保存して戻す

### Modified Capabilities

- `event-drop-bonus`: 交換所のボーナスの入力を「保存しない」から「イベントごとに端末へ保存する」に変える。箱計画のボーナスの入力は保存しないまま、交換所の扱いを参照しない書き方に直す
- `event-shop-roster-need`: 計画の対象外の品目の要る・要らないの「交換回数は保存しない」を外し、開き直したときの交換回数を保存した値にする

## Impact

- `components/events/EventShopList.tsx` の交換回数・所持数・ボーナスの状態（今は `useState`）を、イベントごとの端末の保存に置き換える
- 交換回数のキーを品目を見分ける組にする変換を `lib/event-shop-summary.ts` に足す（計算の関数が使う添字のキーは変えない）
- 端末の保存のキーを `lib/constants/storage-keys.ts` に足す。クラウド同期・API・取り込みのデータ・表示の文言は変えない
- 箱計画（`components/events/EventPlannerClient.tsx`）は変えない
