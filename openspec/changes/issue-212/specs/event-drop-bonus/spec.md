## MODIFIED Requirements

### Requirement: ボーナスの入力
システムは、ロトの無い交換所イベントの交換所の周回計算に、交換所の通貨ごとと、イベントポイントの品目（そのイベントにあるとき）の「1ドロップにつき +N」を入れる欄を設けなければならない (SHALL)。値は 0 以上の整数とし、初期値は 0 とする (SHALL)。負の数・小数・数でない値は 0 以上の整数に直さなければならない (SHALL)。入れた値は、交換所の周回計算の入力の保存（event-shop-saved-inputs）に従い、イベントごとに端末に保存しなければならない (SHALL)。礼装の所持を入れる欄を設けてはならない (SHALL NOT)。欄の近くには、短い見出し（「ドロップ増加礼装」）と、何を入れると何が変わるか（例:「編成した礼装の 1ドロップにつき +N を入れると、1周の獲得量と周回数がボーナス込みになります」）を1行で示さなければならない (SHALL)。ボーナスをサーヴァントの効果として示してはならない (SHALL NOT)。

#### Scenario: 通貨とポイントの欄
- **WHEN** 交換所の通貨が3種類あり、イベントポイントの品目があるイベントを開いたとき
- **THEN** 3種類の通貨とイベントポイントの品目のそれぞれに、初期値 0 のボーナスの欄が表示される

#### Scenario: 見出しと説明
- **WHEN** 利用者が交換所の周回計算を開いたとき
- **THEN** ボーナスの欄の近くに「ドロップ増加礼装」の見出しと、入れると1周の獲得量と周回数が変わることを示す1行が表示される

#### Scenario: ポイントの品目が無いイベント
- **WHEN** イベントポイントの品目が無いイベントを開いたとき
- **THEN** ボーナスの欄は交換所の通貨の分だけ表示される

#### Scenario: 不正な値
- **WHEN** 利用者がボーナスの欄に -3 や 2.5 を入れたとき
- **THEN** 値はそれぞれ 0 と 2 として扱われる

#### Scenario: 交換所のボーナスを開き直したとき
- **WHEN** 利用者があるイベントの交換所で、ある通貨のボーナスに 2 を入れたあと、ページを読み込み直したとき
- **THEN** その通貨のボーナスの欄は 2 のままで、1周の獲得量と周回数はボーナス込みで表示される

### Requirement: 箱計画のボーナスの入力
システムは、箱のあるイベントの箱計画の入力の欄に、箱を開ける通貨の「1ドロップにつき +N」を入れる欄を設けなければならない (SHALL)。交換所の対価の通貨の欄を設けてはならない (SHALL NOT)（箱計画の周回の計算は、箱を開ける通貨だけを集める量として解くので、ほかの通貨のボーナスは結果に効かない）。欄の見出し（「ドロップ増加礼装」）と値の扱い（0 以上の整数、初期値 0、負の数・小数・数でない値は 0 以上の整数に直す）は、交換所のボーナスの入力と同じでなければならない (SHALL)。欄の近くの説明の1行は、入れると周回数と AP がボーナス込みになることを示さなければならず (SHALL)、箱計画に出ない1周の獲得量に触れてはならない (SHALL NOT)。入れた値は画面を開いている間だけ持ち、保存してはならない (SHALL NOT)。交換所のボーナスの保存値を箱計画の欄に使ってはならない (SHALL NOT)。礼装の所持を入れる欄を設けてはならない (SHALL NOT)。周回クエストにドロップの統計が無く、1周あたりの獲得数を手で入れるときは、ボーナスの欄を出してはならない (SHALL NOT)。

#### Scenario: 箱の通貨の欄
- **WHEN** 箱を開ける通貨が1種類、交換所の対価の通貨が4種類あり、ドロップの統計がある箱のイベントを開いたとき
- **THEN** 箱計画の入力の欄に、箱を開ける通貨の初期値 0 のボーナスの欄だけが、「ドロップ増加礼装」の見出しと、周回数と AP がボーナス込みになることを示す説明の1行とともに表示され、交換所の対価の通貨の欄は表示されない

#### Scenario: 不正な値
- **WHEN** 利用者が箱計画のボーナスの欄に -3 や 2.5 を入れたとき
- **THEN** 値はそれぞれ 0 と 2 として扱われる

#### Scenario: 1周の獲得数を手で入れる箱計画
- **WHEN** 周回クエストにドロップの統計が無い箱のイベントを開いたとき
- **THEN** ボーナスの欄は表示されず、1周あたりの獲得数を手で入れる欄だけが表示される

#### Scenario: 画面を開き直したとき
- **WHEN** 利用者が箱計画のボーナスに 2 を入れたあと、ページを読み込み直したとき
- **THEN** ボーナスの欄は 0 に戻る
