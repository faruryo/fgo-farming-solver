# Proposal

## Why

絆トラッカーの「礼装の提案」は、自分のサーヴァントに付ける絆アップ礼装の組み合わせしか出さない。フレンドを選ぶときに、どの礼装を付けたサポートを探せば獲得絆がいちばん増えるかが分からない(オーナーの要望・2026-10-27、#186)。前提だった、提案を礼装の効く相手の条件に合わせる変更(#213)はマージ済み。

## What Changes

- 「礼装の提案」タブの自分の組み合わせの下に、フレンドのサポートのサーヴァントに付いていてほしい絆アップ礼装の上位3つを出す。
- 順位は、自分の組み合わせを決めたうえで、その礼装をフレンドが付けていたときに増える、選んだサーヴァント全員の1周の獲得絆の合計の多い順とする(#186 の本文の案)。
- フレンドの礼装の効果は、サポート時の増加率を持つ礼装ではその値を使う(カルデア・ティータイムは15%)。礼装の効く相手の条件と霊基再臨の段階の扱いは、自分の組み合わせと同じにする。
- フレンドのサーヴァントと礼装のコストは数えない。自身に効く礼装(フレンドのサーヴァント自身にしか効かない)は候補にしない。
- 上位3つは効果の種類で数え、同じ効果の礼装は自分の組み合わせと同じく言い換えとして並べる。
- 自分の組み合わせと同じ礼装をフレンドが付けたときも、効果は重なるものとして数え、重なるかの注記は出さない(オーナーの決定・2026-11-01、2026-11-09)。同じ効果の礼装のうち代表は、組み合わせの提案と同じく図鑑番号の最も小さい礼装にする。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `bond-tracker`: 礼装の提案に、フレンドのサポートに付いていてほしい絆アップ礼装の上位3つを出す要件を足す。

## Impact

- 変更: `lib/bond/craft-essence-advice.ts`(フレンドの礼装の順位を求める関数)、`components/bond/craft-essence-advisor.tsx`(上位3つの表示)、`locales/ja.json`・`locales/en.json`、各テスト。Material Catalog は #213 で入った項目(効く相手の条件・サポート時の増加率・対象)をそのまま使い、変えない。
- 対象件数: イベント限定でない絆アップ礼装59件のうち、フレンドの候補になるのはパーティ全体に効く58件で、自身に効く1件(英霊肖像:ダレイオス三世)が外れる。58件のうちサポート時の増加率を使うのは1件(カルデア・ティータイム、5%→15%)。効果の種類は、条件のない礼装で6種類(+50の英霊肖像9件、15%のティータイム1件、10%のランチタイム1件、5%の4件、2.5%の3件、2%の英霊極点21件)と、条件付きの礼装19件(20%の12件、10%の英霊逢魔7件。種類の数は選んだサーヴァントで変わる)。数えた方法: Atlas Academy の `export/JP/nice_equip.json`(2026-11-08 取得)を今の `distillBondUpCraftEssences` に通し、対象(パーティ全体・自身)・増加率・サポート時の増加率・固定の増加量・条件の有無で数えた。
- 範囲外: 自分の組み合わせをフレンドの礼装と合わせて選び直すこと、フレンドを2人以上数えること、フレンドのサーヴァント自身の獲得絆、イベント限定の絆アップ礼装、所持している礼装での絞り込み。
