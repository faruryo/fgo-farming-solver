# Design

## Context

「礼装の提案」タブ(`components/bond/craft-essence-advisor.tsx`)は、`lib/bond/craft-essence-advice.ts` の `adviseBondCraftEssences` で自分の組み合わせを求めて表示する。#213 で、Material Catalog の絆アップ礼装は効く相手の条件(`appliesTo`)、対象(`target`: パーティ全体か自身か)、サポート時の増加率(`supportRate`。自分で付けたときと違う礼装だけが持つ)を持つようになった。計算は、霊基再臨の段階ごとに条件を判定し、各サーヴァントは段階ごとの値の最大を数える。

この変更は、自分の組み合わせの結果を入力にして、フレンドの礼装を1枚足したときの増える量を種類ごとに求めて並べる。Material Catalog は変えない。

## ゲーム仕様の確認

確かめたこと(2026-11-08):

1. **フレンドのサポートに付いた絆アップ礼装は、自分のサーヴァントに効く**: データで確認した。ゲーム内での実測はしていない。
   - Atlas Academy の `nice/JP/equip/910`(カルデア・ティータイム)の絆の関数は対象が `ptFull`(味方全体＜控え含む＞)で、`followerVals`(サポートで付けたときの値)に `RateCount: 150` を持ち、効果文は「クエストクリア時に得られる絆を5%増やす(サポート時は15%増やす)[最大解放]」。サポートで付けた礼装が味方全体に効く前提のデータになっている。
   - `export/JP/nice_equip.json` で、サポート時に効かない礼装(例: セラピューティック・スパ)は効果文に「(サポート時は無効)」を持ち、`svals` に `ApplySupportSvt: 0` を持つ。候補にする礼装はどれもこの印を持たない(今の蒸留は `ApplySupportSvt` を持つ効果を読まないので、そもそも一覧に入らない)。
   - `followerVals` は候補のうちティータイムだけが持つ。`nice/JP/equip/330`(カルデア・ランチタイム)・`2124`(手稿の翼)・`2512`(英霊極点：蘆屋道満)の API でも無い。サポート時の値が自分で付けたときと同じ礼装では `followerVals` を省くものとして、#213 の蒸留と同じく `svals` の値を使う。
   - プレイヤーの報告: Yahoo!知恵袋 q10315369475(2025-05-23)のベストアンサーの追記に、他人のサポートを借りて自分でも礼装を付けた編成で「効果は重複(スタメン絆110%+、控え90%+)」とある(別々の礼装の組み合わせ)。#186 の 2026-10-28 のコメントで読んだ GamePress の解説にも「フレンドのサポートの絆礼装も自分の編成に効く」とある。
2. **自分とフレンドで同じ礼装を付けたときに効果が重なるか**: ゲーム内では未確認。オーナーの決定で重なる前提にした(下の「決めたこと」の1つ目)。
   - Yahoo!知恵袋 q14328223889(2026-05-20)の回答に「絆やQPにボーナスがかかる礼装はバラ×5枚と完凸1枚の性能が同じ」とあり、自分のサーヴァントに同じ礼装を複数付けたときは重なるとする報告がある。自分とフレンドの組み合わせについての記述ではない。
   - q10315369475 では、自分とサポートにティータイムを置いたときに重なるかの問いに「重複はしないと思います」という回答(冠位編成の文脈)と、重なるとする生成AIの回答があり、割れている。
   - データには絆の関数が `servantFriendshipUp` の1種類しかなく、フレンドポイントの礼装のような重ならない種類の区別(`friendPointUpDuplicate` と旅の始まり)が無いので、データからは決められない。
   - オーナーは「基本重なる想定で良い」と判断し(#186、2026-11-01)、重なる前提で数えて未確認の注記は出さないと決めた(#186、2026-11-09)。

## Goals / Non-Goals

**Goals:**

- 自分の組み合わせの計算と同じ規則(条件・段階・切り捨て)で、フレンドの礼装1枚の増える量を求める。

**Non-Goals:**

- 自分の組み合わせをフレンドの礼装と合わせて選び直すこと(例: ティータイムをフレンドに任せて自分の5%を別の礼装にする)。
- フレンドが2人以上いる編成、フレンドのサーヴァント自身の獲得絆。

## Decisions

### 判断点

なし。前の版の判断点1(自分の組み合わせと同じ礼装の扱い)は、オーナーが案A に決めた(#186、2026-11-09)。

### 決めたこと

- **自分の組み合わせと同じ礼装も重なる前提で数え、注記を出さない**: オーナーの決定(#186、2026-11-09)。典型的な編成ほど上位3つが自分の組み合わせと同じ礼装になる。〔キャスター〕のコスト16のサーヴァント3体・基本絆ポイント3,797・マスターレベル200(上限118)では、自分の組み合わせがカルデア・ランチタイム、カルデア・ティータイム、手稿の翼になり、上位3つも3つともこの3枚になる。採らなかった案: 同じ礼装を候補から外す案は、例の編成で最も効くサポート(+2,280・+1,710・+1,140)を1つも出せず、上位が全員に +5%・+2.5%・+2% の弱い礼装だけになる。重なる前提で数えて「重なるかは未確認」の注記を出す案は、オーナーが注記は要らないとした。

  画面のモック(上の例):

  ```text
  ┌ 礼装の提案 ─────────────────────────────────────────┐
  │ (サーヴァントの選択・マスターレベル・周回クエスト)        │
  │ ◇ 自分の組み合わせ                                    │
  │   A  カルデア・ランチタイム   全員に +10%      5,125   │
  │   B  カルデア・ティータイム   全員に +5%       5,125   │
  │   C  手稿の翼   〔キャスター〕に +20%          5,125   │
  │   1周の獲得絆の合計 15,375 / 礼装なしの合計 11,391     │
  │   コスト 84 / 118                                     │
  │                                                       │
  │ ◇ フレンドのサポートに付いていてほしい礼装              │
  │   1. 手稿の翼   〔キャスター〕に +20%                  │
  │        1周 +2,280(合計 17,655)                       │
  │   2. カルデア・ティータイム   全員に +15%(サポート時)    │
  │        1周 +1,710(合計 17,085)                       │
  │   3. カルデア・ランチタイム   全員に +10%               │
  │        1周 +1,140(合計 16,515)                       │
  │   フレンドのサーヴァントと礼装のコストは数えていません     │
  └───────────────────────────────────────────────────────┘
  ```

- **自分の組み合わせは変えずに上乗せで数える**: #186 の本文の案。自分の組み合わせとフレンドの礼装を合わせて選び直すと、上の表示(自分の組み合わせ)と下の表示の前提が食い違う。
- **各サーヴァントの段階は、フレンドの礼装を加えたうえで選び直す**: 自分の組み合わせと同じ数え方(段階ごとの値の最大)にそろえる。段階を自分の組み合わせで数えた段階に固定すると、自分の組み合わせに段階で効くかが変わる礼装が無いサーヴァント(数えた段階を示さない)の段階を決められず、段階で効く礼装の増える量を取りこぼす。段階の示し方も自分の組み合わせと同じ規則にする。
- **効果の種類の区別にコストを使わない**: フレンドの礼装のコストは数えないため、コストだけが違う礼装は入れ替えても結果が同じ。今の候補ではコストだけが違う同じ効果の礼装は無いので、表示は変わらない。
- **代表は種類の中で図鑑番号の最も小さい礼装にする**: 組み合わせの提案と同じ。前の版は、重なるかの未確認を避けるために自分の組み合わせに入っていない礼装を優先していたが、重なる前提に決まったので優先する理由が無くなった。自分の組み合わせと同じ礼装が代表になっても、どの礼装のサポートを探せばよいかは変わらない。
- **自身に効く礼装は候補にしない**: フレンドのサーヴァント自身にしか効かず、選んだサーヴァントの獲得絆は増えない。今の候補では英霊肖像:ダレイオス三世の1件。
- **増える量が0の種類は出さない**: 段階で条件に合っても、選び直した段階で値が変わらなければ増えない(例: 〔中立〕の礼装を、すでに〔ケモノ科〕の20%を数えた段階のAに足す)。3つに満たないときはある分だけ出す。
- **出す場所は「礼装の提案」タブの自分の組み合わせの下**: #186 の本文の想定。自分の組み合わせが示されないとき(コスト超過・コスト不明)は、上乗せの基準が無いので出さない。
- **増える量と、加えたときの合計を出す**: 自分の組み合わせの合計と並べて読めるようにする。

## Risks / Trade-offs

- [同じ礼装が実際には重ならなかった] → 上位3つが自分の組み合わせと同じ礼装のとき、示した増える量が得られない。オーナーは基本重なると判断した(#186、2026-11-09)。ゲーム内で重ならないと分かったら、同じ礼装を候補から外す(要件の1文の変更で済む)。
- [サポート時の値を持つ礼装が増えたのに `followerVals` を読み落とす] → #213 の蒸留が `followerVals` を読むので、データが来れば自動で使われる。
- [計算の重さ] → 候補はイベント限定でないパーティ全体に効く礼装だけで、1件ごとに選んだ最大5体×4段階の計算を1回するだけなので、自分の組み合わせの探索に比べて無視できる。
