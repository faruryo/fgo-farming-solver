## MODIFIED Requirements

### Requirement: ロト計画 UI
システムは、イベントの一覧（`/events`）と、イベントごとのイベントページ（`/events/[id]`）を提供しなければならない (SHALL)。一覧に載るイベントは「KV `event_data_json` に取り込まれたロト型イベント」と「イベント機能レジストリに登録されたイベント」の和集合とする。イベントページは、そのイベントで使える機能をセクションとして並べるハブとする。既存の恒常導線 (`/material` → `/farming`) は変更しない。一覧・イベントページは、URL 直打ち以外にアプリ内の常設導線（グローバルナビ等）から到達可能でなければならず (SHALL)、どのページもオーファン（到達不能）であってはならない (SHALL NOT)。画面上の名称は「イベント」「イベント一覧」とし、ロト型に限定した名称（「ボックスイベント」「ロトイベント一覧」）を一覧・ナビの見出しに用いてはならない (SHALL NOT)。

#### Scenario: イベント一覧
- **WHEN** ユーザーが `/events` を開いたとき
- **THEN** KV のロト型イベントとレジストリ登録イベントが、同一 ID の重複なく会期情報とともに「開催中・開催予定・終了済み」に分けて一覧表示される。
- **THEN** 各イベントには、そのイベントページで使える機能（例: 「ボックス計画」「料理作成」）がバッジで示される。

#### Scenario: KV に無いレジストリ登録イベント
- **WHEN** あるイベントが KV `event_data_json` に存在せず、イベント機能レジストリにのみ登録されているとき
- **THEN** 一覧にはレジストリの表示用メタ（名前・会期）で掲載され、イベントページも開ける。

#### Scenario: 一覧ページへの常設導線（オーファン禁止）
- **WHEN** ユーザーがアプリのどの画面からでもイベント機能を探すとき
- **THEN** グローバルナビゲーション（`components/common/nav.tsx`）に「イベント」の名称で `/events` 一覧への常設エントリが存在し、URL 直打ちなしで一覧ページへ到達できる。
- **AND** ダッシュボードからの個別イベント直行導線（`/events/[id]`）は一覧導線を代替せず、両者が併存する。

#### Scenario: ダッシュボードからのイベントページ導線
- **WHEN** ダッシュボードの開催中イベントカードのイベントが、イベントページに1つ以上の機能（ボックス計画または料理作成など）を持つとき
- **THEN** そのカードに `/events/[id]` への導線が表示される。
- **WHEN** イベントページに機能を1つも持たないイベントのとき
- **THEN** 導線は表示されない。

#### Scenario: 計画ページへの遷移
- **WHEN** ユーザーが一覧からイベントを選ぶ、またはダッシュボードの該当イベントから遷移したとき
- **THEN** そのイベントのイベントページ (`/events/[id]`) が開き、ヘッダー（名前・会期・開催状態）の下に、使える機能のセクションが表示される。

#### Scenario: 取り込みデータ未存在時の表示
- **WHEN** 対象イベントが KV にもイベント機能レジストリにも存在しないとき
- **THEN** イベントページはエラーにならず、データ未取得である旨のプレースホルダを表示する。

## ADDED Requirements

### Requirement: イベント機能レジストリ
システムは、イベント ID ごとにイベントページで使える機能と表示用メタ（名前・会期）を定義する静的レジストリを持たなければならない (SHALL)。レジストリに載せる情報は、ゲーム内で公開済みのイベント情報に限らなければならない (SHALL)。同一イベントが KV にも存在するとき、表示用メタは KV の値を優先しなければならない (SHALL)。

#### Scenario: 料理作成イベントの登録
- **WHEN** イベント 80614（水着2026）のイベントページを開いたとき
- **THEN** レジストリの登録に従って料理作成セクションが表示される。

#### Scenario: KV とレジストリの両方にあるイベント
- **WHEN** あるイベントが KV のロト型イベントであり、かつレジストリにも登録されているとき
- **THEN** 一覧・ヘッダーの名前と会期は KV の値で表示され、セクションはボックス計画とレジストリ登録機能の両方が表示される。

### Requirement: イベントページのセクション構成
システムは、イベントページにおいて、イベントが持つ機能ごとに独立したセクションを表示しなければならない (SHALL)。ボックス計画セクションは KV にロト型データがあるイベントでのみ、料理作成セクションはレジストリで料理作成が登録されたイベントでのみ表示しなければならない (SHALL)。各セクションの計算は既存の計算ロジックをそのまま用い、イベントページ化によって算出結果が変わってはならない (SHALL NOT)。

#### Scenario: ボックス計画セクション
- **WHEN** KV にロト型データがあるイベントのイベントページを開いたとき
- **THEN** 既存のボックス計画（入力モード・箱数・通貨・周回・AP内訳・育成インパクト・交換所上限警告）がボックス計画セクションとして表示される。

#### Scenario: 料理作成セクションの need は永続ロスター由来
- **WHEN** ロスター設定済みのユーザーが料理作成セクションを表示したとき
- **THEN** 料理作成アドバイザーは、永続ロスター（`ChaldeaState`＋所持数）から求めた育成必要数を、グローバルの周回目的・ストック目標設定に従った実効不足として受け取り、配分を計算する。
- **THEN** `ChaldeaState`・所持数・クラウド同期データは書き換えられない（read-only）。

#### Scenario: ロスター未設定時の料理作成セクション
- **WHEN** ロスター未設定のユーザーが料理作成セクションを表示したとき
- **THEN** 配分計算は行わず、育成対象を設定すると料理配分を算出できる旨と、その設定画面への導線を表示する。

#### Scenario: 機能を持たないセクションは出さない
- **WHEN** イベントが KV のロト型データを持たないとき
- **THEN** ボックス計画セクションは表示されない。
