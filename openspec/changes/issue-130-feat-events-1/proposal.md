# Proposal

## Why

ロトの無い交換所イベントの周回計算（#162・#165・#134）は、ボーナス（礼装・サーヴァントの「ドロップ1回ごとに +N」）を含まない素のドロップ統計で解くので、ボーナス礼装を編成して周回する利用者には、実際より多い周回数と AP が出る（issue #130、epic #129）。1周あたりに通貨とイベントポイントがいくつ手に入るかも、画面に出ていない。

## What Changes

- ロトの無い交換所イベントの交換所のセクションに、通貨ごとと、イベントポイントの品目の「1ドロップあたりのボーナス +N」の入力を足す。値は利用者が手で入れる（オーナーの判断。Atlas からの自動取り込みと礼装の所持の入力は作らない）
- クエストごとに、ボーナス込みの1周あたりの通貨とイベントポイントの獲得量を出す。1周の獲得量は「素の1周の期待値 + 1周あたりのドロップ回数 × N」
- 入れたボーナスを、交換所の周回計算（周回の内訳の周回数・合計 AP・通貨ごとの見込み獲得量）に反映する
- イベントデータの取り込みで、各ドロップの1周あたりのドロップ回数も保存する。取り込み直す前のデータ（回数が無い）では、ボーナスを反映できないことを示し、素の値で計算する
- ボーナスがすべて0のときは、今の周回計算と同じ結果を出す

## Capabilities

### New Capabilities
- `event-drop-bonus`: ロトの無い交換所イベントで、利用者が入れた「1ドロップあたり +N」のボーナスから、1周あたりの通貨とイベントポイントの獲得量を出し、交換所の周回計算に反映する

### Modified Capabilities
（なし。交換所の周回計算の既存の要件（`event-planner` の #128 の要件、#134 の `event-shop-ap-budget`）は書き換えず、ボーナスを入れたときの振る舞いを新しい capability に足す。`event-planner` は未 archive の change `issue-127-bug-events` が、`event-shop-ap-budget` は change `issue-134-feat-events-ap` が持っているため）

## Impact

- 前提: #134 の実装 PR #168 がマージ済みであること。画面は #168 の後の `components/events/EventShopList.tsx` の上に乗る
- `scripts/refresh-event-data.ts`（各ドロップの1周あたりのドロップ回数を保存する）と `lib/master-data/types.ts`（ドロップの型に任意の項目を足す）
- `lib/event-plan.ts`（ボーナス込みの1周の獲得量をソルバーの入力に使う）
- `components/events/EventShopList.tsx` と `app/events/[id]/page.tsx`（ボーナスの入力、1周の獲得量の表、ポイントの品目の受け渡し）
- `locales` の events の文言
- 本番の KV の値は、次の定期の取り込みで新しい項目を持つ。手で書き換えない
