## ADDED Requirements

### Requirement: 読み取った残りを保存する
システムは、スクリーンショットからの取り込み（`event-shop-remaining-import`）で確定した品目ごとの残りを、交換所の入力の一つとしてイベントごとに端末に保存しなければならない (SHALL)。残りは、交換回数と同じ品目を見分ける組に結び付けて保存し、まとめた行の品目でも通貨ごとの品目に保存しなければならない (SHALL)。同じイベントの交換所を開き直したときは、保存した残りを効く上限に使わなければならない (SHALL)。取り込み直しで品目の並びや在庫上限が変わっても、保存した残りを書き換えてはならず (SHALL NOT)、同じ組の品目に使わなければならない (SHALL)。今の交換所に同じ組の品目が無い残りは使ってはならない (SHALL NOT)。残りが効く上限を下げても、保存した交換回数を書き換えてはならず (SHALL NOT)、効く上限の回数として使わなければならない (SHALL)。残りを消す操作のあとは、そのイベントの残りを保存値から除かなければならない (SHALL)。残りは端末だけに保存し、クラウド同期の対象に含めてはならない (SHALL NOT)。

#### Scenario: 開き直しても残る
- **WHEN** 利用者が 80632 の交換所で、叡智の業火の残り 80 を取り込んで確定してから、ページを読み込み直したとき
- **THEN** 叡智の業火の上限は 80 のままで、全部交換で 80 回になる

#### Scenario: 並びが変わっても同じ品目に使う
- **WHEN** 利用者が品目 A の残り 3 を取り込んだあと、取り込み直しで品目 A の前に新しい品目が加わり、交換所を開き直したとき
- **THEN** 品目 A の上限は 3 で、新しい品目には残りが無い

#### Scenario: 残りを消すと前の回数に戻る
- **WHEN** 在庫上限 30 の品目に交換回数 20 が保存されていて、その品目の残り 5 を取り込んだあと、利用者が残りを消す操作をしたとき
- **THEN** 残りを取り込んでいる間は交換回数が 5 と表示され、消したあとは 20 と表示される

## MODIFIED Requirements

### Requirement: 壊れた保存値
システムは、交換所の入力の保存値が読めない形（形が違う、数でない、有限の数でない、負の数、小数など）のときに、画面を落としてはならない (SHALL NOT)。保存値全体が読めない形なら、そのイベントの入力を空（すべて 0、フレンドの礼装と選んだ行は選んでいないもの、残りはどの品目にも無いもの）として読まなければならない (SHALL)。フレンドの礼装の ☆ と選んだ行の合計枚数が 0 以上の整数（フレンドの礼装は「なし」も含む）でなければ、選んでいないものとして読まなければならない (SHALL)。一部の値だけが読めない形なら、その値を 0 として読み、ほかの読める値は使わなければならない (SHALL)。ただし残りは、品目ごとの値が有限の数でないか負の数なら、0（売り切れ）としてではなく、その品目の残りが無いものとして読まなければならない (SHALL)。小数は 0 以上の整数に切り捨て、残り以外の負の数は 0 として読まなければならない (SHALL)。

#### Scenario: 保存値全体が壊れている
- **WHEN** あるイベントの交換所の入力の保存値が、数や表として読めない文字列になっているときに、そのイベントの交換所を開いたとき
- **THEN** 画面は落ちず、交換回数・所持数・ボーナスはすべて 0 で表示され、どの品目にも残りは無い

#### Scenario: 一部の値が壊れている
- **WHEN** あるイベントの保存値で、ある品目の交換回数が文字列、ある通貨の所持数が -5、別の通貨の所持数が 120 になっているときに、交換所を開いたとき
- **THEN** その品目の交換回数は 0、所持数が -5 の通貨は 0、別の通貨の所持数は 120 として表示される

#### Scenario: 残りの値が壊れている
- **WHEN** あるイベントの保存値で、品目 A の残りが文字列、品目 B の残りが -1、品目 C の残りが 4.7 になっているときに、交換所を開いたとき
- **THEN** 品目 A と品目 B には残りが無く在庫上限が上限になり、品目 C の残りは 4 として使われる
