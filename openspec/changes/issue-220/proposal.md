# Proposal

## Why

ロトの無い交換所イベントの交換所の周回計算は、品目の交換できる回数を在庫上限（取り込んだ交換所データの値）だけで決めている。ゲームの中で一部を交換したあとは、品目ごとの「残り」の回数を見ながら交換回数を手で入れ直すしかなく、品目が十数行あると面倒（#220）。所持数の画面にはスクリーンショットをブラウザの中で OCR して取り込む機能（`possession-screenshot-import`）があるので、同じ部品で交換所の画面の「残り」を読み取り、上限として計算に使えるようにする。方針はオーナーが 2026-11-10 に決め（A1・B1・C と D は既定の案）、2026-11-11 に、同じ名前の品目を通貨ごとに見分ける方法を通貨のアイコンの画像照合にし、読み取った残りを品目名のポップアップで手で直せるようにすると決め直した。

## What Changes

- 交換所の周回計算の一覧の上（「全部交換」「優先素材」の並び）に「スクリーンショットから取り込む」の入口を足す。ゲームの交換所の画面のスクリーンショットを何枚か選ぶと、ブラウザの中で OCR して、行ごとの品目の名前・「残り N回」（「売り切れ」は 0）・対価の数を読む。画像は外に送らない
- 読み取った行を交換所の品目に当てはめる。名前と対価の数で品目を絞り、同じ名前・同じ対価の品目が通貨ごとにあるときは、対価の数の左に写った通貨のアイコンを切り出して 16×16 に縮め、その通貨の Atlas のアイコンと比べて一番近い通貨の品目に当てる。一番近い通貨と次の通貨の差が小さい行は「要確認」にする。1枚の画像の中の行の並びは照合の確かめにだけ使い、交換所の順と食い違う行も「要確認」にする。読めなかった行・当てはまらなかった行も「要確認」にする
- 取り込む前に、読み取った結果を品目ごとに確かめて直せる画面を出す。「要確認」の行は、利用者が品目と値の両方を決めるまで入れない。アイコンで当てた行は、切り抜いたアイコンと当てた通貨のアイコンを並べて出す。入れなかった品目の今の値は変えない
- 読み取った「残り」は、交換回数とは別に、品目ごとの上限として持つ。効く上限は在庫上限と残りの小さいほうにし、交換回数の入力の上限、「全部交換」、「優先素材」、複数の通貨の品目をまとめた行の上限と割り振り、全交換の合計、交換所で埋まらない不足の計算に使う。交換回数を手で入れる欄は残す
- 品目名のポップアップ（「欲しい／いらない」と「アイテム詳細 ↗」が並ぶもの）に、在庫上限のある品目の「残り」の入力を足し、読み取った残りを手で直したり、取り込まずに入れたりできるようにする。まとめた行では通貨ごとに入力を並べる
- 残りを、イベントごとにまとめて消せるようにする（上限を在庫上限だけに戻す）。消す操作は取り込みの入口と同じ並びに置く
- 「獲得したイベントアイテム」の通貨ごとの所持数も同じ取り込みで読み、数の左のアイコンを同じ照合で通貨に当てる。差が小さい数と、同じ通貨に2つ当たった数は「要確認」にする
- 残りは、交換所の入力の保存（`event-shop-saved-inputs`）に、交換回数と同じ品目の組に結び付けて端末に保存する

## Capabilities

### New Capabilities

- `event-shop-remaining-import`: 交換所の画面のスクリーンショットから品目ごとの残りと通貨ごとの所持数を読み取り、通貨のアイコンの照合も使って交換所の品目と通貨に当てはめ、取り込む前に確かめて直せること。品目名のポップアップで残りを手で直せること。残りを品目ごとの上限として周回計算に使うこと（効く上限）と、まとめて消せること

### Modified Capabilities

- `event-shop-saved-inputs`: 保存する値に品目ごとの残り（取り込んだものと手で入れたもの）を足し、交換回数と同じ品目の組に結び付けること。交換回数を効く上限で切り詰めて使うこと。残りの保存値が読めない形のときは残りが無いものとして読むこと

## Impact

- `lib/possession-import/ocr-engine.ts`: 今は文字だけを返す。行の切り出しに使うため、文字の枠（画像上の位置）も返す関数を足す。OCR のモデルは今までどおり初めて使うときに読み込む
- `lib/`（新しいモジュール）: OCR の結果から交換所の行を組み立てる処理、アイコンの画素を比べる処理、行を品目と通貨に当てはめる処理、通貨の所持数の読み取り。どれも OCR の結果や 16×16 の画素の配列を入力にした純粋な関数にして、画像なしでテストする。canvas に描いて画素を取る部分だけを分ける
- 外部への要求: 照合のために、交換所データの通貨のアイコン（`https://static.atlasacademy.io/JP/Items/<id>.png`、`access-control-allow-origin: *`）を、画像を選んだあとに取得する。利用者の画像は送らない
- `lib/event-shop-summary.ts`: 在庫上限を使う箇所（`clampExchangeCount`・`selectAllUpToLimit`・`splitRowCount`・`rowLimit`・`shortCount`・全交換の合計）が、残りのある品目では効く上限を使うようにする。保存値の形（`ShopSavedInputs`）と読み取り（`readShopSavedInputs`）に残りを足す
- `components/events/EventShopList.tsx`: 取り込みの入口・確かめの画面・残りを消す操作・行の上限の表示（残りと在庫上限）・品目名のポップアップ（`ItemWantPopover`）の残りの入力
- 箱のあるイベントの箱計画（`lib/event-plan.ts` の `allocateShop`）と、品目がすべてサーヴァント扱いの交換所の一覧は変えない
- 所持数の画面の取り込み（`possession-screenshot-import`）の挙動は変えない
- 取り込み・判定・絞り込みの条件（どの交換所データを取り込むか）は変えないので、対象の件数は数えない
