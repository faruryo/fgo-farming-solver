## Context

- 小窓の欄は `type="text"`・`inputMode="numeric"` で、打った文字をそのまま持ち、範囲は共有の読み方 `readField` で確かめる（`/^\d+$/` なので全角は範囲外）
- 確かめ画面の欄は `type="number"`。ブラウザの数の欄は `1e2` などを通し、文字を貼ると値が空になるなど、空と不正の区別がブラウザで違う（#286 の仕様で文字の欄を選んだ理由）
- オーナーの決定（2026-11-18）: 欄は Base UI の `NumberField`（`@base-ui/react` 1.4.1）で作る。仕様 PR の前の版にあった案 A〜C（文字の欄で自前に落とす・`type="number"`・`pattern`）はやめる

### NumberField の実測（2026-11-18）

`@base-ui/react` 1.4.1 の `NumberField.Root`（`min=1`・`max=120`、宝具Lv は `max=5`、`format={{ useGrouping: false }}`）を一時ページに置き、Playwright の headless Chromium で動かした。日本語入力は CDP の `Input.imeSetComposition`（変換中）と `Input.insertText`（確定）で再現した。表の「値」は `onValueChange` で受けた値。既定（丸める）と `allowOutOfRange` の両方で測った。

| 操作 | 既定（丸める） | `allowOutOfRange` |
|---|---|---|
| 空の欄に「Lv 90」を貼る | 貼り付けを無視。欄は空、値 `null` | 同じ |
| 値 90 の欄に「Lv 90」を貼る | 部品のコードでは数として読めない貼り付けは捨てる（`onPaste` で `preventDefault` し、読めたときだけ値を置く）ので 90 のまま | 同じ |
| 「９０」を貼る | 欄「９０」、値 90。欄を離れると「90」 | 同じ |
| 「90/90」を貼る | 値 90 | 同じ |
| 「1e2」を貼る | 値 100 | 同じ |
| 「1e2」「-5」を打つ | `e`・`-` はキー入力で弾かれ、12・5 | 同じ |
| 「1.5」を打つ | 値 1.5（整数に丸めない） | 同じ |
| 「abc」を打つ | 入らない。値 `null` のまま | 同じ |
| 121 を打つ | 欄は「121」のまま値は 120。Enter（フォームの送信）で 120 が送られ、欄を離れると「120」 | 値 121。欄は 121 のまま |
| 0 を打つ | 値 1。Enter で 1 が送られる | 値 0 |
| 宝具Lv に 6 を打つ | 値 5、欄を離れると「5」 | （測っていない。Lv と同じ扱いになるはず） |
| 欄を空にする | 値 `null`。Enter で `null` が送られる | 同じ |
| 日本語入力で「９」→「９０」と変換中、確定 | 変換中から欄「９０」・値 90。確定後も 90 | 同じ |
| 値 90 の欄を全選択し、日本語入力で「１００」に打ち替えて確定 | 値 100 | 同じ |
| 値 90 の欄を全選択し、日本語入力で「ｌｖ」を変換中、確定 | 変換中の文字は欄に入らず 90 のまま。確定しても 90 | 同じ |
| 値 90 の欄を全選択し、「きゅう」を変換中、「九」で確定 | 変換中は 90 のまま。確定で欄「90九」、漢数字として読まれ値 909 → 120 に丸める | 値 909 |
| 欄の `inputmode` / `type` | `numeric` / `text` | 同じ |

読み取れること:

- 全角の数字は打っても貼っても半角に直る。変換中も確定後も壊れず、自前の変換中・確定の処理は要らない
- 数でない文字（英字・ひらがなの変換中）は部品が欄に入れず、欄の値はそのまま残る。全角で打ち替えて欄が空になり保存値が消える、前の版で心配した経路は起きない。欄が空になるのは人が消したときだけ
- 「Lv 90」の貼り付けは 90 にならず、無視される（前の版の要件「Lv 90 → 90」は満たさない）。値は変わらないので黙って消えることはない
- 既定の丸めは、打っている途中に値だけを変える（121 は欄に「121」と出たまま 120 が送られる）。「九」の確定では 909 → 120 になる。どちらも本人が見ていない値が保存される
- 整数でない値（1.5）は部品が通すので、範囲の判定はこちらで持つ必要がある
- 実測は Chromium だけ。Safari の変換の確定の順序と、実機の数字キーボードは測っていない（tasks の人が行う確かめに残す）

## Goals / Non-Goals

**Goals:** 2つの画面の Lv・宝具Lv の欄を `NumberField` で作る。全角の数字も受け付ける。スマホで数字のキーボード。範囲外と整数でない値は今までどおり保存させない。

**Non-Goals:** 「Lv 90」のような数と文字の混じった貼り付けから数を取り出すこと。増減のボタンやスクラブ。ほかの数字の欄。範囲の変更。

## Decisions

### 判断点

#### 1. 範囲外の値の扱い — 推奨: 丸めずに赤枠で示し、保存させない（`allowOutOfRange`）

| 案 | 121 を打って Enter | 「九」の確定（909） | 1.5 | 今の仕様との差 |
|---|---|---|---|---|
| A. `allowOutOfRange` で丸めず、範囲外と整数でない値を赤枠にして保存・取り込みに入れない【推奨】 | 保存されない。赤枠で分かる | 保存されない。赤枠で分かる | 赤枠 | 無い |
| B. 部品の既定のまま最小・最大に丸める | 120 が保存される（欄は 121 と出たまま） | 120 が保存される | 別に判定が要る | 「範囲に無い値は保存できない」を書き換える |
| C. 打っている間は丸めず、欄を離れたときだけ丸める（自前で `onValueChange` を包む） | Enter が先なら丸め前の値の扱いを決め直す必要がある | 離れると 120 | 別に判定が要る | 書き換える |

根拠: A は、打ち間違い（121）や漢数字の確定（909）を本人が見ないまま 120 として保存する失敗を避けられ、範囲の要件と赤枠の見た目も #286 / #289 のまま使える。B は部品の既定に乗れて足すコードが一番少ないが、実測で欄の文字と送られる値が食い違う時間があり、Lv の打ち間違いが黙って上限になる。C は B の食い違いを減らすが、Enter で保存する経路と欄を離れる経路の順序を自前で持つことになり、薄い包みでなくなる。A で取りこぼすのは、範囲外を打った人が自分で直す手間（丸めればすぐ保存できた）。

### 決めたこと

- `components/ui/` に `NumberField` の薄い包み（`Root` と `Input` だけ、増減のボタンは置かない）を足し、ほかの `components/ui` と同じ見た目の欄にする。`format` は桁区切り無し、`allowOutOfRange` を付け、`locale` は `ja-JP` に固定する（実行環境のロケールで小数点の記号が変わり「1.5」の読み方が実測とずれるのを避ける）
- 欄の値は `number | null` で持ち、空の欄（`null`）は「値なし」と読む。範囲の判定は `lib/servant-roster-review.ts` に数を受ける形で置き、2つの画面と取り込みの可否で使う（確かめ画面の行の状態も `number | null` にし、判定を1つにする）（Lv は 1〜120、宝具Lv は 1〜5 の整数。範囲外と整数でない値は不正）。文字を読む `readField` は欄から外す
- 自前の変換中・確定の処理と「確定で数字が残らないときは前の値に戻す」処理は置かない。実測で、数でない文字は部品が欄に入れず値が残るため、戻す先の値を持たなくても保存値は黙って消えない
- 「Lv 90」の貼り付けは部品のとおり無視する（値は変わらない）。取り出す処理を足すと薄い包みでなくなるため
- 確かめ画面の欄から `type="number"`・`min`・`max`・`step` を外し、小窓と同じ包みにそろえる。候補のボタンで入る値は今までどおり

## Risks / Trade-offs

- 漢数字が数として読まれる（「九」→ 9）→ 範囲外か桁が増えた値は赤枠で止まる（判断点 1 の A）。範囲内に収まる漢数字（空の欄で「九」を確定して 9 になるなど。「十」は数として読まれず入らない）は数として入るが、欄に数が出るので見て分かる
- Safari の変換の確定の順序は測っていない → 部品が `isComposing` に頼らず `keyCode 229` で変換中のキーを通すことはコードで確かめた。実機の確かめを tasks に人が行うものとして残す
- 「Lv 90」を貼っても何も起きないので、貼った人には効かなかったように見える → 欄の値は変わらず保存値も消えないので、今回は扱わない
- `@base-ui/react` の版を上げると貼り付けや丸めの挙動が変わりうる → 部品テストで「９０」→ 90、「Lv 90」で値が変わらない、121 が丸められないことを固定する
