# Spec Delta

## MODIFIED Requirements

### Requirement: サーヴァント扱いの品目の表示と計算
システムは、交換所の一覧で、サーヴァント扱いの品目をアイテムの品目と同じ1つの一覧（`event-shop-single-list`）に、名前とアイコンとともに並べなければならない (SHALL)。周回計算の一覧では、サーヴァント扱いの品目は効率の無い行として、`event-shop-efficiency` の「効率順の1つの一覧」のとおり効率のある行の後に交換所の順で並ぶ。複数の通貨で交換できるサーヴァント扱いの品目は、アイテムの品目と同じ規則で1行にまとめる。アイテムの品目が1つ以上ある交換所では、サーヴァント扱いの品目は、交換回数の入力・全部交換・通貨ごとの必要量・周回の内訳・合計・AP 予算の計算に、アイテムの品目と同じ規則で入れなければならない (SHALL)。品目がすべてサーヴァント扱いの交換所は、「品目がすべてサーヴァント扱いの交換所の一覧」に従い、これらの計算を出さない。サーヴァント扱いの品目はフリクエのドロップ表に現れない品として扱い、効率を表示してはならない (SHALL NOT)。サーヴァント扱いの品目の獲得物の番号を、アイテムの番号として所持数・育成計画の必要数・ドロップ表と突き合わせてはならない (SHALL NOT)。

#### Scenario: 全部交換に入る
- **WHEN** 通貨 A で交換する、在庫上限 40 の英霊結晶と在庫上限 10 のアイテムの品目があり、利用者が全部交換を押したとき
- **THEN** 英霊結晶の交換回数は 40、アイテムの品目の交換回数は 10 になり、通貨 A の必要量には両方の対価の合計が入る

#### Scenario: 効率を出さない
- **WHEN** 交換所に礼装と、AP 換算値のあるアイテムの品目があるとき
- **THEN** 礼装は効率なしでアイテムの品目の後に並び、アイテムの品目は効率つきで並ぶ

#### Scenario: 複数の通貨で交換できる月より団子
- **WHEN** 80632 で、サーヴァント扱いの月より団子が3つの通貨で在庫上限つきで交換できるとき
- **THEN** 月より団子は1行にまとめられ、入れた回数は3つの通貨の品目の交換回数に、合計が入れた回数と等しくなるように分けられる

### Requirement: 品目がすべてサーヴァント扱いの交換所の一覧
システムは、ロトの無い交換所イベントで、交換所の品目がすべてサーヴァント扱いの品目のとき、イベントページの交換所を品目の一覧だけとして表示しなければならない (SHALL)。周回クエストの有無とドロップの統計の有無は、この判定に使ってはならない (SHALL NOT)。一覧は、周回計算のある交換所と同じく、品目を通貨ごとのカードに分けずに交換所の順の1つの一覧とし、複数の通貨で交換できる品目を同じ規則で1行にまとめ、品目ごとに名前・アイコン・1回の個数・対価（通貨の名前またはアイコンと数。まとめた行は通貨ごと）・在庫上限（無いときは上限なし。まとめた行は合計と通貨ごとの在庫上限）を表示しなければならない (SHALL)。通貨名が無い通貨は ID の見出しで表示しなければならない (SHALL)。

一覧だけのときは、全交換の合計と上限なしの品目の数、交換回数の入力、全部交換と不足素材のみの操作、ドロップ増加礼装のボーナスの入力、通貨ごとの所持数の入力と選んだ交換の合計と必要量、1周あたりの獲得量、周回の内訳、合計の周回数と AP、周回できないことや周回が不要なことの表示、AP 予算、「計画の対象外」のラベルと「必要／不要」の切り替えを表示してはならない (SHALL NOT)。交換所のセクションの見出しと説明は、周回計算をしないことが分かるものにしなければならない (SHALL)。この要件は、同じ交換所について、次の要件より優先する。`event-planner` の「ロトの無い交換所イベントの周回計画」、`event-shop-efficiency` のすべての要件（「品目の効率」「効率順の1つの一覧」「効率の区切りを設けない」）、`event-shop-single-list` の「通貨ごとの所持数と必要量を品目の一覧の上と下に出す」と、「複数の通貨で交換できる品目を1行にまとめる」のうち交換回数の入力と割り振りに当たる部分、`event-shop-roster-need` のすべての要件（「品目ごとの要る・要らない」「計画の対象外の品目の要る・要らない」「不足素材のみ」「交換所で埋まらない不足」「育成計画が使えないとき」）、`event-shop-ap-budget` のすべての要件（「全部交換の操作」「交換所の AP 予算」「マスターレベルと黄金の果実の所持数」）、`event-drop-bonus` のうち交換所に当たる要件（「ボーナスの入力」「ボーナス込みの1周の獲得量」「交換所の周回計算への反映」）。同じ capability の「サーヴァント扱いの品目の表示と計算」と「サーヴァント扱いの品目の必要／不要」は、アイテムの品目が1つ以上ある交換所に限る。

品目が1つでもアイテムの品目（サーヴァント扱いであることを持たない既存のデータの品目を含む）である交換所は、一覧だけにしてはならない (SHALL NOT)。イベント一覧（`/events`）とダッシュボードのイベントの表示（交換所のバッジとイベントページへの導線）は、一覧だけの交換所でも変えてはならない (SHALL NOT)。

#### Scenario: 周回場所の無い礼装だけの交換所
- **WHEN** ロトが無く、交換所の品目がすべて礼装で、周回クエストが無いイベント（例: 80638）のイベントページを開いたとき
- **THEN** 交換所の品目が交換所の順の1つの一覧に、名前・アイコン・1回の個数・対価・在庫上限とともに並び、交換回数の入力・全部交換・所持数・必要量・周回の内訳・AP 予算は表示されない

#### Scenario: 周回場所はあるが通貨が落ちない礼装だけの交換所
- **WHEN** ロトが無く、交換所の品目がすべて礼装で、周回クエストはあるがどのドロップの統計にも対価の通貨が無いイベント（例: 80613）のイベントページを開いたとき
- **THEN** 周回場所の無い礼装だけの交換所と同じく、品目の一覧だけが表示され、ドロップ増加礼装のボーナスの入力と1周あたりの獲得量は表示されない

#### Scenario: アイテムの品目が1つでもある交換所
- **WHEN** 交換所に礼装と、アイテムの品目が1つ以上あるとき
- **THEN** 交換所は今までどおり周回計算として表示され、礼装は交換回数の入力と全部交換に入る

#### Scenario: 一覧のバッジは変えない
- **WHEN** 品目がすべてサーヴァント扱いの交換所を持つイベントが、イベント一覧に載るとき
- **THEN** そのイベントには今までどおり交換所の機能のバッジが付く
