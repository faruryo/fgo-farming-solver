# Proposal

## Why

ロトの無い交換所イベントの交換所（例: /events/80632）は、品目を対価の通貨ごとのカードに分けて並べている。ゲーム内の交換所は通貨で分かれておらず、決まった順に1つの一覧で並ぶので、ゲームの画面と見比べながら交換回数を入れにくい（#225）。並び順の元になる Atlas の交換所の `priority` を、今の取り込みは捨てていて、保存している並びは Atlas の配列の順（ID の順）になっている。80632 では、ゲーム内で先頭のサーヴァントコインではなく、月より団子が先頭に来る。品目を素材として得かで比べる効率順（#176）は、オーナーの判断で残す。

## What Changes

- 取り込みで、交換所の品目を Atlas の交換所の並び順（`priority` の小さい順）に並べて保存する。`priority` が同じ品目は今の順を保つ。交換所が Atlas の区分（`slot`、ゲーム内のタブに当たる）を2つ以上持つイベント（手元では 80603 だけ）は、区分ごとにまとめてから並べる。取り込み直していないイベントのデータは今の順のまま表示する
- 交換所の周回計算の品目の一覧を、通貨ごとのカードに分けず、1つの一覧にする。行は、その行の品目を交換できる通貨のうち一番いい効率（AP/個）の高い順に、通貨をまたいで並べ、順位を一覧の中で 1 から付ける。AP 換算できない品目は、効率順の品目の下に、交換所の順（ゲーム内の順）でまとめる
- 同じ獲得物を同じ個数で、在庫上限のある品目として複数の通貨で交換できるときは、1行にまとめ、その行の交換回数の入力を1つにする。まとめた行に入れた回数は、利用者に通貨を選ばせずに、通貨ごとの品目の交換回数に分ける。行には通貨ごとの回数を出す
- 通貨ごとの所持数の入力は、品目の一覧の上に横1列で並べる。通貨ごとの選んだ交換の合計・必要量・全交換の合計は、品目の一覧の下に並べる
- 品目がすべてサーヴァント扱いの交換所の一覧（入力の無い一覧）も、通貨ごとのカードをやめて交換所の順の1つの一覧とし、同じ規則で行をまとめる
- 交換回数の保存の形は変えない。今までどおり通貨ごとの品目に結び付けて保存し、前に保存した値はそのまま読む

## Capabilities

### New Capabilities

- `event-shop-single-list`: 交換所の品目を取り込みでゲーム内の順に並べて保存すること、品目を通貨ごとのカードに分けず1つの一覧で出すこと、複数の通貨で交換できる品目を1行にまとめて回数を通貨ごとの品目に分けること、通貨ごとの所持数と必要量を一覧の上と下に出すこと

### Modified Capabilities

- `event-shop-efficiency`: 通貨ごとのカードの中で効率順に並べる要件を、1つの一覧で通貨をまたいで効率順に並べ、AP 換算できない品目を下に交換所の順で並べる要件に変える。まとめた行の効率は、通貨のうち一番いい値にする
- `event-shop-servant-exchange`: サーヴァント扱いの品目を通貨ごとのカードに並べる要件を、1つの一覧に並べる要件に変える（品目がすべてサーヴァント扱いの交換所の一覧も同じ）
- `event-shop-saved-inputs`: まとめた行の交換回数を、通貨ごとの品目の回数として保存し、前に保存した値をそのまま読む要件を足す

## Impact

- `lib/refresh-event-data-compact.ts` の `compactShop`: Atlas の `priority` で並べ替えてから返す。保存するイベントデータ（KV `event_data_json`）の品目の並びが、取り込み直したイベントから変わる。品目の項目は増やさない
- 取り込みの定期ジョブは、開催中と終了後 30 日以内のイベントしか取り込み直さない。それより前に終わったイベントは、`refresh-event-data` の手動実行（`backfill_since`）で取り込み直すまで今の順で表示される
- PR の preview は KV の今のデータを読むので、preview では新しい並び順を確かめられない（並びの変化は取り込みのテストと、取り込み直したデータを読ませた dev server で確かめる）
- `lib/event-shop-summary.ts`: 1つの一覧の行（まとめた行を含む）を作る関数と、まとめた行の回数を通貨ごとの品目に分ける関数を足す。効率の順位付け（`orderShopByEfficiency`）を、通貨ごとではなく1つの一覧の行を並べるものに変える
- `components/events/EventShopList.tsx`: 通貨ごとのカード（`CurrencyGroupCard`）を、一覧の上の所持数の入力、1つの品目の一覧、一覧の下の通貨ごとの必要量に分ける。品目がすべてサーヴァント扱いの一覧（`EventShopCatalog`）も1つの一覧にする
- 周回の計算（`planShopCurrencies`）、通貨ごとの必要量の出し方、「全部交換」「不足素材のみ」の規則、保存のキーと保存値の形は変えない。「不足素材のみ」は交換所の元の順に品目を見るので、取り込み直して順が変わったイベントでは、同じ素材の品目のどれから埋めるかが新しい順に従う
- 箱のあるイベントの箱計画は変えない
