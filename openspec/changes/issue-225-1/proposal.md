# Proposal

## Why

ロトの無い交換所イベントの交換所（例: /events/80632）は、品目を対価の通貨ごとのカードに分けて並べている。ゲーム内の交換所は通貨で分かれておらず、決まった順に1つの一覧で並ぶので、ゲームの画面と見比べながら交換回数を入れにくい（#225）。並び順の元になる Atlas の交換所の `priority` を、今の取り込みは捨てていて、保存している並びは Atlas の配列の順（ID の順）になっている。80632 では、ゲーム内で先頭のサーヴァントコインではなく、月より団子が先頭に来る。

## What Changes

- 取り込みで、交換所の品目を Atlas の交換所の並び順（`priority` の小さい順）に並べて保存する。`priority` が同じ品目は今の順を保つ。交換所が Atlas の区分（`slot`、ゲーム内のタブに当たる）を2つ以上持つイベント（手元では 80603 だけ）は、区分ごとにまとめてから並べる。取り込み直していないイベントのデータは今の順のまま表示する
- 交換所の周回計算の品目の一覧を、通貨ごとのカードに分けず、保存した順の1つの一覧にする
- 同じ獲得物を同じ個数で、在庫上限のある品目として複数の通貨で交換できるときは、1行にまとめ、その行の交換回数の入力を1つにする。まとめた行に入れた回数は、交換所の順に前の通貨の在庫上限から埋めて、通貨ごとの交換回数に割り振る。行には割り振った通貨ごとの回数を出す
- 通貨ごとの所持数の入力・選んだ交換の合計・必要量・全交換の合計は、品目の一覧とは別の「通貨ごとのまとめ」に、品目の一覧の前に並べて出す
- 効率は、品目の行に通貨1個あたりの値として今までどおり出す。通貨ごとの効率の順位と、AP 換算値の有無で一覧を分ける見出しは無くす
- 品目がすべてサーヴァント扱いの交換所の一覧（入力の無い一覧）も、同じ順の1つの一覧とし、同じ規則で行をまとめる
- 交換回数の保存の形は変えない。今までどおり通貨ごとの品目に結び付けて保存し、前に保存した値はそのまま読む

## Capabilities

### New Capabilities

- `event-shop-game-order`: 交換所の品目をゲーム内の順の1つの一覧で並べること、複数の通貨で交換できる品目を1行にまとめて回数を割り振ること、通貨ごとのまとめを一覧と別に出すこと

### Modified Capabilities

- `event-shop-efficiency`: 通貨ごとのカードの中で効率順に並べ順位を付ける要件を無くし、効率を行に出す要件をまとめた行にも当てはめる
- `event-shop-servant-exchange`: サーヴァント扱いの品目を通貨ごとのカードに並べる要件を、1つの一覧に並べる要件に変える（品目がすべてサーヴァント扱いの交換所の一覧も同じ）
- `event-shop-saved-inputs`: まとめた行の交換回数を、通貨ごとの品目に割り振った回数として保存し、前に保存した値をそのまま読む要件を足す

## Impact

- `lib/refresh-event-data-compact.ts` の `compactShop`: Atlas の `priority` で並べ替えてから返す。保存するイベントデータ（KV `event_data_json`）の品目の並びが、取り込み直したイベントから変わる。品目の項目は増やさない
- 取り込みの定期ジョブは、開催中と終了後 30 日以内のイベントしか取り込み直さない。それより前に終わったイベントは、`refresh-event-data` の手動実行（`backfill_since`）で取り込み直すまで今の順で表示される
- PR の preview は KV の今のデータを読むので、preview では新しい並び順を確かめられない（並びの変化は取り込みのテストと、取り込み直したデータを読ませた dev server で確かめる）
- `lib/event-shop-summary.ts`: 1つの一覧の行（まとめた行を含む）を作る関数と、まとめた行の回数を通貨ごとの品目に割り振る関数を足す。効率の順位付け（`orderShopByEfficiency`）は使わなくなる
- `components/events/EventShopList.tsx`: 通貨ごとのカード（`CurrencyGroupCard`）を、通貨ごとのまとめと1つの品目の一覧に分ける。品目がすべてサーヴァント扱いの一覧（`EventShopCatalog`）も1つの一覧にする
- 周回の計算（`planShopCurrencies`）、通貨ごとの必要量の出し方、「全部交換」「不足素材のみ」の規則、保存のキーと保存値の形は変えない。「不足素材のみ」は交換所の元の順に品目を見るので、取り込み直して順が変わったイベントでは、同じ素材の品目のどれから埋めるかが新しい順に従う
- 箱のあるイベントの箱計画は変えない
