# Proposal

## Why

絆Lvの上限が16に上がり(2026-08-02)、Lv15→16だけで500万ポイントが必要になった。絆上げを続けるユーザーは「目標まであと何周・何APか」を知りたいが、アプリにはサーヴァント個体の絆データも、ユーザーの絆状態を持つ場所もない。

ティーポット(絆2倍)は誤消費が起きやすく、事前に組んだ周回計画はすぐ実態とずれる。そのため計画に従わせる機能ではなく、現在の状態を入れ直すたびに残り周回数を計算し直す見積もり機能として作る。

## What Changes

- 新しいページ `/bond` を追加し、ナビの Tools に載せる。
- ユーザーは絆を上げたいサーヴァントを複数登録し、各騎の現在の絆Lv・次のLvまでの残りポイント(ゲーム画面の表示値)・目標Lv・前衛か控えかを入力する。
- ユーザーは周回するクエストを1つ選ぶ。候補として基本絆P/実効APの上位クエストを並べる。
- 絆ボーナスとして、絆礼装の合計%、フレンドを前衛に置くか、自軍の絆15サーヴァントの体数、ティーポットを使うか(使う場合は所持数)を入力する。マナプリズムを持たないユーザー向けに、ティーポットは既定で使わない。
- 各騎について、目標までの残り絆ポイント・残り周回数・必要APを表示する。ティーポットを使う場合は、所持数を使い切ったときに何周縮むかも表示する。ボーナスの加算・乗算の順序はゲーム側の一次情報で確定していないため、結果は概算として表示する。
- 登録内容と入力値を localStorage に保存し、クラウド同期の対象キーに加える。
- Material Catalog のサーヴァントに、Atlas Academy `nice_servant` の `bondGrowth`(絆Lvごとの累積必要ポイント)を任意項目として追加する。

## Capabilities

### New Capabilities

- `bond-tracker`: 絆上げ対象サーヴァントの登録、絆状態とボーナスの入力、選んだクエストでの残り周回数・必要APの見積もり、`/bond` ページとナビ導線。

### Modified Capabilities

- `material-catalog`: サーヴァントの蒸留項目に `bondGrowth` を追加する。前回のカタログにこの項目がない場合は条件付き GET を使わず取り直し、既存 KV に項目が入らないまま固定されるのを防ぐ。
- `sync`: 絆トラッカーの保存キーをクラウド同期対象に含める。

## Impact

- 新規: `app/bond/page.tsx`、`components/bond/*`、`lib/bond/*`(見積もりの pure 関数とテスト)、`locales/{ja,en}.json` の新しい namespace。
- 変更: `components/common/nav.tsx`(Tools にリンク追加)、`lib/constants/storage-keys.ts` と `storage-keys.test.ts`(同期キー追加)、`lib/material-catalog.ts`・`lib/material-catalog-updater.ts`(`bondGrowth` の蒸留・検証と取り直し条件)。
- データ: `material_catalog_v1` のサーヴァント1件あたり16個の数値が増える(全体で数十KB程度)。キーとスキーマバージョンは変えない。
- 絆キャンペーン(`questFriendship`)の自動反映、ティーポットの失効日管理、編成の提案は今回の範囲外。
