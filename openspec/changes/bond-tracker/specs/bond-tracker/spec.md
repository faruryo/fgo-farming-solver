# Spec Delta

## Purpose

絆Lvを上げたいサーヴァントを登録し、現在の絆状態と絆ボーナスから、選んだクエストで目標Lvに届くまでの残り周回数と必要APを見積もる。計画の実行を管理せず、状態を入れ直すたびに計算し直す。

## ADDED Requirements

### Requirement: 絆トラッカーページと導線

システムは `/bond` に絆トラッカーページを提供し、ナビゲーションの Tools グループから到達できなければならない (SHALL)。画面の文字列は日本語と英語の両方で表示できなければならない (SHALL)。

#### Scenario: ナビから開く
- **WHEN** ユーザーがナビゲーションの Tools グループで絆トラッカーを選ぶ
- **THEN** `/bond` が開き、登録済みサーヴァントの一覧と見積もりが表示される

### Requirement: 絆上げ対象サーヴァントの登録

システムはユーザーが絆上げの対象サーヴァントを複数登録・削除できなければならない (SHALL)。同じサーヴァントを重複して登録してはならない (SHALL NOT)。

#### Scenario: サーヴァントを追加する
- **WHEN** ユーザーがサーヴァント一覧から未登録のサーヴァントを選ぶ
- **THEN** そのサーヴァントが登録され、絆状態の入力欄が表示される

#### Scenario: 登録済みサーヴァントは再追加できない
- **WHEN** ユーザーが登録済みのサーヴァントを追加しようとする
- **THEN** 登録は増えず、既存の登録内容は変わらない

#### Scenario: サーヴァントを削除する
- **WHEN** ユーザーが登録済みサーヴァントを削除する
- **THEN** そのサーヴァントの登録と入力値が一覧と保存内容から消える

### Requirement: 絆状態の入力

システムは登録サーヴァントごとに、現在の絆Lv(0〜15)、次のLvまでの残りポイント、目標絆Lv、前衛か控えかを入力できなければならない (SHALL)。目標絆Lvは現在の絆Lvより大きく16以下でなければならない (SHALL)。次のLvまでの残りポイントは1以上で、現在Lvから次のLvへの必要増分以下でなければならない (SHALL)。範囲外の入力に対しては見積もりを表示せず、どの値が範囲外かを示さなければならない (SHALL)。前衛の初期値は前衛とする (SHALL)。

#### Scenario: 範囲外の残りポイント
- **WHEN** 次のLvまでの残りポイントに、現在Lvから次のLvへの必要増分より大きい値を入力する
- **THEN** そのサーヴァントの見積もりは表示されず、残りポイントが範囲外であることが示される

#### Scenario: 目標Lvが現在Lv以下
- **WHEN** 目標絆Lvに現在の絆Lv以下の値を入力する
- **THEN** そのサーヴァントの見積もりは表示されず、目標Lvが範囲外であることが示される

### Requirement: 目標までの残り絆ポイント

システムは各サーヴァントについて、目標までの残り絆ポイントを「次のLvまでの残りポイント」と「次のLvから目標Lvまでの各Lvの必要増分の合計」の和として算出しなければならない (SHALL)。各Lvの必要増分はそのサーヴァントの絆Lv別累積必要ポイントの差分から求めなければならない (SHALL)。

#### Scenario: 目標が次のLv
- **WHEN** 現在Lv14、次のLvまで残り 100,000、目標Lv15
- **THEN** 残り絆ポイントは 100,000 である

#### Scenario: 複数Lv先が目標
- **WHEN** 現在Lv14、次のLvまで残り 100,000、目標Lv16 で、Lv15→16 の必要増分が 5,000,000 のサーヴァント
- **THEN** 残り絆ポイントは 5,100,000 である

### Requirement: 絆データが未取得のサーヴァント

システムは、絆Lv別累積必要ポイントを持たないサーヴァントについて、見積もりを表示せず、絆データが未取得であることを示さなければならない (SHALL)。他のサーヴァントの見積もりは妨げてはならない (SHALL NOT)。

#### Scenario: 一部のサーヴァントだけ絆データがない
- **WHEN** 登録サーヴァントのうち1騎だけ絆Lv別累積必要ポイントがない
- **THEN** その1騎には絆データ未取得の表示が出て、他の騎には通常どおり見積もりが表示される

### Requirement: 周回クエストの選択

システムはユーザーが見積もりに使うクエストを、基本絆ポイントを持つクエストから1つ選べなければならない (SHALL)。選択の候補として、基本絆ポイント÷実効APが大きい順の上位クエストを提示しなければならない (SHALL)。実効APはアクティブなAP割引キャンペーンを反映しなければならない (SHALL)。クエストが未選択の間は見積もりを表示せず、クエストの選択を促さなければならない (SHALL)。

#### Scenario: 候補の並び
- **WHEN** 絆トラッカーでクエストの候補を開く
- **THEN** 基本絆ポイント÷実効APが大きい順にクエストが並ぶ

#### Scenario: AP割引キャンペーン中
- **WHEN** 選んだクエストにAP半減キャンペーンが適用されている
- **THEN** 必要APは割引後のAPで計算される

### Requirement: 1周あたり獲得絆の概算

システムは1周あたりの獲得絆ポイントを、クエストの基本絆ポイントに (1 + 絆礼装の合計% + 前衛なら20% + フレンドを前衛に置くなら4% + 自軍の絆15サーヴァント数×25%) を掛けて小数点以下を切り捨てた値として算出しなければならない (SHALL)。ティーポットを使う周回はこの値の2倍とする (SHALL)。ボーナスの計算順序はゲームの公式情報で確定していないため、画面は見積もりが概算であることを表示しなければならない (SHALL)。

#### Scenario: 前衛と控えの差
- **WHEN** 基本絆ポイント 1,000、他のボーナスなしで、前衛の騎と控えの騎がいる
- **THEN** 前衛の騎は1周 1,200、控えの騎は1周 1,000 と算出される

#### Scenario: 絆15サーヴァントの加算
- **WHEN** 基本絆ポイント 1,000、前衛、絆礼装 10%、自軍の絆15サーヴァント2騎
- **THEN** 1周あたりの獲得絆は 1,000 × (1 + 0.10 + 0.20 + 0.50) = 1,800 と算出される

### Requirement: 残り周回数と必要AP

システムは各サーヴァントについて、残り絆ポイントを1周あたり獲得絆で割って切り上げた残り周回数と、残り周回数×実効APの必要APを表示しなければならない (SHALL)。残り絆ポイントが0以下なら残り周回数と必要APは0とする (SHALL)。

#### Scenario: 端数は1周に切り上げる
- **WHEN** 残り絆ポイント 2,500、1周あたり獲得絆 1,200、実効AP 40
- **THEN** 残り周回数は3周、必要APは120と表示される

### Requirement: ティーポットの使用

システムはティーポットを使うかどうかを切り替えられなければならず、初期状態は使わないとしなければならない (SHALL)。使う場合、ユーザーはティーポットの所持数を入力でき、システムは所持数の範囲でティーポットを使う周回を先に充てた残り周回数と、ティーポットを使わない場合との差(何周縮むか)を表示しなければならない (SHALL)。ティーポットの所持数は各サーヴァントの見積もりに個別に適用し、画面は複数騎を同じ編成で回すとティーポットを共有することを示さなければならない (SHALL)。

#### Scenario: 所持数で足りる
- **WHEN** 残り絆ポイント 4,000、1周あたり獲得絆 1,000、ティーポット所持数 5
- **THEN** 残り周回数は2周(すべてティーポット使用)で、使わない場合より2周縮むと表示される

#### Scenario: 所持数が尽きる
- **WHEN** 残り絆ポイント 5,000、1周あたり獲得絆 1,000、ティーポット所持数 2
- **THEN** 残り周回数は3周(ティーポット2周+通常1周)で、使わない場合より2周縮むと表示される

#### Scenario: 使わない設定
- **WHEN** ティーポットを使わない設定にしている
- **THEN** 見積もりはティーポットなしで計算され、所持数の入力欄は表示されない

### Requirement: 入力内容の保存

システムは登録サーヴァント、各騎の絆状態、クエスト選択、絆ボーナスとティーポットの設定を localStorage の単一キー `bondTracker` に保存し、次回表示時に復元しなければならない (SHALL)。保存値が壊れている、または想定外の形のときは、画面をクラッシュさせず空の状態で表示しなければならない (SHALL)。

#### Scenario: 再訪時に復元する
- **WHEN** ユーザーが入力後にページを閉じ、再度 `/bond` を開く
- **THEN** 前回の登録サーヴァントと入力値が復元され、見積もりが再計算される

#### Scenario: 壊れた保存値
- **WHEN** `bondTracker` の保存値が JSON として解釈できない
- **THEN** ページはエラーにならず、登録なしの状態で表示される
