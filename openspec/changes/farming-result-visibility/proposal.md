# Proposal: 周回計算結果の公開・非公開設定

## Why

周回計算の結果ページ（`/farming/results/[id]`）は、推測が困難な UUID を用いているものの、URL を知っていれば認証や所有者確認なしに誰でも閲覧できる状態となっています。
一度 SNS や共有リンクで外部に発信した結果をユーザー自身が非公開に戻す手段がなく、目標素材数や周回編成・周回数などの情報公開を本人がコントロールできません。
ログインユーザーが自身の計算結果について公開・非公開を 1 件ごとに選択でき、かつ新規保存時の既定値を設定できるようにすることで、プライバシーを保護しつつ安全に結果を共有できるようにします。

## What Changes

- **DB スキーマ変更**: `farming_results` テーブルに `is_public` カラム（INTEGER NOT NULL DEFAULT 1 = 公開）を追加するマイグレーションを作成します。既存の保存済みデータはすべて公開（1）として扱われ、共有済みリンクは壊れません。
- **新規計算結果の既定公開設定**: 周回計算画面（`/farming` および `/farming/manual`）に、保存時の既定の公開状態（公開/非公開）を設定できるユーザーオプションを追加します。この設定の初期既定値は「公開」であり、アカウント（端末設定/localStorage）ごとに保持されます。未ログインユーザーの計算結果は常に公開（1）として保存されます。
- **結果画面での公開/非公開切り替え**: 結果画面（`/farming/results/[id]`）において、その結果の所有者（ログイン中の本人）に対してのみ公開/非公開を切り替えられるスイッチを提供します。
- **連動更新**: `batch_id` を持つ 2 目標ペア（必要分 / +ストック）の場合、目標 A・目標 B の双方の `is_public` が連動して更新されます。
- **閲覧アクセス制御**: 非公開（`is_public = 0`）に設定された結果に対して所有者以外のユーザー（第三者または未ログインユーザー）がアクセスした場合、結果が存在しない場合と同様に 404 Not Found を返します。所有者本人はログイン状態であれば常に閲覧可能です。
- **ツイートボタンの表示制御**: ツイートボタンは公開（`is_public = 1`）の結果にのみ表示し、非公開の結果では非表示にします。

## Capabilities

### Modified Capabilities
- `farming-history`: 計算結果の保存要件に公開設定（`is_public`）を追加し、所有者による結果ごとの公開/非公開切り替え、非公開結果へのアクセス制御（所有者以外への 404 応答）、および公開結果限定のツイートボタン表示要件を追加・更新します。

## Impact

- **DB**: `migrations/0005_farming_results_visibility.sql`（`ALTER TABLE farming_results ADD COLUMN is_public INTEGER NOT NULL DEFAULT 1;`）
- **APIs**:
  - `app/api/solve/route.ts`: クライアントから送信された公開設定または既定値に基づき `is_public` を保存。
  - `app/api/farming/results/[id]/route.ts`: 所有者による `PATCH`（公開状態の更新）を実装。`GET` 時に非公開かつ非所有者なら 404 を返却。
  - `lib/get-result.ts`: `is_public` および `user_id` を取得し、セッションユーザーとの比較に基づくアクセス制御ロジックを統合。
- **UI コンポーネント**:
  - `components/farming/index.tsx`: 周回計算オプション欄に既定公開設定を追加。
  - `components/farming/result.tsx`: 所有者専用の公開・非公開切り替えスイッチを追加し、ツイートボタンの表示条件を更新。
- **多言語対応**: `locales/ja.json`, `locales/en.json` に公開・非公開切り替え、説明文、通知メッセージ等の文言を追加。
