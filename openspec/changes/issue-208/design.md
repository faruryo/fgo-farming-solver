# Design

## Context

品目の状態は `lib/event-shop-summary.ts` の `shopItemStatus` が `short`・`enough`・`unused`・`outside` のどれかで返し、不足素材のみの回数は同じファイルの `allocateShortfallOnly` が状態を見て入れる。`unused` と `enough` は 0 回で、`components/events/EventShopList.tsx` の行は薄く表示される。在庫上限の無い「必要」の品目は `unlimitedWanted` に入り、行に「上限なし: 回数を入れてください」が出る。伝承結晶の Atlas のアイテム番号は 6999。

## Goals / Non-Goals

**Goals:**
- 不足素材のみで、伝承結晶をいつも在庫上限まで入れる（specs の「不足素材のみ」）
- 不足の無い伝承結晶の表示を、入る回数と食い違わない文言にする（specs の「品目ごとの要る・要らない」）

**Non-Goals:**
- 伝承結晶以外の品目を「いつも交換」にする設定や、利用者が選べる切り替え
- 全部交換・手入力・周回の内訳の変更

## Decisions

1. **状態に `always` を足す。** `shopItemStatus` は、伝承結晶（アイテム扱いで番号 6999）の不足が 0 のとき、`enough`・`unused` の代わりに `{ kind: 'always' }` を返す。不足があれば今までどおり `short`。育成計画で扱う素材の一覧を読めないとき（`planItemIds` が undefined）も、伝承結晶は計画で扱う素材と分かっているので `always` にする。
   - 代わりの案: 状態は変えず、割り当てと表示の側で番号を見る。番号の判定が2か所に散り、薄く表示する条件にも同じ判定が要るので採らない。
2. **割り当て。** `allocateShortfallOnly` は伝承結晶の品目を次のとおり扱う。
   - `always` で在庫上限あり: 在庫上限の回数。
   - `always` で在庫上限なし: 0 にして `unlimitedWanted` に入れる（行の「上限なし」の案内を出すため）。
   - `short` で在庫上限あり: 在庫上限の回数にし、得る個数を残りの不足から差し引く（同じ素材の後の品目と、「交換所では N 個足りない」の残りに効く）。残りの不足が 0 になった後の伝承結晶の品目も在庫上限の回数にする。
   - `short` で在庫上限なし: 残りの不足があれば今までどおり不足の分、無ければ 0 にして `unlimitedWanted` に入れる。
   - 1回の個数が 0 以下の品目は今までどおり 0。
3. **表示。** `always` は「いつも上限まで交換」（en: "Always max"）と表示し、薄く表示しない。切り替えは出さない。在庫上限なしで回数が 0 のときは、計画の対象外の「必要」と同じ「上限なし: 回数を入れてください」を出す。
4. **伝承結晶の番号は定数にする。** `QP_ITEM_ID` と同じ場所に `CRYSTAL_ITEM_ID = 6999` を置く。

## Risks / Trade-offs

- [不足が在庫上限より少ないときも上限まで入るので、必要量より多く交換する] → issue の「いつも上限まで」に合わせた。足りない分はいつもどおり「あと N 個」で見える
- [番号 6999 が将来変わる] → Atlas の伝承結晶の番号は長く固定されている。変わったら定数を直す
