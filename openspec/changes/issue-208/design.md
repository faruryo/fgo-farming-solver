# Design

## Context

品目の状態は `lib/event-shop-summary.ts` の `shopItemStatus` が `short`・`enough`・`unused`・`outside` のどれかで返し、不足素材のみの回数は同じファイルの `allocateShortfallOnly` が状態と「要る」のキーの集合（`wanted`）を見て入れる。「要る」は `components/events/EventShopList.tsx` の `useWantedItems` が `STORAGE_KEYS.EVENTS_SHOP_WANTED_ITEMS` に `Record<string, true>` で保存し、「不要」に戻すとキーを消す。切り替え（`WantedToggle`）は `outside` の行にだけ出る。在庫上限の無い「必要」の品目は `unlimitedWanted` に入り、行に「上限なし: 回数を入れてください」が出る。伝承結晶の Atlas のアイテム番号は 6999、カルデアの夢火は 1000（`skillLvUp` の種類だが育成計画には出ないので、今は `outside`）。

## Goals / Non-Goals

**Goals:**
- 伝承結晶と夢火を、既定で「必要」とし、不足素材のみで在庫上限まで入れる（specs の「不足素材のみ」）
- この2つに、状態に関わらず切り替えを出し、品目ごとに「不要」にできる（specs の「計画の対象外の品目の要る・要らない」）

**Non-Goals:**
- 既定で交換する品目を利用者が増やす設定
- コード・リムーバー／オープナー、サーヴァントコインなどの初期値の変更
- 表示のラベル・文言の変更、全部交換・手入力・周回の内訳の変更

## Decisions

1. **既定で交換する品目は定数の集合にする。** `QP_ITEM_ID` と同じ場所に `DEFAULT_WANTED_ITEM_IDS = new Set([6999, 1000])` を置く。サーヴァント扱いの品目（`kind: 'svt'`）は番号が同じでも含めない。判定は `isDefaultWanted(item)` の1か所にまとめる。
2. **一覧を読めないときの状態。** `shopItemStatus` は `planItemIds` が undefined のとき、伝承結晶なら必要数 0 で `unused`、夢火なら `outside` を返す（必要数が 1 以上なら今までどおり `short` か `enough`）。番号で扱いが決まっているので、一覧が無くても見分けられる。
3. **保存。** 保存の形を `Record<string, boolean>` に広げる。既定で交換する品目は、「必要」なら `true`、「不要」なら `false` を保存する。ほかの品目は今までどおり「必要」で `true`、「不要」でキーを消す。読むときは、キーがあればその値、無ければ既定で交換する品目は `true`、ほかは `false`。今までの保存値（`true` だけ）はそのまま読める。`allocateShortfallOnly` に渡す `wanted` は、この解決をした後の「必要」のキーの集合にする（未選択の伝承結晶・夢火のキーを含む）。
   - 代わりの案: 「不要」を別のキーに保存する。2つのキーの食い違い（両方に載る）を扱う規則が要るので採らない。
4. **切り替えの表示。** 切り替えは、状態が `outside` の品目と、状態のある既定で交換する品目（`short`・`enough`・`unused`・`outside`）に出す。ラベル（「あと N 個」など）は今までどおりで、切り替えを横に並べる。状態の無い品目（QP、育成計画が使えないとき）には出さない。
5. **割り当て。** `allocateShortfallOnly` は、既定で交換する品目で「必要」のものを次のとおり扱う。
   - 在庫上限あり: 状態に関わらず在庫上限の回数。`short` なら得る個数を残りの不足から差し引く（同じ素材の後の品目と、「交換所では N 個足りない」の残りに効く）。
   - 在庫上限なし: `short` で残りの不足があれば今までどおり不足の分。それ以外は 0 にして `unlimitedWanted` に入れる。
   - 1回の個数が 0 以下の品目は今までどおり 0。
   - 「不要」の既定で交換する品目は、今までの規則のまま（`short` なら不足の分、それ以外は 0）。
   ほかの品目の扱いは変えない（「必要」を使うのは `outside` のときだけ）。
6. **上限なしの案内。** 今の「上限なし: 回数を入れてください」は `outside` の分岐にしかないので、`unlimitedWanted` に入った既定で交換する品目（`short`・`enough`・`unused` の行）でも、回数が 0 で「必要」のときに出す。

## Risks / Trade-offs

- [不足が在庫上限より少ないときも上限まで入るので、必要量より多く交換する] → オーナーの判断（#208 の決めること①）。要らなければ「不要」にすると不足の分だけになる
- [番号 6999・1000 が将来変わる] → Atlas の番号は長く固定されている。変わったら定数を直す
- [既定で交換する品目の「不要」を `false` で保存するので、古い版の画面は `false` を「不要」として読む] → 古い版は `true` だけを見るので食い違わない
