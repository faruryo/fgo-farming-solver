# Proposal

## Why

#127 で、ロトの無い交換所イベント（例: 80632 復刻版:盈月剣風帖）も交換所と周回クエストのドロップが KV に入り、イベントページに交換所の一覧が出るようになった。しかし一覧だけで、「欲しい品目を取るには、どのクエストを何周すればよいか」は分からない（issue #128、epic #129 の B4）。今の周回計画（`allocateShop`・`buildEventDrops`・`runEventSolver`）は箱計画と組み合わさっていて、通貨も1種類しか扱わない。80632 は通貨が3種類で、1周で3種類が同時に落ちる。

## What Changes

- ロトの無い交換所イベントのイベントページで、交換所の品目ごとに交換する回数を選べるようにする（上限のある品目を全部選ぶ操作も付ける）
- 通貨ごとの所持数を入れられるようにし、通貨ごとの必要量（選んだ交換の合計 − 所持）を出す
- 通貨ごとの必要量を1つの最適化（既存のソルバー）にまとめて渡し、AP 最小の周回の内訳（クエストごとの周回数、合計の周回数と AP、通貨ごとの見込み獲得量）を出す。1周で複数の通貨が落ちることを、通貨ごとの制約として扱う
- ドロップはイベントのボーナス礼装・サーヴァントを含まない統計値なので、その前提を画面に示す（ボーナスは #130）
- 箱のあるイベントのボックス計画の結果は変えない

## Capabilities

### New Capabilities
（なし）

### Modified Capabilities
- `event-planner`: ロトの無い交換所イベントで、交換所の品目の選択から通貨ごとの必要量と周回の内訳を出す

## Impact

- `lib/event-plan.ts`（通貨ごとの需要を受け取る形のソルバーへの渡し方を足す。既存の関数の結果は変えない）、`lib/event-shop-summary.ts`
- `components/events/EventHubClient.tsx`（ロトの無い交換所イベントのセクション）、新しい周回計画の部品
- `locales` の events の文言
- 各ユニットテストと、画面の確認（375px と desktop）
