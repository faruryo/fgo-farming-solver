# Proposal

## Why

所持サーヴァントは、育成計算機のカードを1騎ずつ押して「所持」にするしかなく、Lv と宝具Lv は入れる場所が無い（#260）。あとで作るレイド向けの編成計算は、誰を持っていて Lv と宝具Lv がいくつかを入力にするので、ゲームのスクリーンショットからまとめて取り込めるようにする。画面から切り出したアイコンを Atlas のアイコンと比べる部品は、交換所の取り込み（#220）で main に入っているので使い回す。

オーナーの実物のスクリーンショット2枚（ゲームの「サーヴァント強化」のサーヴァント選択画面を、並びを「宝具Lv.順」と「Lv.順」にして iPhone で撮ったもの）が届いた。この仕様は、その2枚で測った値で読み取りを決める。前の版が頼った古い参考画像は根拠から外した。測った結果、(1) 並びを「宝具Lv.順」にした画面は1枚のカードから宝具Lv と Lv の両方が読める、(2) 交換所の取り込みの比べ方（明るさをそろえる）は候補が約 2,000 枚あると使えず、明るさをそろえない比べ方で重なる表示の升目を除くと 42 枚全部が大差で当たる、(3) 画像をまるごと読む文字認識ではカードの文字が読めず、カードごとに文字の帯を切り出して拡大すれば全部読める、と分かった（design.md の Context）。

## What Changes

- 育成計算機のサーヴァントの一覧の上に「スクリーンショットから取り込む」の入口を足す。ゲームの「サーヴァント強化」のサーヴァント選択画面のスクリーンショットを何枚か選ぶと、ブラウザの中で読み取る。画像は外に送らない。並びを「宝具Lv.順」にして撮るよう案内し、「Lv.順」の画像も受け付ける（Lv だけを読む）
- 画面の上の見出しの文字でこの画面かを見分け、7 列の格子の横の位置と大きさを決める。段の縦の位置は顔の照合で探す。下の端で切れた段は読まない
- カードごとに顔の部分を、Atlas の顔のアイコン（再臨の段階と霊衣のものを含む）と比べてサーヴァントを当てる。クラスのアイコン・鍵・星・文字・「PARTY」などが重なる所は比べない。一番近いサーヴァントからも遠いカードと、次に近い別のサーヴァントとの差が小さいカードは「要確認」にする
- カードごとに上と下の文字の帯を拡大して読み、「数字/数字」の形から宝具Lv と Lv を取る。複数の画像の結果をサーヴァントごとにまとめ、同じサーヴァントで読みが食い違うとき（同じサーヴァントを複数持つ場合を含む）は「要確認」にする
- 取り込む前に、読み取った結果を確かめて直せる画面を出す。「要確認」のカードは、利用者がサーヴァントと値を決めるまで入れない。当てたカードは、切り抜いた顔と当てたサーヴァントのアイコンを並べて出す
- 確定すると、入れたサーヴァントを育成計算機の「所持」にし、Lv と宝具Lv を新しい保存先に端末で保存する。育成計画の値（再臨・スキル・アペンドスキルの今と目標）は変えない。入れなかったサーヴァントの値は変えない
- 顔のアイコンの照合に使う小さなデータ（アイコンを 16×16 に縮めたもの）を、マスターデータの更新ジョブで作って配る。利用者の端末が顔のアイコンを1枚ずつ取りに行かないようにする

## Capabilities

### New Capabilities

- `servant-roster-screenshot-import`: 「サーヴァント強化」のサーヴァント選択画面のスクリーンショットからカードごとにサーヴァントを見分け、Lv と宝具Lv を読み、取り込む前に確かめて直せること。入れたサーヴァントを所持にし、Lv と宝具Lv を育成計画の値と別に端末へ保存すること。照合に使う顔のアイコンのデータを事前に作って配ること

### Modified Capabilities

（なし）

## Impact

- `lib/shop-screenshot-import/icon-match.ts`: 縮小（`cropCells`・`downscaleIcon`・`integralImage`）・明るさをそろえない差（`rawPixelDiff`）・位置を振る関数（`coarseRects`）をそのまま使う。このファイルは変えない。明るさをそろえる差と通貨の決め方は使わない
- `lib/`（新しいモジュール）: 画面の見分けと格子の組み立て、文字の帯からの値の読み取り、顔の照合、画像をまたいだまとめ。画像なしでテストできる純粋な関数にする
- `lib/possession-import/ocr-engine.ts`: 枠つきの文字認識（`recognizeWithBoxes`）をそのまま使う（画像のまるごとに1回と、カードごとの文字の帯に）。変えない
- マスターデータの更新ジョブ（`scripts/run-updater.ts`）と `MASTER_DATA` の KV: 顔のアイコンの照合用データを作って置く段を足す。配る API のルートを1つ足す
- `components/material/`: 取り込みの入口と確かめの画面。既存の所持の印（`material` の保存値の中）を、入れたサーヴァントについて「所持」にする
- 新しい保存先（端末の localStorage のキーを1つ）: サーヴァントごとの Lv と宝具Lv。`ChaldeaState`（`hooks/create-chaldea-state.ts`）の形は変えない。クラウド同期の対象には足さない
- 外部への要求: 更新ジョブが Atlas の顔のアイコン（`https://static.atlasacademy.io/JP/Faces/`）を取得する。利用者の画像は送らない
- 所持数の画面の取り込み（`possession-screenshot-import`）と交換所の取り込み（`event-shop-remaining-import`）の挙動は変えない
- 既存のデータの取り込み・判定・絞り込みの条件は変えない（新しい機能の追加）ので、対象の件数は数えない
