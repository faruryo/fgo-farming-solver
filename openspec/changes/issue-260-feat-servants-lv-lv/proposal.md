# Proposal

## Why

所持サーヴァントは、育成計算機のカードを1騎ずつ押して「所持」にするしかなく、Lv と宝具Lv は入れる場所が無い（#260）。あとで作るレイド向けの編成計算は、誰を持っていて Lv と宝具Lv がいくつかを入力にするので、ゲームの霊基一覧のスクリーンショットからまとめて取り込めるようにする。画面から切り出したアイコンを Atlas のアイコンと比べる部品は、交換所の取り込み（#220）で main に入っているので使い回す。

オーナーの実物の霊基一覧のスクリーンショットはまだ無い。この仕様は、古い参考画像2枚（中国版のスキル強化の選択画面、2020年の日本版の霊基変還の一覧）で決められる骨格までを決め、実物を見ないと決められない点は design.md の「実物で確かめてから決める点」に分けて、数値を推測で決めない。

## What Changes

- 育成計算機のサーヴァントの一覧の上に「スクリーンショットから取り込む」の入口を足す。ゲームの霊基一覧のスクリーンショットを何枚か選ぶと、ブラウザの中で読み取る。画像は外に送らない
- 画像の中のカードの並び（格子）を見つけ、カードごとに顔のアイコンを切り出して、Atlas の顔のアイコン（再臨の段階と霊衣のものを含む）と比べてサーヴァントを当てる。一番近いサーヴァントと次に近い別のサーヴァントの差が小さいカードは「要確認」にする
- カードに出ている文字から Lv と宝具Lv を読む。カードに出る文字はゲームの並び順で変わるので、画像ごとに読めた種類の値だけを取り、複数の画像の結果をサーヴァントごとにまとめる。同じサーヴァントで値が食い違うとき（同じサーヴァントを複数持つ場合を含む）は「要確認」にする
- 取り込む前に、読み取った結果を確かめて直せる画面を出す。「要確認」のカードは、利用者がサーヴァントと値を決めるまで入れない。当てたカードは、切り抜いた顔と当てたサーヴァントのアイコンを並べて出す
- 確定すると、入れたサーヴァントを育成計算機の「所持」にし、Lv と宝具Lv を新しい保存先に端末で保存する。育成計画の値（再臨・スキル・アペンドスキルの今と目標）は変えない。入れなかったサーヴァントの値は変えない
- 顔のアイコンの照合に使う小さなデータ（アイコンを 16×16 に縮めたもの）を、マスターデータの更新ジョブで作って配る。利用者の端末が顔のアイコンを1枚ずつ取りに行かないようにする

## Capabilities

### New Capabilities

- `servant-roster-screenshot-import`: 霊基一覧のスクリーンショットからカードごとにサーヴァントを見分け、Lv と宝具Lv を読み、取り込む前に確かめて直せること。入れたサーヴァントを所持にし、Lv と宝具Lv を育成計画の値と別に端末へ保存すること。照合に使う顔のアイコンのデータを事前に作って配ること

### Modified Capabilities

（なし）

## Impact

- `lib/shop-screenshot-import/icon-match.ts`: 縮小・差の取り方・探し方を使い回す。候補が多いこと（顔のアイコン 2,066 枚）とカードの上に重なる表示への対応は関数を足して行い、交換所の取り込みの挙動は変えない
- `lib/`（新しいモジュール）: カードの格子の組み立て、カードの文字からの値の読み取り、顔の照合、画像をまたいだまとめ。画像なしでテストできる純粋な関数にする
- `lib/possession-import/ocr-engine.ts`: 枠つきの文字認識（`recognizeWithBoxes`）をそのまま使う。変えない
- マスターデータの更新ジョブ（`scripts/run-updater.ts`）と `MASTER_DATA` の KV: 顔のアイコンの照合用データを作って置く段を足す。配る API のルートを1つ足す
- `components/material/`: 取り込みの入口と確かめの画面。既存の所持の印（`material` の保存値の中）を、入れたサーヴァントについて「所持」にする
- 新しい保存先（端末の localStorage のキーを1つ）: サーヴァントごとの Lv と宝具Lv。`ChaldeaState`（`hooks/create-chaldea-state.ts`）の形は変えない。クラウド同期の対象には足さない
- 外部への要求: 更新ジョブが Atlas の顔のアイコン（`https://static.atlasacademy.io/JP/Faces/`）を取得する。利用者の画像は送らない
- 所持数の画面の取り込み（`possession-screenshot-import`）と交換所の取り込み（`event-shop-remaining-import`）の挙動は変えない
- 既存のデータの取り込み・判定・絞り込みの条件は変えない（新しい機能の追加）ので、対象の件数は数えない
