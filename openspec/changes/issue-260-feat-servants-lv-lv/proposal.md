# Proposal

## Why

所持サーヴァントは、育成計算機のカードを1騎ずつ押して「所持」にするしかなく、Lv と宝具Lv は入れる場所が無い（#260）。あとで作るレイド向けの編成計算は、誰を持っていて Lv と宝具Lv がいくつかを入力にするので、ゲームのスクリーンショットからまとめて取り込めるようにする。画面から切り出したアイコンを Atlas のアイコンと比べる部品は、交換所の取り込み（#220）で main に入っているので使い回す。

オーナーの実物のスクリーンショット6枚（ゲームの「サーヴァント強化」のサーヴァント選択画面を iPhone で撮ったもの。一覧のいちばん上を「宝具Lv.順」と「Lv.順」で撮った2枚と、「宝具Lv.順」で一覧を途中まで送った3枚・最後まで送った1枚）が届いた。この仕様は、その6枚で測った値で読み取りを決める。前の版が頼った古い参考画像は根拠から外した。測った結果、(1) 並びを「宝具Lv.順」にした画面は1枚のカードから宝具Lv と Lv の両方が読める、(2) 交換所の取り込みの比べ方（明るさをそろえる）は候補が約 2,000 枚あると使えず、明るさをそろえない比べ方で重なる表示の升目を除くと、6枚のまるごと写った 120 枚全部が大差で当たる、(3) 画像をまるごと読む文字認識ではカードの文字が読めず、カードごとに文字の帯を切り出して拡大すれば全部読める、と分かった（design.md の Context）。

## What Changes

- 育成計算機のサーヴァントの一覧の上に「スクリーンショットから取り込む」の入口を足す。ゲームの「サーヴァント強化」のサーヴァント選択画面のスクリーンショットを何枚か選ぶと、ブラウザの中で読み取る。画像は外に送らない。並びを「宝具Lv.順」にして撮るよう案内し、「Lv.順」の画像も受け付ける（Lv だけを読む）
- 画面の上の見出しの文字でこの画面かを見分け、7 列の格子の横の位置と大きさを決める。段の縦の位置は顔の照合で探す。下の端で切れた段と、上の端で見出しやボタンの帯に隠れた段は読まない
- カードごとに顔の部分を、Atlas の顔のアイコン（再臨の段階と霊衣のものを含む）と比べてサーヴァントを当てる。クラスのアイコン・鍵・星・文字・「PARTY」などが重なる所は比べない。一番近いサーヴァントからも遠いカードと、次に近い別のサーヴァントとの差が小さいカードは「要確認」にする
- カードごとに上と下の文字の帯を拡大して読み、「数字/数字」の形から宝具Lv と Lv を取る。画面の上の所持数と、並びの項目（宝具Lv.順か Lv.順か）と向き（降順か昇順か）も読む
- Lv と宝具Lv が下がらないことと画面の作りで読みを検査する（値の範囲、サーヴァントのレア度と Lv の上限、並び順、前に取り込んだ値、所持数と読めたカードの数）。検査に通らなかった読みは取り込む値の候補から外し、通った読みが無いサーヴァントは「要確認」にして、前後のカードから推定できる値を候補に添える（issue のオーナーのコメント、2026-11-14）
- 複数の画像の結果をサーヴァントごとにまとめる。同じサーヴァントを複数持つときは、一番強い1騎（宝具Lv が高いほう、同じなら Lv が高いほう）だけを取り込み、ほかの個体は捨てる（オーナーの決定）
- 取り込む前に、読み取った結果を確かめて直せる画面を出す。「要確認」のカードは、利用者がサーヴァントと値を決めるまで入れない。当てたカードは、切り抜いた顔と当てたサーヴァントのアイコンを並べて出す
- 確定すると、入れたサーヴァントを育成計算機の「所持」にし、Lv と宝具Lv を新しい保存先に保存する。育成計画の値（再臨・スキル・アペンドスキルの今と目標）は変えない。入れなかったサーヴァントの値は変えない
- Lv と宝具Lv の保存先をクラウド同期の対象に足す（オーナーの決定、2026-11-14:「基本スマホから入力するけど PC からみたい」）。同期の方式（保存内容をまるごと入れ替える、新旧と競合の決め方）は変えず、同期するキーを1つ足す。取り込みの無い端末がクラウドの Lv・宝具Lv を黙って消さないよう、縮小ガードに「Lv・宝具Lv を持つサーヴァントの数」の指標を足し、食い違いの画面・縮小の確認・見比べにその数を出す
- 育成計算機のカードに、保存されている Lv と宝具Lv を出す（「所持」のカードだけ、表示だけ）。PC で見る場所はここにする
- 顔のアイコンの照合に使う小さなデータ（アイコンを 16×16 に縮めたもの）を、マスターデータの更新ジョブで作って配る。利用者の端末が顔のアイコンを1枚ずつ取りに行かないようにする

## Capabilities

### New Capabilities

- `servant-roster-screenshot-import`: 「サーヴァント強化」のサーヴァント選択画面のスクリーンショットからカードごとにサーヴァントを見分け、Lv と宝具Lv を読み、取り込む前に確かめて直せること。入れたサーヴァントを所持にし、Lv と宝具Lv を育成計画の値と別に保存して、育成計算機のカードに出すこと。照合に使う顔のアイコンのデータを事前に作って配ること

### Modified Capabilities

- `sync`: サーヴァントごとの Lv・宝具Lv をクラウド同期の対象に足す。縮小ガードの指標を3つから4つにし（Lv・宝具Lv を持つサーヴァントの数を足す）、食い違いの選択モーダル・縮小の確認ダイアログ・同期管理画面の見比べにその数を出す。同期の方式と、既存の3つの指標の決め方は変えない

## Impact

- `lib/shop-screenshot-import/icon-match.ts`: 縮小（`cropCells`・`downscaleIcon`・`integralImage`）・明るさをそろえない差（`rawPixelDiff`）・位置を振る関数（`coarseRects`）をそのまま使う。このファイルは変えない。明るさをそろえる差と通貨の決め方は使わない
- `lib/`（新しいモジュール）: 画面の見分けと格子の組み立て、文字の帯からの値の読み取り、顔の照合、画像をまたいだまとめ。画像なしでテストできる純粋な関数にする
- `lib/possession-import/ocr-engine.ts`: 枠つきの文字認識（`recognizeWithBoxes`）をそのまま使う（画像のまるごとに1回と、カードごとの文字の帯に）。変えない
- マスターデータの更新ジョブ（`scripts/run-updater.ts`）と `MASTER_DATA` の KV: 顔のアイコンの照合用データを作って置く段を足す。配る API のルートを1つ足す
- `components/material/`: 取り込みの入口と確かめの画面。既存の所持の印（`material` の保存値の中）を、入れたサーヴァントについて「所持」にする。カード（`servant-card.tsx`）に Lv・宝具Lv の表示を足す
- 新しい保存先（localStorage のキーを1つ）: サーヴァントごとの Lv と宝具Lv。`ChaldeaState`（`hooks/create-chaldea-state.ts`）の形は変えない
- クラウド同期: 同期するキーの一覧（`lib/constants/storage-keys.ts` の `CLOUD_SYNC_KEYS`）に新しいキーを足す。`lib/cloud-sync/shrink-guard.ts` の規模と判定に指標を1つ足し、`components/cloud/` の縮小の確認ダイアログ・食い違いの画面・見比べに数を出す。`hooks/use-cloud-sync.ts` の保存・取り込み・新旧の決まりと、`/api/cloud`・スナップショット（本文を中身を見ずに置く）は変えない。クラウドの保存内容と日ごとのスナップショットが、Lv・宝具Lv のぶん大きくなる（1騎あたり約 30 バイト、500 騎で約 15KB）
- 古い版のアプリ（デプロイをまたいで開いたままのタブ）が保存すると、クラウドの保存内容から Lv・宝具Lv が消える。持っている端末の値は消えず、その端末の次の保存で戻る（design.md の「クラウド同期」）
- 外部への要求: 更新ジョブが Atlas の顔のアイコン（`https://static.atlasacademy.io/JP/Faces/`）を取得する。利用者の画像は送らない
- 所持数の画面の取り込み（`possession-screenshot-import`）と交換所の取り込み（`event-shop-remaining-import`）の挙動は変えない
- 対象の件数: 縮小ガードの判定に指標を1つ足すが、この指標が数える Lv・宝具Lv の保存値はこの変更で初めてできるもので、今あるクラウドの保存内容には無い。クラウドの数が 0 の間は止まらないので、今ある保存内容で新しく止まる保存は 0 件（数えた方法: 判定の式「クラウドの数から 10 以上減り、半分以下になる」に、新しいキーの無い保存内容の数 0 を当てた。本番の KV・D1 の保存内容は読んでいない）。既存の3つの指標と、ほかの取り込み・絞り込みの条件は変えない
