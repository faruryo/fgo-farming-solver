# Spec Delta

## ADDED Requirements

### Requirement: 所持サーヴァントの Lv・宝具Lv のクラウド同期
システムは、サーヴァントごとの Lv・宝具Lv の保存値（`servant-roster-screenshot-import`）をクラウド同期の対象に含め、複数端末間で同期しなければならない (SHALL)。Lv・宝具Lv は、保存内容の中の独立した1項目として載せ、既存の項目の中身と保存内容の形を変えてはならない (MUST NOT)。端末の間の新旧・競合・食い違いは、ほかの同期対象と同じ決まりで扱い、Lv・宝具Lv をサーヴァントごとに合成してはならない (MUST NOT)。クラウドの保存内容に Lv・宝具Lv の項目が無いとき、取り込みでこの端末の Lv・宝具Lv を消してはならない (MUST NOT)。食い違いの選択モーダル、縮小の確認ダイアログ、保存が保留されている間の同期管理画面の規模の対比、同期管理画面の見比べは、端末の側とクラウドの側のそれぞれについて、Lv か宝具Lv の値を持つサーヴァントの数を示さなければならない (SHALL)。

#### Scenario: スマホで取り込んだ値が PC に届く
- **WHEN** オートシンクが有効なスマホで、スクリーンショットから Lv・宝具Lv を取り込んで確定したとき
- **THEN** 変更から 5 秒後に `/api/cloud` を通じて Cloudflare KV に Lv・宝具Lv が保存される
- **WHEN** 未同期の変更が無い別の認証済み端末（PC）で、ログインまたは同期を実行したとき
- **THEN** クラウドに保存された Lv・宝具Lv が PC に復元・適用される

#### Scenario: 別の端末のほうが新しい
- **WHEN** この端末に Lv 80 が保存されているサーヴァントについて、別の端末が Lv 90 を取り込んで保存し、この端末に未同期の変更が無い状態で同期を実行したとき
- **THEN** この端末の Lv・宝具Lv は、クラウドの保存内容のものにまるごと置き換わり、そのサーヴァントの Lv は 90 になる

#### Scenario: 別の端末のほうが新しく、この端末にも未同期の変更がある
- **WHEN** 2つの端末がそれぞれ別のサーヴァントの Lv・宝具Lv を取り込み、片方が先に保存し、もう片方がクラウドのほうが新しいことを検出したとき
- **THEN** 既存のコンフリクトとして扱い、自動で適用も保存もしない
- **THEN** 利用者が選んだ側の Lv・宝具Lv がまるごと残り、選ばなかった側だけにあった Lv・宝具Lv を混ぜない

#### Scenario: 一度も同期していない端末で取り込んだ
- **WHEN** 一度もクラウドと同期していない端末で Lv・宝具Lv を 300 騎ぶん取り込み、クラウドには Lv・宝具Lv の無い保存内容があるとき
- **THEN** 既存の分岐状態として選択モーダルを出し、この端末の側に 300、クラウドの側に 0 を、Lv・宝具Lv の値を持つサーヴァントの数として示す

#### Scenario: 古い版のアプリが同期データを読む
- **WHEN** Lv・宝具Lv を同期対象に持たない古い版のアプリが、Lv・宝具Lv を含むクラウドの保存内容を取り込むとき
- **THEN** 古い版が知っている項目は今までどおり適用され、Lv・宝具Lv の項目があることで取り込みが失敗しない

#### Scenario: Lv・宝具Lv の項目の無い保存内容を取り込む
- **WHEN** Lv・宝具Lv が保存されている端末が、Lv・宝具Lv の項目の無いクラウドの保存内容（古い版のアプリか、取り込みを確定していない端末が保存したもの）を取り込むとき
- **THEN** この端末の Lv・宝具Lv は消えず、取り込みの前と同じ値で残る
- **WHEN** そのあと、この端末がクラウドへ保存したとき
- **THEN** クラウドの保存内容に Lv・宝具Lv が戻る

#### Scenario: この版が知らない欄を同期で落とさない
- **WHEN** Lv・宝具Lv の保存値の中に、この版が知らない欄を持つクラウドの保存内容を取り込み、そのあとこの端末から保存したとき
- **THEN** クラウドの保存内容の Lv・宝具Lv に、知らない欄が取り込みの前と同じ値で残っている

## MODIFIED Requirements

### Requirement: 破壊的な縮小保存の抑止
システムは、クラウドへ保存しようとする内容がクラウドの現行値より極端に少ないとき、保存を中断してユーザーに確認を求めなければならない (SHALL)。判定は自動保存・手動保存の双方に適用し、コンフリクトのバイパス(強制上書き)によって迂回できてはならない (SHALL NOT)。

判定指標は次の4つとし、いずれか1つでも成立したとき縮小とみなさなければならない (SHALL)。

- 有効サーヴァント件数(`material` のうち `all` を除き `disabled` でないもの): クラウド値から10件以上かつ半数以下へ減少
- 所持アイテム種類数(`posession` のうち数量が正のもの): 同上
- Lv・宝具Lv を持つサーヴァント件数(サーヴァントごとの Lv・宝具Lv の保存値のうち、Lv が 1〜120 の整数であるか、宝具Lv が 1〜5 の整数であるもの。保存値が無いときは 0 件): 同上
- 同期対象キーの欠落: クラウドに存在する同期対象キーのうち、保存内容に含まれないものが2件以上ある

指標の算出はアイテムカタログなどの外部データに依存してはならない (SHALL NOT)。キー欠落の判定対象は、現行の同期対象キー一覧とクラウド保存内容の積集合に限らなければならない (SHALL)。単一キーの削除は正規のデータ移行として起こりうるため、欠落1件で発火させてはならない (SHALL NOT)。

#### Scenario: 空同然のデータによる上書き
- **WHEN** ローカルの有効サーヴァントが0件・所持アイテムが0種類の状態で、クラウドに461件・104種類のデータがある状態で保存が実行されるとき
- **THEN** 保存を中断し、確認ダイアログを表示する。

#### Scenario: 通常の編集
- **WHEN** 有効サーヴァントが461件から458件へ、所持アイテムが104種類から95種類へ減る保存が実行されるとき
- **THEN** 確認を挟まず保存する。

#### Scenario: 初回保存
- **WHEN** クラウドにデータが無い状態で保存が実行されるとき
- **THEN** 確認を挟まず保存する。

#### Scenario: 同期対象キーの消失
- **WHEN** クラウドに存在する同期対象キーが2件以上、保存内容から欠落しているとき
- **THEN** サーヴァント件数・所持種類数の増減にかかわらず保存を中断し、確認ダイアログを表示する。

#### Scenario: 単一キーのデータ移行
- **WHEN** 旧形式のキー1件が移行によって削除され、それ以外に縮小が無いとき
- **THEN** 確認を挟まず保存する。

#### Scenario: 片方の端末にだけ Lv・宝具Lv の取り込みがある
- **WHEN** クラウドに 300 騎ぶんの Lv・宝具Lv があり、Lv・宝具Lv を一度も取り込んでおらず保存値の無い端末が、有効サーヴァント件数と所持アイテム種類数の変わらない保存を実行するとき
- **THEN** 保存を中断し、確認ダイアログに、保存しようとした内容の 0 件とクラウドの 300 件を Lv・宝具Lv を持つサーヴァント件数として表示する。
- **THEN** 同期管理画面を開くと、保留中の規模の対比にも同じ 0 件と 300 件が出ている。

#### Scenario: Lv・宝具Lv の無いクラウドへの保存
- **WHEN** クラウドの保存内容に Lv・宝具Lv が無く（この変更の前に保存されたもの）、保存が実行されるとき
- **THEN** Lv・宝具Lv を持つサーヴァント件数を理由に保存を中断しない。

#### Scenario: Lv・宝具Lv が増える保存
- **WHEN** クラウドに 300 騎ぶんの Lv・宝具Lv があり、320 騎ぶんの Lv・宝具Lv を持つ保存が実行されるとき
- **THEN** 確認を挟まず保存する。
