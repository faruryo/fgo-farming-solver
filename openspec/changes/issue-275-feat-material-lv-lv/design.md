# Design

## Context

動機は proposal.md の Why を参照。

**今の作り**（main 5903ada のコードを読んで確かめた）

- カード（`components/material/servant-card.tsx`、`memo` で包んである）は、所持のときだけ、クラス名の行に Lv・宝具Lv の文字（`data-testid="servant-card-level"` の `span`）を出す。押しても何も起きない。カードの中の操作は、顔のリンク（`/servants/[id]`）、再臨のピップとスキルのチップ（押して +1、長押し・右クリックで -1）、所持の切り替えのボタン
- 一覧（`components/material/index.tsx`）は `useServantLevels` を1回呼び、カードごとに `lv`・`npLv` を渡す。474 枚のカードを常に描く
- 保存値（localStorage の1つのキー）は `{"<サーヴァントの ID>": {"lv": 90, "npLv": 2}}` の形。`lib/servant-levels.ts` の `withServantLevels` は取り込みの行を重ねる関数で、値の無い欄（`null`・範囲の外）を「前の値を残す」と読む。消す関数は無い
- `useServantLevels`（`hooks/use-servant-levels.ts`）は `lazyWrite` で、setter が呼ばれるまで書かない。書けば同期の通知が出て未同期の編集になる
- 縮小ガード（`lib/cloud-sync/shrink-guard.ts`）は「Lv・宝具Lv を持つサーヴァントの数」も比べ、`SHRINK_MIN_DELTA`（10）以上減って半分以下になる保存を止める。1騎ずつの消去は1回の保存で 1 しか減らないので届かない
- 取り込みの確かめ画面の欄の読み方は `lib/servant-roster-review.ts` の `readField`（空は「値なし」、`^\d+$` で、Lv 1〜120・宝具Lv 1〜5 の範囲の外は「範囲に無い」）
- `components/ui/dialog.tsx` は Base UI の Dialog を包んだもの。Popup は `initialFocus`・`finalFocus` を受け取れ、Escape と外側の押下で閉じ、開いている間はフォーカスを中に閉じ込める

**要素の数**（brainstorm で dev の `/material` を Playwright で開いて `document.querySelectorAll('*').length` で数えた。issue の材料のコメント）

| 状態 | 要素数 |
|---|---|
| 全騎が未所持 | 21,157 |
| 全騎が所持 | 29,689 |

## Goals / Non-Goals

**Goals:**

- カードの要素を、値のある騎では増やさず、値の無い所持の騎でも1つまでにする
- 手入力と取り込みで、通る値と保存値の書き方（知らない欄を残す）をそろえる

**Non-Goals:**

- 未所持のカードからの入力、入れたら所持にする動き（オーナーの決定で入口を出さない）
- レア度・聖杯の刻みによる検査（オーナーの決定で入れない）
- サーヴァントの詳細ページ（`/servants/[id]`）での入力
- 同期の方式・縮小ガード・取り込みの流れの変更

## Decisions

### 判断点

なし。入れる場所（案 C）と未所持のカードの扱い（入口を出さない）はオーナーが 2026-11-16 に決めた。値の確認の範囲も同じ日に決まった。下の細部は、オーナーの好み（文言を短く、画面に情報を詰め込まない）と既存の作りから1つに決まるので、「決めたこと」に理由とともに書く。

### 決めたこと

1. **小窓は一覧に1つだけ置く**。一覧が「直しているサーヴァントの ID」（無ければ閉じている）を持ち、Dialog を1つ描く。カードは編集の状態を持たず、押されたことを `onEditLevel(servantId, button)` のような1つのコールバックで一覧へ知らせるだけにする。一覧はこのコールバックを `useCallback` で固定し、`memo` のカードが小窓の開閉で描き直されないようにする。理由: カードに状態を持たせると 474 枚それぞれに入力の状態が要り、#126 の負荷に戻るため（材料の決めたこと）
2. **ボタンの文字は今の表示のまま**。値のある騎は「Lv 90・宝具 2」（片方なら片方）、値の無い所持の騎は「Lv –」。ボタンは今の `span` と同じ場所（クラス名の行）に置き、見た目は文字のまま（下線や枠を常には出さない）。押せることは、ポインタを載せたときとフォーカスのときの見た目で示す。理由: 材料の「値のある騎は今の表示をボタンに替えるだけ」をそのまま取り、カードの見た目を変えないため
3. **ボタンの読み上げの名前**は「<サーヴァント名> の Lv・宝具Lv を入れる」。見える文字（値）はそのまま読ませ、名前に値を重ねない。理由: 474 枚のボタンが同じ「Lv 90・宝具 2」になると、どの騎のボタンか分からないため
4. **小窓の中身**は、見出しにサーヴァント名、「Lv」と「宝具Lv」の欄（ラベルつき）、注記1つ「空にして保存すると消えます」、保存とキャンセルのボタン。範囲の説明は注記に入れず、範囲に無い欄だけを見た目と `aria-invalid` で示し、保存を押せなくする。理由: オーナーの「小窓の中は名前・Lv・宝具・保存・キャンセルと短い注記1つまで」。範囲は打ち間違えたときにだけ要る情報なので、常には出さない
5. **欄は数字の文字の欄**（`inputMode="numeric"`、`type="text"`）にし、読み方は `readField` をそのまま使う。`type="number"` は使わない。理由: `readField` は文字列を読む関数で、取り込みの確かめ画面と同じ入力を同じように扱えるため。`type="number"` はブラウザが `1e2` などを通し、空と不正の区別もブラウザごとに違う
6. **開いたときのフォーカスは Lv の欄**（`initialFocus`）、**閉じたときは開いたボタン**（`finalFocus` に、押されたボタンの要素を渡す）。Dialog に Trigger を使わない（ボタンは474 枚のカードに散らばっていて、小窓は1つのため）ので、戻り先を明示する。Enter は欄の `form` の送信で保存にする
7. **保存の書き方**は、`lib/servant-levels.ts` に1騎を欄のとおりに置き換える純粋関数（例: `withServantLevel(prev, id, { lv, npLv })`。`lv`・`npLv` は数か `null`）を足す。`null` の欄はその騎の項目から消し、数の欄は置き換える。その騎の項目のうち `lv`・`npLv` 以外の欄は残す。`lv`・`npLv` を消して残る欄が無くなった項目はキーごと消す。ほかの騎の項目には触れない。`useServantLevels` はこれを `setStored(prev => …)` で呼ぶ setter を返す。理由: 取り込みの `withServantLevels` は空を「残す」と読むので、空を「消す」と読む別の関数が要る（材料の決めたこと）。空の項目を残しても読む側は無視するが、保存値を小さく保つほうを取る
8. **値が変わらないときは書かない**。保存を押した時点の欄の値が、今の保存値（`readServantLevels` で読んだもの）と同じなら setter を呼ばずに閉じる。理由: `lazyWrite` の hook は setter を呼ぶだけで保存値を作り、同期の通知を出すため。値の無い騎の「Lv –」を開いて空のまま保存しても、保存値と未同期の編集を作らない
9. **小窓を開いている間にクラウド同期で値が変わったとき**は、欄の値は開いたときのまま残し、保存すると、その騎の Lv・宝具Lv を欄のとおりに置き換える（関数は最新の保存値に重ねるので、ほかの騎の同期の値は残る）。理由: 利用者が入力している最中に欄を書き換えると、打った値が消えるため
10. **未所持への切り替えと小窓**: 小窓が開いている間はモーダルで、カードの所持の切り替えは押せない。カードが未所持になったあとは入口を出さない（保存値は残す。今の表示の要件と同じ）
11. **文言**は既存のカードと同じく `t()` のキーを足し、`locales/ja.json` と `locales/en.json` に同じキーを足す（`servant-card-lv`・`servant-card-np-lv` の隣）

## Risks / Trade-offs

- [値の無い所持の騎に「Lv –」が増え、全騎が所持のとき最大 +474 要素] → 1枚に1要素だけで、案 A の +2,370 の 1/5。材料の測定で 29,689 → 30,163 前後（+1.6%）
- [カードの見た目が文字のままで、押せると気付かれにくい] → ホバーとフォーカスの見た目で示す。気付かれなければ、あとで見た目だけを変えられる（仕様の要件は変わらない）
- [ボタンを押す位置が再臨のピップ・スキルのチップの近くで、育成記録モードで押し違える] → ボタンはクラス名の行（ピップとチップの行の上）にあり、今の表示と同じ場所。ピップとチップの押下の処理には触れない
- [Base UI の `finalFocus` に渡したボタンが、閉じるまでに一覧の描き直し（フィルターの変更など）で消える] → 小窓はモーダルで一覧を操作できないので、開いている間にボタンは消えない。開いている間に同期の取り込みでその騎が未所持になるとボタンが消えるが、そのときはフォーカスが Base UI の既定の戻り先に移るだけで、値は壊れない
