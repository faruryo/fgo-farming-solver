## 2. 比較の計算

- [ ] 2.1 `lib/event-plan.ts` に、イベント・通貨の必要量・通貨ごとの +N・☆ ごとの入力（凸と無凸の +N と所持枚数）・フレンドの ☆ から、合計枚数ごとの最良の組み合わせと周回数・AP・1枚少ない行からの AP の減り・その行の各通貨の +N を返す純粋関数と、選んだ合計枚数（未選択を含む）と行から使う行を決める純粋関数を足す（spec の「ボーナス礼装の枚数の比較」、design の決定 3・4・5）。`applyDropBonus` と `planShopCurrencies` を使い、既存の関数の振る舞いは変えない。`lib/event-plan.test.ts` に次を足す
  - spec のシナリオ「枚数ごとの行」の値（1枚: 15周・600 AP、2枚: 12周・480 AP・120 の減り、3枚: 10周・400 AP・80 の減り、4枚以上の行が無い）
  - 「凸を先に数える」（凸1・無凸1で合計2枚が 10 周）
  - 「フレンドの礼装なし」で合計 0 枚の行から始まり、対応のある通貨の +N が 0 で解かれる
  - 対応の無い通貨には通貨ごとの +N が使われ、各行の対応のある通貨の +N は編成から求めた値になる
  - 使う行: 未選択なら AP 最少（同じ AP なら合計枚数の少ない行）、選んだ合計枚数の行があればそれ、無くなっていれば AP 最少の行
  - 同じ AP の組み合わせでは周回の少ない、次に ☆5・☆4 の少ないものが選ばれる
  - 通貨の必要量が無いとき・ドロップの統計が無いとき・集められる通貨が1つも無いときは行を返さない
  - 周回では集められない通貨があるとき、各行は集められる通貨だけで解かれ、集められない通貨が結果に示される
  - ☆ が3つ・所持が十分・合計 6 枚の最大の場合でも結果が返る
