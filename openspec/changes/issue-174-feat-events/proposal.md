# Proposal

## Why

#130（#170 の仕様）で、ロトの無い交換所イベントの交換所の周回計算に、通貨ごとの「1ドロップにつき +N」を手で入れる欄を足した。全素材が落ちる最高難易度を回るだけの利用者が迷うのは「ボーナス礼装を ☆5・☆4・☆3 それぞれ何枚付ければよいか」で、今の欄では枚数を変えるたびに各通貨の +N を自分で足し直して周回数を見比べるしかない（issue #174）。

## What Changes

- イベントデータの取り込みで、ロトの無い交換所イベントの交換所の通貨ごとに、その通貨のドロップを増やすボーナス礼装の ☆ を、Atlas の礼装のスキル（イベントのドロップ増加の効果）から決めて保存する。通貨と ☆ を手で割り当てない（オーナーの判断⑤）。☆ が1つに決まらない通貨とイベントポイントは対応させない
- 交換所の周回計算に、☆ ごとの礼装1枚あたりの +N（凸と無凸を分ける）と、☆ ごとの凸・無凸の所持枚数と、フレンドの礼装の ☆ を入れる欄を足す（オーナーの判断③④）。既存の通貨ごとの +N 欄は残す（判断②）
- 合計 0〜6 枚（フレンドの1枠を含む。フレンドの1枠は凸の値で数える）のそれぞれで、所持の範囲で AP が最も少ない ☆5・☆4・☆3 の枚数の組み合わせと、その周回数・AP・1枚少ないときからの AP の減りを並べる比較の表を足す。各行は「礼装1枚あたりの +N × 枚数」から各通貨の +N を出し、今の交換所の周回計算に渡して求める（判断②）
- `event-drop-bonus` の「礼装の所持を入れる欄を設けてはならない」を、交換所の周回計算について改訂する（オーナーの許可）。箱計画の同じ要件は変えない（判断①: 箱計画には載せない）

## Capabilities

### New Capabilities
（なし）

### Modified Capabilities
- `event-drop-bonus`: 交換所の「ボーナスの入力」から礼装の所持の欄の禁止を外し、ボーナス礼装の ☆ と通貨の対応の取り込み・☆ ごとの入力・枚数の比較の表の要件を足す。箱計画の要件は変えない（`event-planner` は未 archive の change `issue-127-bug-events` が持つ capability なので、取り込みの要件もこの capability に足す）

## Impact

- `scripts/refresh-event-data.ts` と `lib/refresh-event-data-compact.ts`（礼装のデータの取得と、通貨と ☆ の対応の決定）
- `lib/master-data/types.ts`（イベントデータに通貨と ☆ の対応を任意の項目として足す。取り込み直す前のデータには無い）
- `lib/event-plan.ts`（枚数の組み合わせから各通貨の +N を出し、比較の行を求める純粋関数）
- `components/events/EventShopList.tsx` と新しい部品（☆ ごとの入力と比較の表）
- `locales` の events の文言
- KV のイベントデータの形（任意の項目の追加。既存の読み手は無視する）。定期ジョブの次の実行で取り込み直される
