## MODIFIED Requirements

### Requirement: クラススコア目標素材の合算反映
システムは、育成の必要数を「サーヴァント育成ぶん」と「クラススコアぶん」に分けて扱わなければならない (SHALL)。育成ぶんは育成素材計算機が `material/result` とは別の保存先に書き、クラススコアぶんは保存せずクラススコアの状態から求める。画面に出す必要数は両者をアイテムIDごとに足した値とし、素材結果画面・周回ソルバー連携・クエスト効率・ダッシュボード・進捗レポートは、同じ1つの合算の手順を通して必要数を読まなければならない (SHALL)。

#### Scenario: クラススコア目標を含む必要素材の計算
- **GIVEN** サーヴァント育成目標とクラススコア目標（例: セイバー目標）が設定されている
- **WHEN** ユーザーが素材計算を実行したとき
- **THEN** 育成ぶんの保存先にはサーヴァント育成に必要な素材だけが保存され、クラススコアぶんは含まれない
- **THEN** 素材結果画面と周回ソルバー（`/farming`）への連携パラメータには、育成ぶんとクラススコアぶんをアイテムIDごとに合算した必要数が反映される

#### Scenario: クラススコアを変えた直後の素材結果
- **GIVEN** 素材計算を一度実行したあと、クラススコア画面で目標のマスを増やした
- **WHEN** ユーザーがクラススコア画面のリンクから `/material/result` を開いたとき
- **THEN** 各素材の必要数は、増やした目標マスぶんを含む値で表示され、内訳のクラススコアぶんが全体の必要数を上回らない
- **THEN** `/material` で素材計算を実行し直す必要はない

#### Scenario: 読む画面のあいだで必要数が一致する
- **GIVEN** 育成ぶんとクラススコアぶんの両方に必要数がある
- **WHEN** ユーザーが素材結果画面、クエスト効率、ダッシュボードの不足数、進捗レポートを順に見たとき
- **THEN** 同じアイテムの必要数はどの画面でも同じ値になる

### Requirement: マス単位クラススコア目標の素材計算結果への動的合算
システムは、クラスボード盤面上でマス単位に設定された目標のうち未解放のマスに必要な素材を、クラススコアぶんとして必要数の合算に含めなければならない (SHALL)。盤面の変更は、素材計算を実行し直さなくても、次に必要数を読んだ時点で反映されなければならない (SHALL)。

#### Scenario: マス単位目標の素材計算への合算
- **GIVEN** クラスボード詳細画面で特定のマス群が「目標」に設定されている
- **WHEN** ユーザーが素材結果画面（`/material/result`）、クエスト効率、ダッシュボードのいずれかを表示したとき
- **THEN** 目標マス（未解放分）に必要な通常素材、ピース・モニュメント、QP、星光の砂、トーチが、育成ぶんと合算された値で表示される
- **THEN** 周回ソルバー（`/farming`）の必要素材パラメータにも合算された数が反映される

## ADDED Requirements

### Requirement: 育成ぶんの必要数の自動更新
システムは、サーヴァントの状態を変えられる画面（`/material` とクラス別の `/material/[className]`）で、サーヴァント素材のデータを読み込んだ直後と、サーヴァントの状態（所持・現在値・目標）がユーザーの操作またはクラウド復元などの読み込みで変わったときに、素材計算の実行を待たずに育成ぶんの必要数を書き直さなければならない (SHALL)。自動更新は値が変わったときだけ書き、素材データの読み込み前は書いてはならない (SHALL NOT)。また自動更新の書き込みだけで、クラウド同期の未保存の変更を作ってはならない (SHALL NOT)。

#### Scenario: 育成記録モードで現在のスキルLvを上げる
- **GIVEN** 素材計算を一度実行してある
- **WHEN** ユーザーが `/material` でサーヴァントの現在のスキルLvを1つ上げたとき
- **THEN** 育成ぶんの必要数は上げたスキルLvぶん減った値に書き直される
- **THEN** 素材計算を実行し直さずに `/material/result` を開いても、減った値が表示される

#### Scenario: 新しい端末で育成の画面を開く
- **GIVEN** クラウド復元をまだしていない新しい端末
- **WHEN** ユーザーが `/material` を開き、素材データの読み込み後に育成ぶんが書かれたとき
- **THEN** クラウド同期の未保存の変更は作られず、最初のクラウド復元は競合にならずに行われる

#### Scenario: 空の状態で開いたあと移行前のデータを復元する
- **GIVEN** 新しい端末で、サーヴァントの目標が無いまま `/material` を開き、育成ぶんの保存先が空の値で作られた
- **WHEN** そのあと、育成ぶんを持たない移行前のクラウドデータ（サーヴァントの状態と旧 `material/result`）を復元したとき
- **THEN** 育成ぶんの必要数は、復元したサーヴァントの状態から求め直した値に書き直される
- **THEN** 必要数は求め直した育成ぶんとクラススコアぶんの合算で表示され、旧 `material/result` は使われない

#### Scenario: クラス別ページで目標を変える
- **WHEN** ユーザーが `/material/[className]` でサーヴァントの目標を変えたとき
- **THEN** 育成ぶんの必要数は変えた目標に合わせて書き直される

#### Scenario: 素材マスタを読み込む前は書き直さない
- **GIVEN** サーヴァント素材のデータをまだ読み込んでいない
- **WHEN** サーヴァントの状態が保存から読み込まれたとき
- **THEN** 育成ぶんの必要数は書き換えられず、前に保存した値が残る

### Requirement: 育成ぶんの保存先への移行
システムは、育成ぶんの保存先がまだ無い端末では、旧 `material/result` を育成ぶんとクラススコアぶんに分けようとせず、サーヴァントの状態から育成ぶんを求めて育成ぶんの保存先に保存しなければならない (SHALL)。移行は `/material` だけでなく、必要数を読む画面（素材結果、周回ソルバー連携、クエスト効率、ダッシュボード、進捗レポート）を開いたときにも行わなければならない (SHALL)。サーヴァントの目標が無ければ、育成ぶんは必要な素材が無い値で確定して保存する。旧 `material/result` を読むのは、移行のための素材データの取得中と取得に失敗したときだけとし、そのときは合算済みの必要数として読み、クラススコアぶんを足してはならない (SHALL NOT)。育成ぶんの保存先があるかはキーがあるかで決め、値が空でもあるものとして扱う。育成ぶんの保存先ができたあとは、旧 `material/result` を必要数の計算に使ってはならない (SHALL NOT)。移行の書き込みだけで、クラウド同期の未保存の変更を作ってはならない (SHALL NOT)。`/material/result` を URL のクエリ付きで開いたときは、サーヴァントの状態から求めた育成ぶんが空ならクエリの値を育成ぶんとして表示に使い、空でなければ求めた育成ぶんを使わなければならない (SHALL)。素材データの取得中と取得失敗の間はクエリの値を使う。クエリの値は保存してはならない (SHALL NOT)。育成ぶんの保存先があっても、そのあとサーヴァントの状態が変わって求め直しが終わっていない間は、保存値を今の育成ぶんとみなしてはならず (SHALL NOT)、旧 `material/result` があればそれを合算済みとして読み、無ければ保存値を使う。求め直しの取得に失敗したときは、必要数が古い可能性を表示しなければならない (SHALL)。

#### Scenario: 移行前の端末で素材結果を開く
- **GIVEN** 端末に旧 `material/result` だけがあり、サーヴァントの育成目標とクラススコアの目標が設定されている
- **WHEN** ユーザーが `/material` を開かずに `/material/result` を開いたとき
- **THEN** 素材データの取得が終わると、サーヴァントの状態から求めた育成ぶんが育成ぶんの保存先に保存される
- **THEN** 必要数は求めた育成ぶんとクラススコアぶんの合算で表示され、クラススコアぶんが二重に足されない

#### Scenario: 読む画面で先に移行してから自動復元が来る
- **GIVEN** 新しい端末で、サーヴァントの目標が無いままダッシュボードを開き、育成ぶんの保存先が空の値で作られた
- **WHEN** そのあと、移行前のクラウドデータ（サーヴァントの状態と旧 `material/result`）が自動で復元されたとき
- **THEN** `/material` を開かなくても、育成ぶんの必要数は復元したサーヴァントの状態から求め直した値に書き直される

#### Scenario: サーヴァントの状態を読み込む前は判定しない
- **GIVEN** 端末に旧 `material/result` とサーヴァントの育成目標がある
- **WHEN** 必要数を読む画面が、サーヴァントの状態の保存値をまだ読み込んでいないとき
- **THEN** 育成ぶんの保存先は作られず、目標なしとして空の値で確定されない

#### Scenario: 移行の途中と取得の失敗
- **GIVEN** 端末に旧 `material/result` だけがある
- **WHEN** 必要数を読む画面が素材データを取得している間、または取得に失敗したとき
- **THEN** 必要数は旧 `material/result` の値のまま表示され、クラススコアぶんは足されない
- **THEN** 取得に失敗したときは育成ぶんの保存先は作られず、次に開いたときに移行をやり直す

#### Scenario: サーヴァントの目標が無く旧値だけを持つ端末
- **GIVEN** 旧 `material/result` があり、育成ぶんの保存先が無く、サーヴァントの目標が無い
- **WHEN** ユーザーが必要数を読む画面か `/material` を開いたとき
- **THEN** 育成ぶんの保存先は必要な素材が無い値で作られ、必要数はクラススコアぶんだけになる
- **THEN** サーヴァントの状態を変えたり素材計算を実行し直したりしなくても、旧 `material/result` は使われなくなる

#### Scenario: 移行後は旧値を使わない
- **GIVEN** 育成ぶんの保存先がある
- **WHEN** 必要数を読むとき
- **THEN** 旧 `material/result` に値が残っていても、必要数は育成ぶんとクラススコアぶんの合算で求められる

#### Scenario: クエリ付きで素材結果を開く
- **GIVEN** URL のクエリに必要数が付いている
- **WHEN** ユーザーが `/material/result` をそのクエリ付きで開いたとき
- **THEN** サーヴァントの状態から求めた育成ぶんが空なら、クエリの値が育成ぶんとして表示に使われ、クラススコアぶんと合算される
- **THEN** 求めた育成ぶんが空でなければ、クエリの値ではなく求めた育成ぶんが使われる
- **THEN** 素材データの取得中と取得失敗の間は、クエリの値が使われる
- **THEN** どの場合もクエリの値は育成ぶんの保存先に保存されない

#### Scenario: 空の値を作ったあとの復元で求め直しに失敗する
- **GIVEN** 新しい端末で、目標が無いまま育成ぶんの保存先が空の値で作られ、そのあと移行前のクラウドデータ（目標のあるサーヴァントの状態と旧 `material/result`）が復元された
- **WHEN** 求め直しのための素材データの取得に失敗したとき
- **THEN** 必要数は空の育成ぶんではなく旧 `material/result` の値で表示され、必要数が古い可能性が表示される

#### Scenario: 育成目標をすべて消した端末
- **GIVEN** 育成ぶんの保存先が空（必要な素材なし）で、旧 `material/result` に値が残っている
- **WHEN** 必要数を読むとき
- **THEN** 旧 `material/result` は使われず、必要数はクラススコアぶんだけになる
