## MODIFIED Requirements

### Requirement: クラススコア目標素材の合算反映
システムは、育成の必要数を「サーヴァント育成ぶん」と「クラススコアぶん」に分けて扱わなければならない (SHALL)。育成ぶんは育成素材計算機が `material/result` とは別の保存先に書き、クラススコアぶんは保存せずクラススコアの状態から求める。画面に出す必要数は両者をアイテムIDごとに足した値とし、素材結果画面・周回ソルバー連携・クエスト効率・ダッシュボード・進捗レポートは、同じ1つの合算の手順を通して必要数を読まなければならない (SHALL)。

#### Scenario: クラススコア目標を含む必要素材の計算
- **GIVEN** サーヴァント育成目標とクラススコア目標（例: セイバー目標）が設定されている
- **WHEN** ユーザーが素材計算を実行したとき
- **THEN** 育成ぶんの保存先にはサーヴァント育成に必要な素材だけが保存され、クラススコアぶんは含まれない
- **THEN** 素材結果画面と周回ソルバー（`/farming`）への連携パラメータには、育成ぶんとクラススコアぶんをアイテムIDごとに合算した必要数が反映される

#### Scenario: クラススコアを変えた直後の素材結果
- **GIVEN** 素材計算を一度実行したあと、クラススコア画面で目標のマスを増やした
- **WHEN** ユーザーがクラススコア画面のリンクから `/material/result` を開いたとき
- **THEN** 各素材の必要数は、増やした目標マスぶんを含む値で表示され、内訳のクラススコアぶんが全体の必要数を上回らない
- **THEN** `/material` で素材計算を実行し直す必要はない

#### Scenario: 読む画面のあいだで必要数が一致する
- **GIVEN** 育成ぶんとクラススコアぶんの両方に必要数がある
- **WHEN** ユーザーが素材結果画面、クエスト効率、ダッシュボードの不足数、進捗レポートを順に見たとき
- **THEN** 同じアイテムの必要数はどの画面でも同じ値になる

### Requirement: マス単位クラススコア目標の素材計算結果への動的合算
システムは、クラスボード盤面上でマス単位に設定された目標のうち未解放のマスに必要な素材を、クラススコアぶんとして必要数の合算に含めなければならない (SHALL)。盤面の変更は、素材計算を実行し直さなくても、次に必要数を読んだ時点で反映されなければならない (SHALL)。

#### Scenario: マス単位目標の素材計算への合算
- **GIVEN** クラスボード詳細画面で特定のマス群が「目標」に設定されている
- **WHEN** ユーザーが素材結果画面（`/material/result`）、クエスト効率、ダッシュボードのいずれかを表示したとき
- **THEN** 目標マス（未解放分）に必要な通常素材、ピース・モニュメント、QP、星光の砂、トーチが、育成ぶんと合算された値で表示される
- **THEN** 周回ソルバー（`/farming`）の必要素材パラメータにも合算された数が反映される

## ADDED Requirements

### Requirement: 育成ぶんの必要数の自動更新
システムは、サーヴァントの状態を変えられる画面（`/material` とクラス別の `/material/[className]`）で、サーヴァント素材のデータを読み込んだ直後と、サーヴァントの状態（所持・現在値・目標）が変わったときに、素材計算の実行を待たずに育成ぶんの必要数を書き直さなければならない (SHALL)。自動更新は値が変わったときだけ書き、育成ぶんの保存先がまだ無いときは、必要な素材が無い結果で保存先を作ってはならない (SHALL NOT)。また自動更新はユーザーの編集ではない導出値の書き込みとして通知しなければならず、それだけでクラウド同期の未保存の変更を作ってはならない (SHALL NOT)。

#### Scenario: 育成記録モードで現在のスキルLvを上げる
- **GIVEN** 素材計算を一度実行してある
- **WHEN** ユーザーが `/material` でサーヴァントの現在のスキルLvを1つ上げたとき
- **THEN** 育成ぶんの必要数は上げたスキルLvぶん減った値に書き直される
- **THEN** 素材計算を実行し直さずに `/material/result` を開いても、減った値が表示される

#### Scenario: 新しい端末で育成の画面を開く
- **GIVEN** クラウド復元をまだしていない新しい端末
- **WHEN** ユーザーが `/material` を開き、素材データの読み込み後に育成ぶんが書かれたとき
- **THEN** クラウド同期の未保存の変更は作られず、最初のクラウド復元は競合にならずに行われる

#### Scenario: 空の状態で開いたあと移行前のデータを復元する
- **GIVEN** 新しい端末で、サーヴァントの目標が無いまま `/material` を開いた
- **WHEN** そのあと、育成ぶんを持たない移行前のクラウドデータ（旧 `material/result` あり）を復元したとき
- **THEN** 育成ぶんの保存先は作られておらず、必要数は復元した旧 `material/result` の値で表示される

#### Scenario: クラス別ページで目標を変える
- **WHEN** ユーザーが `/material/[className]` でサーヴァントの目標を変えたとき
- **THEN** 育成ぶんの必要数は変えた目標に合わせて書き直される

#### Scenario: 素材マスタを読み込む前は書き直さない
- **GIVEN** サーヴァント素材のデータをまだ読み込んでいない
- **WHEN** サーヴァントの状態が保存から読み込まれたとき
- **THEN** 育成ぶんの必要数は書き換えられず、前に保存した値が残る

### Requirement: 旧形式の必要数の読み替え
システムは、育成ぶんの保存先がまだ無い端末とスナップショットでは、旧 `material/result` の値を合算済みの必要数として読み、クラススコアぶんを足してはならない (SHALL NOT)。育成ぶんの保存先があるかはキーがあるかで決め、値が空でもあるものとして扱う。育成ぶんの保存先を書くのは、素材計算と育成ぶんの自動更新だけでなければならず、必要数を読む画面は開いただけで保存先を作ってはならない (SHALL NOT)。育成ぶんの保存先ができたあとは、旧 `material/result` を必要数の計算に使ってはならない (SHALL NOT)。

#### Scenario: 移行前の端末で素材結果を開く
- **GIVEN** 端末に旧 `material/result` だけがあり、クラススコアの目標が設定されている
- **WHEN** ユーザーが `/material/result` を開いたとき
- **THEN** 必要数は旧 `material/result` の値のまま表示され、クラススコアぶんが二重に足されない
- **THEN** 素材結果画面やクエスト効率を開いただけでは育成ぶんの保存先は作られず、次に開いたときも旧値のまま表示される

#### Scenario: サーヴァントの目標が無く旧値だけを持つ端末（既知の制限）
- **GIVEN** 旧 `material/result` があり、育成ぶんの保存先が無く、サーヴァントの目標が無い
- **WHEN** ユーザーが `/material` を開いたりサーヴァントの状態を変えたりしたとき
- **THEN** 育成ぶんの保存先は作られず、必要数は素材計算を実行し直すまで旧 `material/result` の値のまま表示される

#### Scenario: 移行後は旧値を使わない
- **GIVEN** 育成ぶんの保存先がある
- **WHEN** 必要数を読むとき
- **THEN** 旧 `material/result` に値が残っていても、必要数は育成ぶんとクラススコアぶんの合算で求められる

#### Scenario: 育成目標をすべて消した端末
- **GIVEN** 育成ぶんの保存先が空（必要な素材なし）で、旧 `material/result` に値が残っている
- **WHEN** 必要数を読むとき
- **THEN** 旧 `material/result` は使われず、必要数はクラススコアぶんだけになる
