# Spec Delta

## Purpose

イベントの交換所に、サーヴァント扱いの交換（種火・フォウくん・礼装など）を取り込んで並べ、交換回数と周回の計算に入れ、育成計画で扱わない品として必要／不要を選べるようにする。

## ADDED Requirements

### Requirement: サーヴァント扱いの交換の取り込み
システムは、イベントの交換所を取り込むとき、Atlas Academy がサーヴァント扱い（`purchaseType` が `servant`）として返す交換のうち、対価がイベントアイテムのものも、アイテムの交換と同じく交換所のデータに保存しなければならない (SHALL)。保存する内容は、アイテムの交換と同じ「獲得物」「1回の個数」「コスト（通貨・個数）」「在庫上限」に加え、獲得物がサーヴァント扱いであること、獲得物の名前・レア度・アイコンとする。獲得物の名前・レア度・アイコンを取得できなかった交換は、名前に交換所の見出しを使って保存し、そのイベントの取り込みを止めてはならない (SHALL NOT)。同じ獲得物が対価の通貨ごと・在庫上限ごとに別の交換として並ぶときは、交換ごとに別の品目として保存しなければならない (SHALL)。コマンドコード・霊衣開放権の交換は取り込まない。アイテムの交換があるロトの無い交換所のイベントでは、イベントの通貨をアイテムの交換から決め、サーヴァント扱いの交換を取り込むことで既存のイベントの通貨を変えてはならない (SHALL NOT)。アイテムの交換が無くサーヴァント扱いの交換だけがある交換所のイベントも、交換所のイベントとして取り込まなければならない (SHALL)。獲得物がサーヴァント扱いであることを持たない既存のデータは、アイテムの交換として読まなければならない (SHALL)。

#### Scenario: 種火・フォウくん・礼装の交換
- **WHEN** 取り込むイベントの交換所に、イベントアイテムを対価にする種火・フォウくん・礼装の交換があるとき
- **THEN** それぞれが獲得物・1回の個数・コスト・在庫上限・サーヴァント扱いであること・名前・レア度・アイコンとともに交換所のデータに保存される

#### Scenario: 同じ礼装が通貨ごとに並ぶ
- **WHEN** 同じ礼装の交換が、通貨 A で在庫上限 2、通貨 B で在庫上限 1、通貨 C で在庫上限 1 の3つあるとき
- **THEN** 3つの品目として、それぞれの通貨と在庫上限で保存される

#### Scenario: コマンドコードは取り込まない
- **WHEN** 交換所にコマンドコードの交換があるとき
- **THEN** その交換は交換所のデータに入らない

#### Scenario: サーヴァント扱いの交換が先に並ぶ
- **WHEN** ロトの無い交換所のイベントで、Atlas の並びの最初が礼装の交換で、その後に通貨 B を対価にするアイテムの交換が並ぶとき
- **THEN** イベントの通貨は通貨 B になる

#### Scenario: 獲得物の情報を取得できない
- **WHEN** サーヴァント扱いの交換の獲得物の名前・レア度・アイコンを取得できなかったとき
- **THEN** その品目は交換所の見出しを名前にして保存され、同じイベントのほかの品目と、ほかのイベントの取り込みは続く

#### Scenario: 種類を持たない既存のデータ
- **WHEN** 品目がサーヴァント扱いであることを持たない、この変更より前に取り込んだイベントの交換所を表示するとき
- **THEN** すべての品目はこれまでどおりアイテムの品目として表示・計算される

### Requirement: サーヴァント扱いの品目の表示と計算
システムは、交換所の一覧で、サーヴァント扱いの品目をアイテムの品目と同じ通貨ごとのカードに、名前とアイコンとともに並べなければならない (SHALL)。サーヴァント扱いの品目は、交換回数の入力・全部交換・通貨ごとの必要量・周回の内訳・合計・AP 予算の計算に、アイテムの品目と同じ規則で入れなければならない (SHALL)。サーヴァント扱いの品目はフリクエのドロップ表に現れない品として扱い、効率と順位を表示してはならない (SHALL NOT)。サーヴァント扱いの品目の獲得物の番号を、アイテムの番号として所持数・育成計画の必要数・ドロップ表と突き合わせてはならない (SHALL NOT)。

#### Scenario: 全部交換に入る
- **WHEN** 通貨 A のカードに、在庫上限 40 の英霊結晶と在庫上限 10 のアイテムの品目があり、利用者が全部交換を押したとき
- **THEN** 英霊結晶の交換回数は 40、アイテムの品目の交換回数は 10 になり、通貨 A の必要量には両方の対価の合計が入る

#### Scenario: 効率を出さない
- **WHEN** 通貨のカードに礼装と、AP 換算値のあるアイテムの品目があるとき
- **THEN** 礼装は順位と効率なしで前に並び、アイテムの品目は効率順に並ぶ

### Requirement: サーヴァント扱いの品目の必要／不要
システムは、サーヴァント扱いの品目を、育成計画で扱わない品目として「計画の対象外」と表示し、アイテムの計画の対象外の品目と同じく「必要」と「不要」を選べるようにしなければならない (SHALL)。初期値・端末への保存・別のイベントでも同じ選択を使うこと・不足素材のみの操作での回数の入れ方・育成計画が未設定や読み込み中・失敗のときに表示しないことは、アイテムの計画の対象外の品目と同じとする。サーヴァント扱いの品目は、育成計画で扱う素材の一覧を読み込めないときも、計画の対象外と判定できる。選択は獲得物ごとに保存し、獲得物の番号が同じアイテムの品目の選択と取り違えてはならない (SHALL NOT)。サーヴァント扱いの品目は、交換所で埋まらない不足の要約に数えない。

#### Scenario: 種火を必要にする
- **WHEN** 利用者が在庫上限 100 の種火を「必要」に、在庫上限 2 の礼装を「不要」にして、不足素材のみの操作をしたとき
- **THEN** 種火の交換回数は 100、礼装の交換回数は 0 になる

#### Scenario: 別のイベントでも同じ選択を使う
- **WHEN** 利用者があるイベントの交換所で星のフォウくんを「必要」にし、星のフォウくんを並べる別のイベントの交換所を開いたとき
- **THEN** 別のイベントでも星のフォウくんは「必要」になっている

#### Scenario: 番号が同じアイテムの品目とは別に保存する
- **WHEN** サーヴァント扱いの品目と、獲得物の番号が同じアイテムの品目があり、利用者がサーヴァント扱いの品目だけを「必要」にしたとき
- **THEN** アイテムの品目の選択は変わらない
