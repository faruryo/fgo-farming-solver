# Design

## Context

この change は、#135・#164 の実装 PR #165 がマージされた後の main に乗る。#165 の後の交換所の周回計算（`components/events/EventShopList.tsx`）は、次の要素を持つ。

- 通貨ごとのカード: 品目ごとの交換回数の入力、通貨ごとの「在庫上限まですべて交換する数を入れる」（`selectAllUpToLimit`）、所持数、必要量
- 周回の内訳: `planShopCurrencies` の結果
- 上部の周回の合計の1行

箱のあるイベントの箱計画（`components/events/EventPlannerClient.tsx`）は、AP 予算を出している。

- 計算: `lib/ap-budget.ts` の `computeApBudget(needAp, maxAp, goldenFruitOwned)`。回復の回数を切り上げ、黄金の果実 → 聖晶石 → 課金額の順に割り当てる
- 最大 AP: `hooks/use-master-level.ts` の `useMasterLevel()` で、マスターレベルから求める
- 黄金の果実の所持数: `useLocalStorage(STORAGE_KEYS.EVENTS_GOLDEN_FRUIT, 0)` に保存する
- 入力欄: `EventPlannerClient` の「AP予算」の入力欄（マスターレベル、所持黄金の果実）
- 内訳の表示: `EventPlanResultCard` の「AP予算内訳」

## Goals / Non-Goals

**Goals:**
- 全通貨をまとめて在庫上限まで選ぶ操作と、交換所の周回の合計 AP に対する AP 予算を出す
- 箱計画と同じ規則・同じ保存先の値を使い、2つの画面で値と結果がずれないようにする

**Non-Goals:**
- イベントのボーナス礼装・サーヴァントによるドロップの増加（#130）。#162 と同じく、素の統計値で計算し、注記を残す
- 会期の残りと1日の AP から、会期内にどこまで届くか（#136）
- 自然回復の AP を差し引くこと。箱計画も差し引いていない
- 銀・銅の果実と聖晶石の個別の換算。箱計画と同じく、黄金の果実と聖晶石だけを数える
- 交換回数の保存（epic #129 の「やらないこと」E2）

## Decisions

### 1. 全部交換は既存の通貨ごとの選択を全通貨に当てる

`lib/event-shop-summary.ts` に、交換所の全通貨について `selectAllUpToLimit` を順に当てた交換回数を返す純粋関数を置く。在庫上限の無い品目には触れない（`selectAllUpToLimit` の既存の規則）。ボタンは交換所のセクションの上部、#165 の周回の合計の1行の近くに置く。文言は、押した結果が分かるもの（例:「すべての通貨で、在庫上限まですべて交換する数を入れる」）にする。

採らなかった案: 交換回数とは別に「全部交換した場合」の計算結果を出す。今の選択と別の結果が並ぶと、どちらが今の計画か分かりにくい。また #162 の「交換回数で計画を表す」形を崩す。

### 2. AP 予算は箱計画の部品を切り出して共用する

`EventPlannerClient` の「AP予算」の入力欄（マスターレベル、所持黄金の果実）と、`EventPlanResultCard` の「AP予算内訳」の表示を、`components/events/` の小さな部品に切り出す。箱計画と交換所の周回計算の両方から使う。計算は `computeApBudget` をそのまま呼び、値は `useMasterLevel` と同じ黄金の果実の保存先から読む。箱計画の表示と振る舞いは変えない（既存のテストが通ったままであること）。

交換所では、周回の内訳の `result.total_ap` が出ているとき（`planShopCurrencies` の `status` が `planned` で `result` があるとき）だけ AP 予算を出す。周回では集められない通貨があるときも、集められる通貨の分の AP で出す。#165 の上部の1行の注記と同じく、その AP は一部の通貨の分であることを、AP 予算の近くにも短く書く。

採らなかった案: 交換所に入力欄と内訳を書き写す。規則や見た目が2か所でずれる。

### 3. 画面

- 全部交換のボタン: 交換所のセクションの上部
- AP 予算の入力欄（マスターレベル、所持黄金の果実）と内訳（回復の回数、黄金の果実の消費、聖晶石、課金額）: 周回の内訳の下
- #165 の上部の周回の合計の1行に、AP 予算の要点（例:「黄金の果実 3・聖晶石 4」）を足すかは決めない。足すと1行が長くなり、375px で折り返すため。まず周回の内訳の下にだけ出す
- 375px で横スクロールを出さない。内訳は箱計画と同じ並びで、狭い幅では折り返す

## Risks / Trade-offs

- [ボーナスを含まないので、実際より多い周回・AP・回復の回数になる] → #162 と同じ注記を残す。#130 でボーナスが入れば直る
- [#165 がマージされる前に実装に入ると、乗る画面が無い] → 実装（ops-graph）は #165 のマージ後に main から始める
- [箱計画の部品を切り出すと、箱計画の見た目が変わるおそれがある] → 箱計画の既存のテストを保ち、tasks の画面の確認で箱のあるイベントも開く
