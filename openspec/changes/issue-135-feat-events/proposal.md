# Proposal

## Why

#128（実装 PR #162）で、ロトの無い交換所イベントでは品目ごとに交換する回数を選べるようになった。ただ、品目は元の順に並ぶだけで、どの品目から交換すると得か、どこで止めればよいかは分からない（issue #135、epic #129 の B1）。全部を交換しきるのは大変なので、どこで止めるかを判断できるようにしたい。#131 の調査で、素材の AP 換算値は既存の計算でドロップ表から出せることが分かり、2026-10-24 にオーナーが並べ方の方針を決めた。

## What Changes

- ロトの無い交換所イベントの交換所で、通貨ごとのカードの中の品目を「未選択」「欲しい」「効率順」「要らない」の段に分けて並べる
- AP 換算値のある品目（フリクエで落ちる素材）は、通貨1個あたりの価値（1回の交換で得る個数 × 素材の AP 換算値 ÷ 1回の対価）を「効率」として出し、効率の高い順に順位を付けて並べる
- 効率順の段に「ここまで交換すれば効率が良い」区切りを出す。区切りは、その通貨1個をイベントの周回で集めるのに要る AP（通貨ごとに AP を分けない）を効率が下回る位置に置く
- AP 換算値の無い品目（伝承結晶・サーヴァントコイン・礼装・QP など）は、利用者が品目ごとに「欲しい」か「要らない」を選ぶ。最初はどれも未選択の段に並ぶ
- イベント名が「復刻:」（全角のコロンと「復刻版:」を含む）で始まるイベントは、ページの見出しに「復刻」を示す
- 品目ごとの交換回数の入力・所持数・周回の内訳など #128 の表示と動きは変えない。欲しい／要らないの選択は並べ方だけを変え、交換回数は変えない

## Capabilities

### New Capabilities
- `event-shop-efficiency`: ロトの無い交換所イベントの交換所の品目を、素材の AP 換算値による効率と利用者の欲しい／要らないの選択で並べ、ここまで交換すれば効率が良い区切りを示す

### Modified Capabilities
（なし）

## Impact

- 前提: #128 の実装 PR #162 がマージ済みであること。画面は #162 の `components/events/EventShopList.tsx` と `EventHubClient.tsx` の上に乗る
- `app/events/[id]/page.tsx`（ロトの無い交換所イベントのときだけドロップ表を読み、交換所の品目の AP 換算値を渡す）
- 新しい純粋関数（品目の効率・段分け・区切り）と、そのユニットテスト
- `components/events/EventShopList.tsx`（並べ方・効率・区切り・欲しい／要らないの切り替え）、`EventHubClient.tsx`（復刻の表示）
- `locales` の events の文言
