## MODIFIED Requirements

### Requirement: 所持数と目標による個人最適化(2段階重み)

システムは各素材の重みを、グローバルな周回目的、所持数(`owned`)、育成必要数(`required`)、カテゴリ・レアリティ別の在庫基準 `buffer(item)` から決定しなければならない (SHALL)。低在庫倍率を `lowStockWeight = buffer > 0 ? 1 + buffer / (owned + buffer) : 1` と定義し、有限かつ `1以上2以下` にしなければならない (SHALL)。

「今の育成を進める」では `owned < required` の素材だけを対象とし、重みを `lowStockWeight` とする。「新規サーヴァントに備える」では `owned < max(required, buffer)` の素材を対象とし、同じ重みを使う。「素材全体の効率を見る」では所持数・必要数・在庫基準にかかわらず全対象素材の重みを1とする。スキル石・モニュピの包含設定は各モードの対象判定より先に適用する。

#### Scenario: 育成不足の中で低在庫を優先する

- **WHEN** 「今の育成を進める」で、同じ相対効率を持つ2素材がともに育成不足であり、一方の `owned / buffer` が小さい
- **THEN** 在庫比率の小さい素材の重みが大きくなる

#### Scenario: 必要総数を倍率に使わない

- **WHEN** 必要数1000・所持数200の素材と、必要数100・所持数30の同レアリティ素材を比較する
- **THEN** 必要数ではなく所持数と共通バッファーで倍率が決まり、所持数30の素材が高く評価される

#### Scenario: レアリティごとの在庫水準を比較する

- **WHEN** 金・銀・銅素材の所持数が同じで、各素材のバッファーが異なる
- **THEN** 各バッファーに対する在庫の薄さが倍率へ反映される

#### Scenario: 新規サーヴァントへの備えに目標未設定素材を含める

- **WHEN** 「新規サーヴァントに備える」で、育成必要数0かつ所持数がバッファー未満の素材がある
- **THEN** その素材は低在庫倍率で効率ポイントへ寄与する

#### Scenario: 未入力の所持数を0個とみなさない

- **WHEN** 「新規サーヴァントに備える」で、素材の所持数が未入力である
- **THEN** その素材を対象から外し、所持数入力を促す

#### Scenario: 素材全体では一律評価する

- **WHEN** 「素材全体の効率を見る」が選択されている
- **THEN** 対象素材は所持数・必要数・バッファーにかかわらず重み1で寄与する

#### Scenario: バッファー0を安全に扱う

- **WHEN** レアリティ不明などにより素材のバッファーが0である
- **THEN** 0除算を行わず、対象となる場合の重みを1とする

#### Scenario: 育成不足は主優先

- **WHEN** `training` で育成不足の素材がある
- **THEN** その素材を低在庫倍率で評価する

#### Scenario: ストックOFFは余剰を次点で拾う

- **WHEN** 旧ストックOFF設定を移行する
- **THEN** `training` を選び、育成目標を満たした素材は対象外にする

#### Scenario: ストックONは余剰を目標に昇格

- **WHEN** 旧ストックON設定を移行する
- **THEN** `reserve` を選び、`max(required, buffer)` 未満の素材を対象にする

#### Scenario: ストック込み目標に到達したら除外

- **WHEN** `reserve` で `owned >= max(required, buffer)` である
- **THEN** その素材の重みを0にする

#### Scenario: カテゴリ群でストック個数が異なる

- **WHEN** 素材カテゴリごとに異なるバッファーが設定されている
- **THEN** 該当カテゴリのバッファーで対象判定と低在庫倍率を計算する

#### Scenario: 育成目標ゼロ素材もONなら一定数狙う

- **WHEN** `reserve` で育成必要数0かつ入力済み所持数がバッファー未満である
- **THEN** その素材を低在庫倍率で評価する

#### Scenario: 全部モード

- **WHEN** `all` を選ぶ
- **THEN** 全対象素材を重み1で評価する

### Requirement: クエスト一覧/検索ページ

システムは `/quests` にクエスト一覧/検索ページを提供し、各クエストのエリア・名前・AP・効率ポイントを表示しなければならない (SHALL)。名前・エリア検索、効率ポイント順、AP効率・周回効率、石含む・石除くの各操作と、ストームポッド関連のバッジを維持しなければならない (SHALL)。現在のグローバルな周回目的を効率ポイントへ反映して表示し、画面内のモード表示から共通のモード選択UIを開けなければならない (SHALL)。従来の「不足のみ／全部」と「ストック込み」操作は表示してはならない (SHALL NOT)。

#### Scenario: 一覧でモードを変更する

- **WHEN** クエスト一覧から周回目的を変更する
- **THEN** ページ遷移なしで効率ポイントとランキングが再計算される

#### Scenario: 効率ポイント順の表示

- **WHEN** ユーザーが一覧ページを開く
- **THEN** クエストを効率ポイント降順で表示する

#### Scenario: 検索

- **WHEN** ユーザーがエリア名またはクエスト名で検索する
- **THEN** 一致するクエストだけを表示する

#### Scenario: トグルでスコア再計算

- **WHEN** ユーザーがスキル石の包含を切り替える
- **THEN** 効率ポイントとランキングを即時に再計算する

#### Scenario: 分母切替でスコア再計算

- **WHEN** ユーザーがAP効率または周回効率を選ぶ
- **THEN** 見出し、文字色、効率ポイント、ランキングを即時に更新する

#### Scenario: ストック込みトグルでスコア再計算

- **WHEN** 旧ストック込みトグルに相当する備蓄目的を選ぶ
- **THEN** `reserve` を保存し、効率ポイントとランキングを即時に再計算する

#### Scenario: ストームポッド無料判定

- **WHEN** ポッド無料期間中の対象クエストがある
- **THEN** そのクエストへ「ポッド無料中」バッジを表示する

#### Scenario: 効率ポイントの右寄せと狭幅でのクエスト名確保

- **WHEN** 狭い画面幅で一覧を表示する
- **THEN** クエスト名の幅を確保し、効率ポイントを右寄せする

#### Scenario: 効率ポイントの説明導線

- **WHEN** ユーザーが説明アイコンを操作する
- **THEN** 共通の説明文を表示する

#### Scenario: 既存の絞り込みと分母を維持する

- **WHEN** ユーザーが検索、分母、またはスキル石の包含を変更する
- **THEN** 一覧と効率ポイントが従来どおり即時更新される

#### Scenario: 詳細への遷移

- **WHEN** ユーザーが一覧の行を選択する
- **THEN** そのクエストの `/quests/[id]` 詳細へ遷移する

### Requirement: クエスト詳細の効率ポイント表示

システムは `/quests/[id]` に、当該クエストの効率ポイントと素材別 contribution の内訳を表示しなければならない (SHALL)。AP効率・周回効率の切り替え、共通の説明文、内訳の列見出しを維持しなければならない (SHALL)。現在のグローバルな周回目的を合計点と内訳へ反映して表示し、画面内のモード表示から共通のモード選択UIを開けなければならない (SHALL)。従来の「ストック込み」操作は表示してはならない (SHALL NOT)。

#### Scenario: 詳細でモードを変更する

- **WHEN** クエスト詳細から周回目的を変更する
- **THEN** ページ遷移なしで合計点と素材別内訳が再計算される

#### Scenario: 内訳を表示する

- **WHEN** ユーザーがクエスト詳細を開く
- **THEN** 合計点と、寄与した素材ごとの素材名・重み・寄与度が表示される

#### Scenario: 内訳表示

- **WHEN** ユーザーがクエスト詳細を開く
- **THEN** 効率ポイントと素材別内訳を表示する

#### Scenario: 詳細ページの説明ツールチップ

- **WHEN** ユーザーが説明アイコンを操作する
- **THEN** 一覧と同じ説明文を表示する

#### Scenario: 詳細ページのストック込みトグル

- **WHEN** 旧ストック込みトグルに相当する備蓄目的を選ぶ
- **THEN** `reserve` を保存し、合計点と内訳を即時に再計算する

#### Scenario: 詳細ページの分母トグル

- **WHEN** ユーザーがAP効率または周回効率を選ぶ
- **THEN** 見出し、文字色、合計点、内訳を即時に更新する

#### Scenario: スコアが0でもカードとトグルを表示

- **WHEN** 現在モードの効率ポイントが0である
- **THEN** 0点のカード、対象素材がない旨、分母とモードの変更操作を表示する

#### Scenario: 内訳の列見出し

- **WHEN** ユーザーが素材別内訳を見る
- **THEN** 素材名、重み、寄与度の列見出しを表示する

#### Scenario: スコア0でも変更できる

- **WHEN** 現在モードで対象素材がなく効率ポイントが0である
- **THEN** 現在モードと変更操作は表示されたままとなる

## REMOVED Requirements

### Requirement: 余剰ストックを目標に含めるグローバル設定(stockEnabled)

**Reason**: ユーザーの目的を表さない真偽値であり、`required + buffer` が長期育成目標を過剰に膨らませるため。

**Migration**: 新しい周回目的へ移行し、在庫基準は低在庫倍率と `reserve` の対象判定に再利用する。
