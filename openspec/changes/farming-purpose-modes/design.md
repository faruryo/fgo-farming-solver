## Context

動機は [proposal.md](./proposal.md) を参照。現在は `shortageOnly` と `stockEnabled` が別々に保存され、クエスト効率、ソルバー取り込み、配布アドバイザー、進捗表示がそれぞれ参照している。`stockBuffer` と素材カテゴリ・レアリティ判定、localStorageのタブ間同期、クラウド保存、既存の `Sheet` と `Dialog` は再利用できる。

## Goals / Non-Goals

**Goals:**

- 1つの保存値から、対応画面の対象素材・重み・有限目標を一貫して導出する。
- 旧設定を失わず、新しい目的名へ一度だけ移行する。
- 既存UI部品と保存経路だけで、どこからでも変更・説明確認を可能にする。

**Non-Goals:**

- 新しい設定ページ、計算説明ルート、状態管理ライブラリは追加しない。
- 手入力ソルバー、ストックバッファーの編集値、過去の計算履歴は変更しない。
- モードごとのバッファー編集や独自倍率は追加しない。

## Decisions

### 1. 周回目的を単一の列挙値として保存する

`training | reserve | all` を新しいlocalStorageキーへ保存し、既存のタブ間同期とクラウド同期へ追加する。各画面は同じhookを参照する。2つの真偽値を残す案は組み合わせの意味が曖昧なため採用しない。新しいContextや状態管理ライブラリは、既存同期経路で足りるため追加しない。

### 2. 対象判定・重み・有限目標を共有純関数に集約する

低在庫倍率は `buffer > 0 ? 1 + buffer / (owned + buffer) : 1` とする。対象判定は `training: owned < required`、`reserve: owned < max(required, buffer)`、`all: 全対象素材` とし、`all` の重みだけ1に固定する。数量を必要とする画面では `training` と `reserve` の目標をそれぞれ `required` と `max(required, buffer)` から導出する。

必要総数を倍率へ入れる案は、大きな将来目標が現在庫の薄い小さな目標を押しのけるため採用しない。`required + buffer` は育成目標と在庫基準を二重計上するため廃止する。

所持数が未入力の素材は `reserve` で0個とみなさず除外し、既存の入力ナッジを出す。未入力素材が大量に最優先となる誤判定を避けるためである。

### 3. `all` はスコア専用とし、数量画面では `training` を使う

`all` には有限の必要個数がない。ソルバー、配布アドバイザー、進捗表示で全素材の架空目標を作らず、登録済み育成目標による `training` の数量へフォールバックし、その場に注記する。任意の固定個数を与える案はユーザーの意図を推測することになるため採用しない。

### 4. 既存の `Sheet` と `Dialog` に共通UIを置く

ハンバーガーメニューの既存 `Sheet` に3択と「計算方法を見る」を追加する。影響画面には現在モードを示す小さなトリガーを置き、同じ選択UIを開く。説明は既存 `Dialog` で表示し、新しいルートは作らない。説明内容だけを共有コンポーネントにし、画面ごとの別実装は持たない。

### 5. バッファーは在庫基準として残す

既存値と編集UIを維持し、表示上の意味を「目標への上乗せ」から「この個数を下回ると在庫が薄い基準」へ変更する。カテゴリ・レアリティ別の値は低在庫倍率と `reserve` の対象判定で共有する。

### 6. 旧設定は新しい値がない時だけ移行する

移行順は、旧「全部」なら `all`、それ以外で `stockEnabled=true` なら `reserve`、それ以外は `training` とする。新しい値を書いた後は旧値を再評価しない。旧キーは当面読み取り専用で残し、ロールバック時にも利用できるようにする。

## Risks / Trade-offs

- [低在庫倍率により既存スコアの尺度が変わる] → 倍率を1以上2以下に制限し、素材別内訳と説明ダイアログで根拠を示す。
- [`all` と数量画面の表示が一致しないように見える] → 数量画面では `training` を使うことを数値の近くに明示する。
- [未入力と0個を混同するとランキングが偏る] → 未入力は対象外にし、所持数入力を促す。明示的な0個は計算対象にする。
- [タブ間同期とクラウド復元で旧値が再適用される] → 新キーの存在を優先する純粋な移行関数をテストする。
- [Sheet内からDialogを開く際にフォーカスが失われる] → 既存部品のフォーカス管理を使い、キーボード操作と復帰先を検証する。

## Migration Plan

1. 共有型、計算純関数、旧値からの移行関数を追加し、境界ケースをテストする。
2. 新キーをlocalStorage・タブ間同期・クラウド同期へ追加する。
3. 共通選択UIと説明Dialogを追加し、旧トグルを置き換える。
4. クエスト効率、ソルバー取り込み、配布アドバイザー、進捗表示を共有関数へ切り替える。
5. 旧キーは読み取り用に残して段階的に配信する。問題時は新キー参照を止め、旧キーから従来挙動へ戻せる。過去の履歴とスナップショットは書き換えない。
