## Context

`scripts/refresh-event-data.ts` は `nice_event.lotteries.length === 0` のイベントを捨てる。`lib/event-features.ts` の `featuresFor` は、KV にイベントがあれば無条件に `'box'` を返し、`components/events/EventHubClient.tsx` は `'box'` のときだけ箱計画（`EventPlannerClient`）を出す。交換所の表示は箱計画の中にしか無い。`components/events/EventListClient.tsx` の機能バッジは `'box'` 以外をすべて「料理作成」と表示する。

## Goals / Non-Goals

**Goals:**
- ロトが無く交換所があるイベントを KV に入れ、ダッシュボードのリンク・`/events` 一覧・個別ページに出す
- 個別ページで、交換所の中身（通貨ごとの全交換に要る合計と品目）を見せる

**Non-Goals:**
- 交換所からの周回計画（#128）
- ミッション・ポイント報酬の取り込み（#115）
- 箱イベントの画面と計算の変更

## Decisions

### 取り込みは「ロトも交換所も無ければスキップ」

ロトが空で交換所（`compactShop` の結果）が空でなければ、ロトを空配列、`unlimitedBoxes` を `false` として入れる。交換所とクエストのドロップは箱イベントと同じ `compactShop`・`compactFarmingNodes` を通す。`EventPlannerEvent.currency` は必須項目なので、ロトが無いときは交換所の最初のエントリーの対価の通貨を入れる（箱計画では使わない。KV の形は変えない）。

### 交換所のエントリーに通貨の表示名を任意項目で持たせる

ロトの無いイベントは通貨が複数あり（実測で 2〜6 種類）、`currency` 1つでは名前が足りない。画面側の `getItems` は `qp`・`skillLvUp`・`tdLvUp` しか返さないので、イベント通貨の名前を引けない。そこで取り込み時に、`itemMap`（`nice_item.json`）から対価の通貨の名前とアイコンを引いて、`EventShopItem` の任意項目に入れる。既存の `name`・`icon` と同じく任意項目なので、古い KV のデータもそのまま読める。名前が無いときは画面で通貨の ID を出す。

採らなかった案: 画面で通貨の名前を引く `nice_item.json` を別に読み込む。ページごとに大きな JSON を読むことになる。

### 機能の判定は KV の中身で決める

`featuresFor` は、KV のイベントのロトが1件以上なら `'box'`、交換所が1件以上なら `'shop'` を返す（レジストリの機能との和集合、`box` が先）。KV のイベントがあるが箱も交換所も無いときは、今の取り込みでは起きない（どちらも無ければ取り込まない）。`mergeEventList` と個別ページも同じ判定を使う。ダッシュボードのリンク（`EventSection` の `hasEventPage`）は KV の ID の有無で決まっているので、取り込まれれば出る。

### 交換所一覧はロトの無いイベントだけに出す

`'shop'` があって `'box'` が無いとき、個別ページに交換所一覧を出す。箱のあるイベントは、今までどおり箱計画の中で交換所を扱い、一覧を重ねて出さない。一覧は通貨ごとにまとめ、各通貨について全交換に要る合計（`costAmount × limitNum` の和。`limitNum` が 0 のエントリーは無制限として合計に含めず、無制限であることを表示する）と、品目（名前・1回の個数・在庫上限・1回の対価）を並べる。

### 実測（propose の段階、2026-10-18）

`BACKFILL_SINCE` を1年前にして、今の取り込みスクリプトと、スキップ条件だけを緩めた写しを、KV に書かずにファイル出力だけで走らせた。

- 取り込み窓の `eventQuest` は 79件。今のスクリプトが取り込むロトのあるイベントは1件（`80586`、48,605 bytes）
- 写しは、ロトが無く交換所のあるイベント 11件を足して 12件、268,080 bytes。増えた分は1年でおよそ 220 KB。Cloudflare KV の値の上限（25 MiB）に対して十分に小さい
- `80632` は、交換所 42件（素材のみ。`purchaseType='item'` かつ `payType='eventItem'`）、周回ノード 7件。対価の通貨は3種類（武蔵うどん 15件・江戸むすび 15件・東干し柿 12件）
- 11件すべてで、対価の通貨の名前が `itemMap` から引けた（名前の無いエントリーは0件）
- `80614`（レジストリに料理作成として登録済み）も交換所イベントとして入る。KV とレジストリの機能は和集合になる

## Risks / Trade-offs

- [ロトの無いイベントの数だけ KV が増える] → 1年で約 220 KB。上限に対して小さい
- [箱イベントで `'shop'` も返るようになる] → 個別ページは `'box'` があれば交換所一覧を出さないので、表示は変わらない。一覧のバッジに「交換所」が増える
- [`currency` に交換所の最初の通貨が入る] → 箱計画を出さないので使われない。後で `currency` を読む機能を足すときは、ロトの有無を見る
