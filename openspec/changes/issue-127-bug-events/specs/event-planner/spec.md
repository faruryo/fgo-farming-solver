## ADDED Requirements

### Requirement: イベント機能の判定と交換所一覧
システムは、イベントページで使える機能を KV のイベントの中身から判定しなければならない (SHALL)。ロトが1件以上あるときだけボックス計画を、交換所が1件以上あるときは交換所を、使える機能としなければならない (SHALL)。ロトが無いイベントでボックス計画の画面を出してはならない (SHALL NOT)。KV に交換所のデータがあってロトが無いイベントのページには、交換所の一覧を出さなければならない (SHALL)。KV に交換所のデータが無いときは、交換所一覧を出してはならない (SHALL NOT)。一覧は対価の通貨ごとにまとめ、通貨ごとに全交換に要る合計と、各品目の名前・1回の個数・在庫上限・1回の対価を示さなければならない (SHALL)。在庫上限の無い品目は合計に含めず、上限が無いことを示さなければならない (SHALL)。ロトのあるイベントは、交換所を今までどおりボックス計画の中で扱い、交換所一覧を重ねて出してはならない (SHALL NOT)。

#### Scenario: ロトの無い交換所イベントのページ
- **WHEN** ユーザーが、ロトが無く交換所のあるイベント（例: `80632`）の `/events/[id]` を開いたとき
- **THEN** ボックス計画は表示されず、交換所一覧が通貨ごとに表示される。
- **AND** 各通貨の見出しに通貨名と全交換に要る合計が出て、その下に品目が並ぶ。

#### Scenario: ダッシュボードと一覧への掲載
- **WHEN** ロトが無く交換所のあるイベントが取り込まれているとき
- **THEN** ダッシュボードの開催中イベントのカードに「イベントページ」リンクが出て、`/events` 一覧にも交換所のバッジ付きで出る。

#### Scenario: ロトのあるイベントの表示は変わらない
- **WHEN** ユーザーが、ロトと交換所の両方があるイベントのページを開いたとき
- **THEN** ボックス計画が今までどおり表示され、交換所一覧は別に表示されない。

#### Scenario: 通貨名を持たない古いデータ
- **WHEN** 交換所のエントリーに通貨の表示名が保存されていないとき
- **THEN** 交換所一覧は通貨の ID を見出しに出し、エラーにならない。

## MODIFIED Requirements

### Requirement: イベントデータの取り込み
システムは、ロトか交換所のあるイベントのロトボックス・交換所・イベント通貨の情報を Atlas Academy の `nice_event` から取得・コンパクト化して KV (`event_data_json`) に保存しなければならない (SHALL)。取得・整形は GitHub Actions 定期ワークフローで行い、Cloudflare Workers では KV を読むだけとする。保存は**全置換ではなく蓄積マージ**とし、過去に取り込んだイベントは取り込み窓の外になっても KV から削除してはならない (SHALL NOT)。Atlas のロトが0件で交換所のあるイベントは、ロトを空として取り込まなければならず (SHALL)、ロトも交換所も無いイベントは取り込んではならない (SHALL NOT)。Atlas のロトが1件以上あってすべて検証に通らないイベントは、交換所イベントとして取り込んではならず (SHALL NOT)、今までどおりスキップしなければならない (SHALL)。交換所の各エントリーには、対価の通貨の表示名とアイコンを、取得できるときに保存しなければならない (SHALL)。

#### Scenario: ロトボックスと箱コストの取得
- **WHEN** 取り込みワークフローがロトのある対象イベントを処理するとき
- **THEN** 各ロトの「1箱あたりの確定内容（アイテムと個数）」「1箱あたりのコスト（イベント通貨と個数）」「箱の最大数（`maxNum`）」「レアボックス判定（`isRare`）」が KV に保存される。

#### Scenario: 交換所の取得
- **WHEN** 取り込みワークフローが対象イベントを処理するとき
- **THEN** 交換所アイテムの「獲得物」「コスト（通貨・個数）」「在庫上限（`limitNum`）」が KV に保存される。

#### Scenario: 過去イベントの蓄積保持（マージ）
- **WHEN** 取り込みワークフローが実行され、既存 KV に過去のロト型イベントが存在するとき
- **THEN** 既存イベントは `id` をキーに温存され、今回フェッチしたイベントは同一 `id` を新データで上書き（upsert）、今回フェッチに含まれない過去イベントは削除されずに残る。

#### Scenario: 過去イベントのバックフィル
- **WHEN** 取り込み対象期間の下限を過去に遡って指定して取り込みを実行したとき
- **THEN** 指定期間内の過去ロト型イベントが `nice_event` から取得され、蓄積マージで KV に追加される。

#### Scenario: スキーマ不整合のスキップ
- **WHEN** あるイベントの `nice_event` がバリデーションに失敗したとき
- **THEN** そのイベントはスキップされ、他のイベントの取り込みと既存 KV データは影響を受けない。

#### Scenario: 上流障害時の既存データ保護
- **WHEN** 取り込み元のイベントカタログ (`basic_event.json`) が空、または既存 KV の取得に失敗したとき
- **THEN** KV への書き込みは行われず、既存の `event_data_json` がそのまま温存される（空データで上書きしない）。

#### Scenario: 変化が無いときの非書き込み
- **WHEN** マージ結果が既存 KV と同一（新規追加・更新が無い）のとき
- **THEN** KV への書き込みはスキップされ、既存データが温存される。

#### Scenario: 既存恒常データの不可侵
- **WHEN** イベントデータを取り込むとき
- **THEN** 恒常ドロップデータ (`all_drops_json`) と `getWars` の `eventId == 0` フィルタは変更されない。

#### Scenario: ロトの無い交換所イベントの取り込み
- **WHEN** 取り込みワークフローが、ロトが空で交換所のあるイベント（例: `80632`）を処理するとき
- **THEN** そのイベントはロトを空、交換所と周回ノードを箱イベントと同じ形にして KV に保存される。
- **AND** 交換所の各エントリーに、対価の通貨の表示名とアイコンが保存される。

#### Scenario: ロトの検証がすべて失敗したイベントのスキップ
- **WHEN** Atlas のロトが1件以上あり、そのすべてが検証に通らないイベントを処理するとき
- **THEN** そのイベントは交換所イベントとして取り込まれずにスキップされ、既存 KV の同じイベントのデータは影響を受けない。

#### Scenario: ロトも交換所も無いイベントのスキップ
- **WHEN** 取り込みワークフローが、ロトも交換所も空のイベントを処理するとき
- **THEN** そのイベントは KV に保存されない。

### Requirement: ロト計画 UI
システムは、開催中（および直近終了）のロト型イベントの一覧と、個別イベントの計画ページを提供しなければならない (SHALL)。MVP では既存の恒常導線 (`/material` → `/farming`) を変更しない独立ルート (`/events`) として提供する。一覧・計画の各ページは、URL 直打ち以外にアプリ内の常設導線（グローバルナビ等）から到達可能でなければならず (SHALL)、どのページもオーファン（到達不能）であってはならない (SHALL NOT)。

#### Scenario: イベント一覧
- **WHEN** ユーザーが `/events` を開いたとき
- **THEN** 取り込み済みのイベント（ロトの無い交換所イベントを含む）が会期情報とともに一覧表示され、会期外（終了済み）は明示される。
- **AND** 各イベントには使える機能（ボックス計画・交換所・料理作成）がバッジで示される。

#### Scenario: 一覧ページへの常設導線（オーファン禁止）
- **WHEN** ユーザーがアプリのどの画面からでもロトイベント機能を探すとき
- **THEN** グローバルナビゲーション（`components/common/nav.tsx`）に `/events` 一覧への常設エントリが存在し、URL 直打ちなしで一覧ページへ到達できる。
- **AND** ダッシュボードからの個別イベント直行導線（`/events/[id]`）は一覧導線を代替せず、両者が併存する。

#### Scenario: 計画ページへの遷移
- **WHEN** ユーザーが一覧からイベントを選ぶ、またはダッシュボードの該当イベントから遷移したとき
- **THEN** そのイベントの計画ページ (`/events/[id]`) が開き、入力フォームと算出結果が表示される。

#### Scenario: 取り込みデータ未存在時の表示
- **WHEN** 対象イベントの KV データが存在しないとき
- **THEN** 計画ページはエラーにならず、データ未取得である旨のプレースホルダを表示する。
