# Proposal

## Why

品目を交換したいかどうかは、今は交換所の行の［必要｜不要］でしか選べず、その選択は「不足素材のみ」で回数を入れるときにしか効かない。「不要」にしても入力欄は残り、入れた回数は合計・通貨の必要量・周回数に入る。オーナーは、品目ごとに「欲しい／いらない」を1回決めれば、交換所でもアイテム一覧でも同じ設定が効き、交換所では「いらない」の品目が入力欄ごと表の最後に畳まれるようにしたい（#242）。前の方向（交換所の［必要｜不要］のまま不要の行の入力欄を隠す、PR #243）は、この change で置き換える。

## What Changes

- 品目ごとの設定を「欲しい」と「いらない」の2つにする。何も設定していない品目は「欲しい」とする。設定はイベントをまたいで共通にし、交換所とアイテム一覧（/items）のどちらで変えても同じ設定になる
- 交換所の行から［必要｜不要］の切り替えをなくす。品目名をタップしたときだけ、その品目の「欲しい／いらない」のポップアップを出す
- 交換所で「いらない」の品目は入力欄を出さず、表の最後に「▸ いらない品目 N 件」として畳む。開くと名前だけが並び、名前をタップすると「欲しい」に戻せる
- 「いらない」の品目の交換回数は、通貨ごとの選んだ交換の合計・必要量・周回の内訳・合計・AP 予算に入れない。入れた回数は保存値に残し、「欲しい」に戻すと入力欄と計算に戻る
- 「全部交換」と「不足素材のみ」は「欲しい」の品目にだけ回数を入れ、「いらない」の品目の回数は変えない
- **BREAKING**（交換所の振る舞い）: 伝承結晶とカルデアの夢火を「不足素材のみ」で在庫上限まで入れる動き（既定で交換する品目）をやめる。伝承結晶はほかの素材と同じく不足の分だけ入れ、夢火はほかの計画の対象外の品目と同じく 0 にする。上限まで欲しいときは手で入れる
- 「不足素材のみ」は、「欲しい」の計画の対象外の品目を 0 にする（今の「必要」を選んだ計画の対象外の品目を在庫上限にする動きをやめる）
- アイテム一覧の全部の品目の行に「欲しい／いらない」の切り替えを常に出す
- 今の［必要｜不要］の保存値は、同じ保存値を新しい意味で読み、明示した選択を引き継ぐ
- 設定をクラウド同期の対象に加える。交換回数は今までどおり端末だけに保存する
- 交換所とアイテム一覧のほかの画面（周回ソルバーの目標、育成計算機など）には、この change では効かせない

## Capabilities

### New Capabilities

- `item-want-setting`: 品目ごとの「欲しい／いらない」の設定（値・初期値・保存と引き継ぎ・効かせる画面）、アイテム一覧での切り替え、交換所の品目名からのポップアップ、「いらない」の品目を表の最後に畳むこと、「いらない」の品目の回数を計算に入れないこと

### Modified Capabilities

- `event-shop-roster-need`: 「計画の対象外の品目の要る・要らない」（行の［必要｜不要］と既定で交換する品目）を外し、「不足素材のみ」を「欲しい」の品目の不足だけを埋める規則に変える。「品目ごとの要る・要らない」「交換所で埋まらない不足」「育成計画が使えないとき」から切り替えの記述を外し、「いらない」の品目を埋めない規則に合わせる
- `event-shop-servant-exchange`: サーヴァント扱いの品目の「必要／不要」を、品目ごとの「欲しい／いらない」の設定に従う要件に変える
- `event-shop-single-list`: まとめた行に出す育成計画の表示から「必要／不要」の切り替えを外し、まとめた行の「欲しい／いらない」を行ごとに扱う。「全部交換」「不足素材のみ」が「欲しい」の品目の回数だけを置き換えることに合わせる
- `event-shop-ap-budget`: 「全部交換」が「欲しい」の品目だけを在庫上限にし、「いらない」の品目の回数を変えない要件に変える
- `event-shop-saved-inputs`: まとめて置き換える操作の後の保存値の例を、「いらない」の品目の回数を変えない規則に合わせる
- `sync`: 品目ごとの「欲しい／いらない」の設定をクラウド同期の対象に加える

## Impact

- `lib/event-shop-summary.ts`: `DEFAULT_WANTED_ITEM_IDS` と `isDefaultWanted` の「不足素材のみ」での扱いをやめる（育成計画で扱う素材の一覧を読めないときのラベルの判定には番号を使い続ける）。`allocateShortfallOnly` を「欲しい」の品目の不足だけを埋める規則にし、「いらない」の品目の回数を変えない。`selectAllCurrenciesUpToLimit` を「欲しい」の品目だけにする。必要量（`computeShopCurrencyNeeds`）に渡す回数から「いらない」の品目を除く
- `components/events/EventShopList.tsx`: `WantedToggle` と行の2段目（`RowPlanRow`）の切り替えをなくし、品目名のポップアップ（`components/ui/popover.tsx`）と、表の最後の畳んだ「いらない品目」を足す。`useWantedItems` を、未設定を「欲しい」とする読み方に変える
- `components/items/index.tsx`（/items）: 行ごとに「欲しい／いらない」の切り替えを足す。行は短縮 ID だが、設定は Atlas の番号で引く（`atlasId`）
- `lib/constants/storage-keys.ts`: `events/shopWantedItems` を `CLOUD_SYNC_KEYS` に加え、`storage-keys.test.ts` の並びの検査を直す
- 文言は `locales/ja.json` と `locales/en.json` に足す
- 対象件数: 実データを取れなかった。変わる対象は利用者の端末の保存値（品目ごとの選択と交換回数）で、repo からは読めない。交換所の側（伝承結晶と夢火の品目を持つ交換所の数）は、手元の dev KV の写しを `pnpm exec wrangler kv key get event_data_json --binding MASTER_DATA --local` で読もうとしたが wrangler がエラーで終わり、数えなかった。影響は design.md の判断点の例で説明した
