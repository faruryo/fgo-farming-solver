# Proposal

## Why

交換所の周回計算の一覧では、「計画の対象外」の品目と既定で交換する品目（伝承結晶とカルデアの夢火）の行に「必要／不要」の切り替えが出る。sm 未満の幅では、状態と切り替えを行の下の2段目に置く（#240）ため、これらの行は約2段の高さになる。「不要」の品目には回数を入れないので、交換回数の入力欄は要らない（#242、オーナーの発案）。育成対象を設定した状態では、計画の対象外で不要の品目（月より団子・サーヴァントコイン・フォウくんなど）が多く、入力欄を外してその位置に切り替えを置けば、不要の行が1段で済み、表が縦にかなり短くなる。

入力欄を隠すと、見えない回数が合計に入りうる。全部交換は全品目に回数を入れ、切り替えは交換回数を変えず、交換回数はイベントごとに保存するのに、要る・要らないの選択はイベントをまたいで共通だからだ。隠すと同時に、見えない回数を計算に入れない規則を決める。

## What Changes

- 育成計画から見た状態と切り替えを出している行のうち、「不要」を選んでいて、不足素材のみの操作で回数が入らない行（以下「隠す行」）では、交換回数の入力欄を出さず、その位置に「必要／不要」の切り替えを置く。状態のラベルは品目名の下に置き、sm 未満でも行の下の2段目を出さない
- 隠す行の交換回数は、保存値を残したまま、通貨ごとの必要量・選んだ交換の合計・周回の内訳・合計・AP 予算に入れない。保存値に回数があっても、画面のどこにも出ない回数が計算に入ることはない
- 「必要」に戻すと入力欄が戻り、残しておいた保存値が入力欄と計算に戻る
- 「全部交換」は、隠す行の交換回数を変えない（上限まで入れない）。説明の文言を、不要にした品目を除くことが分かるものにする
- 要る・要らないの選択は、今までどおりイベントをまたいで共通に端末へ保存する
- 不足のある既定で交換する品目（「あと N 個」の伝承結晶など）は、「不要」でも不足素材のみが不足の分の回数を入れるので、入力欄を出す（隠す行にしない）
- 育成計画が使えないときなど、切り替えを出していない行は、今までどおり入力欄を出し、保存値を計算に入れる

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `event-shop-roster-need`: 「不要」の品目の行で交換回数の入力欄を隠し、その行の回数を計算に入れず、全部交換の対象から外す要件を足す。切り替えが交換回数を変えない今の規則と、選択をイベントをまたいで共通に保存する今の規則は変えない

## Impact

- `components/events/EventShopList.tsx`: `ShopRow` で、隠す行は入力欄の代わりに切り替えを出し、sm 未満の2段目（`RowPlanRow`）を出さない。隠す行の判定は `RowPlan` の状態と選択から出す。通貨ごとの必要量・周回計算（`computeShopCurrencyNeeds` → `planShopCurrencies`）と通貨ごとの選んだ交換の合計に渡す交換回数から、隠す行の回数を除く。「全部交換」（`selectAllCurrenciesUpToLimit` の呼び出し）で隠す行の回数を変えない。全部交換の説明の文言を変える（`locales/ja.json`・`locales/en.json`）
- `lib/event-shop-summary.ts`: 交換回数から指定した行の回数を除く関数、または全部交換の対象から除く引数を足す（形は実装で決める）
- 交換回数の保存の形、要る・要らないの保存の形とキー（`events/shopWantedItems`）は変えない。前に保存した値はそのまま読む
- 不足素材のみの割り当て（`allocateShortfallOnly`）の規則は変えない。今の規則で、隠す行には常に 0 を入れる
- 取り込み・判定・絞り込みの条件（どのデータが対象になるか）は変えないので、実データの件数は数えない
