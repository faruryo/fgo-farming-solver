## ADDED Requirements

### Requirement: サーヴァント扱いの品目の欲しい・いらない
システムは、アイテムの品目が1つ以上ある交換所で、サーヴァント扱いの品目を、育成計画で扱わない品目として「計画の対象外」と表示し、アイテムの品目と同じく品目ごとの「欲しい／いらない」の設定（`item-want-setting`）に従わせなければならない (SHALL)。初期値・端末への保存・別のイベントでも同じ設定を使うこと・品目名からのポップアップ・「いらない品目」への畳み・「いらない」の回数を計算に入れないこと・不足素材のみの操作での回数の入れ方（計画の対象外の品目として 0 にする）・育成計画が未設定や読み込み中・失敗のときと、育成計画で扱う素材の一覧を読み込めないときにラベルを表示しないことは、アイテムの計画の対象外の品目と同じとする。設定は獲得物ごとに持ち、獲得物の番号が同じアイテムの品目の設定と取り違えてはならない (SHALL NOT)。サーヴァント扱いの品目は、交換所で埋まらない不足の要約に数えない。品目がすべてサーヴァント扱いの交換所は、「品目がすべてサーヴァント扱いの交換所の一覧」に従い、ラベル・ポップアップ・「いらない品目」を表示しない。

#### Scenario: 礼装をいらないにする
- **WHEN** 利用者が在庫上限 2 の礼装に 2 を入れてから、礼装の品目名をタップして「いらない」を選んだとき
- **THEN** 礼装の行は表の最後の「いらない品目」に入り、その 2 回は通貨の必要量と周回の合計に入らない

#### Scenario: 不足素材のみで種火は 0 になる
- **WHEN** 在庫上限 100 の種火が「欲しい」で、利用者が不足素材のみの操作をしたとき
- **THEN** 種火の交換回数は 0 になる

#### Scenario: 別のイベントでも同じ設定を使う
- **WHEN** 利用者があるイベントの交換所で星のフォウくんを「いらない」にし、星のフォウくんを並べる別のイベントの交換所を開いたとき
- **THEN** 別のイベントでも星のフォウくんは「いらない」になっている

#### Scenario: 番号が同じアイテムの品目とは別に持つ
- **WHEN** サーヴァント扱いの品目と、獲得物の番号が同じアイテムの品目があり、利用者がサーヴァント扱いの品目だけを「いらない」にしたとき
- **THEN** アイテムの品目は「欲しい」のまま変わらない

## MODIFIED Requirements

### Requirement: 品目がすべてサーヴァント扱いの交換所の一覧
システムは、ロトの無い交換所イベントで、交換所の品目がすべてサーヴァント扱いの品目のとき、イベントページの交換所を品目の一覧だけとして表示しなければならない (SHALL)。周回クエストの有無とドロップの統計の有無は、この判定に使ってはならない (SHALL NOT)。一覧は、周回計算のある交換所と同じく、品目を通貨ごとのカードに分けずに交換所の順の1つの一覧とし、複数の通貨で交換できる品目を同じ規則で1行にまとめ、品目ごとに名前・アイコン・1回の個数・対価（通貨の名前またはアイコンと数。まとめた行は通貨ごと）・在庫上限（無いときは上限なし。まとめた行は合計と通貨ごとの在庫上限）を表示しなければならない (SHALL)。通貨名が無い通貨は ID の見出しで表示しなければならない (SHALL)。

一覧だけのときは、全交換の合計と上限なしの品目の数、交換回数の入力、全部交換と不足素材のみの操作、ドロップ増加礼装のボーナスの入力、通貨ごとの所持数の入力と選んだ交換の合計と必要量、1周あたりの獲得量、周回の内訳、合計の周回数と AP、周回できないことや周回が不要なことの表示、AP 予算、「計画の対象外」のラベル、品目名からの「欲しい／いらない」のポップアップと「いらない品目」の畳みを表示してはならない (SHALL NOT)。交換所のセクションの見出しと説明は、周回計算をしないことが分かるものにしなければならない (SHALL)。この要件は、同じ交換所について、次の要件より優先する。`event-planner` の「ロトの無い交換所イベントの周回計画」、`event-shop-efficiency` のすべての要件（「品目の効率」「効率順の1つの一覧」「効率の区切りを設けない」）、`event-shop-single-list` の「通貨ごとの所持数と必要量を品目の一覧の上と下に出す」と、「複数の通貨で交換できる品目を1行にまとめる」のうち、まとめる条件とまとめた行の在庫上限・対価の表示を除く部分（育成計画の表示、交換回数の入力と分け方、通貨ごとの交換回数の表示、全部交換と不足素材のみの合計と内訳の表示）、`event-shop-roster-need` のすべての要件（「欲しい品目の要る・要らない」「欲しい品目の不足素材のみ」「交換所で埋まらない不足」「育成計画が使えないとき」）、`item-want-setting` のうち交換所に当たる要件（「交換所の品目名からの欲しい・いらない」「いらない品目を表の最後に畳む」「いらない品目の回数を計算に入れない」）、`event-shop-ap-budget` のすべての要件（「全部交換の操作」「交換所の AP 予算」「マスターレベルと黄金の果実の所持数」）、`event-drop-bonus` のうち交換所に当たる要件（「ボーナスの入力」「ボーナス込みの1周の獲得量」「交換所の周回計算への反映」）。同じ capability の「サーヴァント扱いの品目の表示と計算」と「サーヴァント扱いの品目の欲しい・いらない」は、アイテムの品目が1つ以上ある交換所に限る。

品目が1つでもアイテムの品目（サーヴァント扱いであることを持たない既存のデータの品目を含む）である交換所は、一覧だけにしてはならない (SHALL NOT)。イベント一覧（`/events`）とダッシュボードのイベントの表示（交換所のバッジとイベントページへの導線）は、一覧だけの交換所でも変えてはならない (SHALL NOT)。

#### Scenario: 周回場所の無い礼装だけの交換所
- **WHEN** ロトが無く、交換所の品目がすべて礼装で、周回クエストが無いイベント（例: 80638）のイベントページを開いたとき
- **THEN** 交換所の品目が交換所の順の1つの一覧に、名前・アイコン・1回の個数・対価・在庫上限とともに並び、交換回数の入力・全部交換・所持数・必要量・周回の内訳・AP 予算は表示されない

#### Scenario: 周回場所はあるが通貨が落ちない礼装だけの交換所
- **WHEN** ロトが無く、交換所の品目がすべて礼装で、周回クエストはあるがどのドロップの統計にも対価の通貨が無いイベント（例: 80613）のイベントページを開いたとき
- **THEN** 周回場所の無い礼装だけの交換所と同じく、品目の一覧だけが表示され、ドロップ増加礼装のボーナスの入力と1周あたりの獲得量は表示されない

#### Scenario: アイテムの品目が1つでもある交換所
- **WHEN** 交換所に礼装と、アイテムの品目が1つ以上あるとき
- **THEN** 交換所は今までどおり周回計算として表示され、礼装は交換回数の入力と全部交換に入る

#### Scenario: 一覧のバッジは変えない
- **WHEN** 品目がすべてサーヴァント扱いの交換所を持つイベントが、イベント一覧に載るとき
- **THEN** そのイベントには今までどおり交換所の機能のバッジが付く

## REMOVED Requirements

### Requirement: サーヴァント扱いの品目の必要／不要
**Reason**: サーヴァント扱いの品目の［必要｜不要］の切り替えを、品目ごとの「欲しい／いらない」の設定（`item-want-setting`）に従わせる「サーヴァント扱いの品目の欲しい・いらない」に置き換えるため。不足素材のみで「必要」の品目を在庫上限にする扱いもなくなる。
**Migration**: 前に「必要」と保存したサーヴァント扱いの品目は「欲しい」、それ以外は「欲しい」（未設定）として読む。獲得物ごとに持ち、番号が同じアイテムの品目と取り違えない扱いは「サーヴァント扱いの品目の欲しい・いらない」に移す。
