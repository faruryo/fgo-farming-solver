## ADDED Requirements

### Requirement: 欲しい品目の要る・要らない
システムは、ロトの無い交換所イベントの交換所の品目を、このサイトの育成計画で扱う素材（育成計画が必要数を出しうる素材。QP を除く）と、それ以外の品目に分け、「欲しい」の品目ごとに次のどれかを表示しなければならない (SHALL)。育成計画で扱う素材は、育成計画の必要数から所持数を引いた不足（0 未満は 0）を求め、必要数が 1 以上で不足が 0 なら「足りている（交換不要）」、不足が 1 以上なら「あと N 個」（N は不足）、必要数が 0 なら「使わない」と表示する。育成計画で扱わない品目（呼符・サーヴァントコイン・聖杯・コード・リムーバー・カルデアの夢火・他のイベントアイテムなど）は「計画の対象外」と表示する。育成計画で扱う素材の一覧を読み込めないときは、必要数が 0 の品目にラベルを表示せず、計画の対象外の品目を見分けられないことを表示しなければならない (SHALL)。ただし伝承結晶とカルデアの夢火は番号で扱いが決まっているので、一覧を読み込めないときも、伝承結晶は育成計画で扱う素材として、夢火は計画の対象外として、ラベルを表示しなければならない (SHALL)。QP の品目は対象に含めず、ラベルを表示しない。「いらない」の品目は、表の最後の畳んだ「いらない品目」（`item-want-setting`）に名前だけを出し、ラベルを表示しない。不足は品目が得る素材ごとに求め、交換所に同じ素材の品目が複数あっても同じ不足を表示する。育成計画と所持数は、育成計画のページと所持数のページで保存した値を読むだけとし、交換所の画面から書き換えてはならない (SHALL NOT)。

#### Scenario: 不足がある素材
- **WHEN** 育成計画で素材 S の必要数が 30、所持数が 25 のとき
- **THEN** 素材 S の品目に「あと 5 個」と表示される

#### Scenario: 足りている素材
- **WHEN** 育成計画で素材 S の必要数が 30、所持数が 40 のとき
- **THEN** 素材 S の品目に「足りている（交換不要）」と表示される

#### Scenario: 育成計画で扱うが必要数が 0 の素材
- **WHEN** 品目が育成計画で扱う素材で、育成計画での必要数が 0 のとき
- **THEN** その品目に「使わない」と表示される

#### Scenario: 育成計画で扱わない品目
- **WHEN** 品目が呼符・コード・リムーバー・他のイベントアイテムのどれかのとき
- **THEN** その品目に「計画の対象外」と表示される

#### Scenario: 育成計画で扱う素材の一覧を読み込めないとき
- **WHEN** 育成計画は読み込めたが、育成計画で扱う素材の一覧を読み込めなかったとき
- **THEN** 不足のある素材と足りている素材にはラベルが表示され、伝承結晶と夢火を除く必要数が 0 の品目にはラベルが表示されず、計画の対象外の品目を見分けられないことが表示される

#### Scenario: 一覧を読み込めないときの伝承結晶と夢火
- **WHEN** 伝承結晶と夢火の育成計画での必要数が 0 で、育成計画で扱う素材の一覧を読み込めなかったとき
- **THEN** 伝承結晶の品目に「使わない」、夢火の品目に「計画の対象外」と表示される

#### Scenario: いらない品目にはラベルを出さない
- **WHEN** 育成計画で素材 S の不足が 5 で、利用者が素材 S の品目を「いらない」にしているとき
- **THEN** 素材 S の品目は表の最後の「いらない品目」に名前だけが出て、「あと 5 個」は表示されない

### Requirement: 欲しい品目の不足素材のみ
システムは、交換所の周回計算に「不足素材のみ」の操作を設けなければならない (SHALL)。操作をすると、「欲しい」のすべての品目の交換回数を次のとおりに置き換える。不足のある素材について、交換所の元の順に「欲しい」の品目を見て、まだ埋まっていない不足を「1回の交換で得る個数」で割って切り上げた回数を、在庫上限のある品目では在庫上限までで入れ、入れた回数で得る個数を不足から差し引いて次の品目へ進む。在庫上限の無い品目は上限で打ち切らない。伝承結晶とカルデアの夢火も、ほかの品目と同じ規則で扱う。「欲しい」の品目のうち、1回の交換で得る個数が 0 以下の品目と、それ以外の品目（足りている素材・使わない素材・計画の対象外の品目・QP の品目）は 0 にする。「いらない」の品目の交換回数は変えてはならない (SHALL NOT)。操作の後の必要量・周回の内訳・合計・AP 予算は、利用者が各品目に同じ回数を入れたときと同じでなければならない (SHALL)。操作の後も、利用者は「欲しい」の各品目の交換回数を変えられなければならない (SHALL)。育成計画・所持数・品目の「欲しい／いらない」が変わっても、入れ終えた交換回数を操作なしに変えてはならない (SHALL NOT)。

#### Scenario: 不足の分だけ交換する
- **WHEN** 素材 S の不足が 5 で、素材 S を1回に1個得る在庫上限 10 の品目があり、利用者が不足素材のみの操作をしたとき
- **THEN** その品目の交換回数は 5 になり、足りている品目・使わない品目・計画の対象外の品目の交換回数は 0 になり、それに合う必要量と周回の合計が出る

#### Scenario: 1回に複数個得る品目
- **WHEN** 素材 S の不足が 5 で、素材 S を1回に3個得る在庫上限 10 の品目があるとき
- **THEN** 不足素材のみの操作で、その品目の交換回数は 2 になる

#### Scenario: 同じ素材の品目が複数あるとき
- **WHEN** 素材 S の不足が 5 で、交換所の元の順に、素材 S を1回に1個得る在庫上限 3 の品目と、在庫上限 10 の品目があるとき
- **THEN** 不足素材のみの操作で、前の品目の交換回数は 3、後の品目の交換回数は 2 になる

#### Scenario: 在庫上限の無い素材の品目
- **WHEN** 素材 S の不足が 7 で、素材 S を1回に1個得る在庫上限の無い品目だけがあるとき
- **THEN** 不足素材のみの操作で、その品目の交換回数は 7 になる

#### Scenario: 計画の対象外の品目
- **WHEN** 在庫上限 1 のコード・リムーバーと在庫上限 1 の夢火がどちらも「欲しい」で、利用者がコード・リムーバーに 1 を入れてから不足素材のみの操作をしたとき
- **THEN** コード・リムーバーと夢火の交換回数は 0 になる

#### Scenario: 育成計画で使わない伝承結晶
- **WHEN** 伝承結晶が「欲しい」で、育成計画での必要数が 0 で、交換所に伝承結晶を1回に1個得る在庫上限 2 の品目があり、利用者が不足素材のみの操作をしたとき
- **THEN** その品目の交換回数は 0 になる

#### Scenario: 不足が在庫上限より少ない伝承結晶
- **WHEN** 伝承結晶が「欲しい」で、伝承結晶の不足が 1 で、伝承結晶を1回に1個得る在庫上限 2 の品目があり、利用者が不足素材のみの操作をしたとき
- **THEN** その品目の交換回数は 1 になる

#### Scenario: いらない品目の回数は変えない
- **WHEN** 素材 S の不足が 5 で、素材 S を1回に1個得る在庫上限 10 の品目を利用者が「いらない」にしていて、その品目の保存した交換回数が 3 のときに、不足素材のみの操作をしたとき
- **THEN** その品目の保存した交換回数は 3 のまま変わらず、計算には入らず、素材 S の不足は埋まらない

## MODIFIED Requirements

### Requirement: 交換所で埋まらない不足
システムは、育成計画の不足のある素材（QP を除く）のうち、交換所に品目があるものについて、不足素材のみの回数で埋まる素材の数と、不足のある素材の数を要約として表示しなければならない (SHALL)。不足素材のみの回数は「欲しい」の品目にだけ入るので、品目がすべて「いらない」の素材は埋まらない素材として数える。在庫上限まで交換しても不足が残る素材は、その素材の「欲しい」の品目のうち交換所の元の順で最後の品目に、残る個数を「交換所では N 個足りない」と表示しなければならない (SHALL)。交換所に品目の無い素材の不足と、計画の対象外の品目は、この要約に数えない。

#### Scenario: 在庫上限で埋まらない
- **WHEN** 素材 S の不足が 15 で、素材 S を1回に1個得る在庫上限 10 の「欲しい」の品目だけがあるとき
- **THEN** その品目に「交換所では 5 個足りない」と表示され、要約では素材 S は埋まらない素材として数えられる

#### Scenario: 要約
- **WHEN** 交換所に品目のある素材のうち3つに不足があり、そのうち2つが不足素材のみの回数で埋まるとき
- **THEN** 「育成計画の不足 3 素材のうち、交換所で埋まるのは 2 素材」と要約が表示される

#### Scenario: いらない品目しかない素材
- **WHEN** 素材 S の不足が 5 で、素材 S の品目が1つだけあり、利用者がその品目を「いらない」にしているとき
- **THEN** 要約で素材 S は埋まらない素材として数えられ、「交換所では N 個足りない」はどの行にも表示されない

#### Scenario: 最後の品目がいらないとき
- **WHEN** 素材 S の不足が 5 で、交換所の元の順に、素材 S を1回に1個得る在庫上限 3 の「欲しい」の品目 A と、在庫上限 10 の「いらない」の品目 B があり、利用者が不足素材のみの操作をしたとき
- **THEN** 品目 A の交換回数は 3 で、品目 A の行に「交換所では 2 個足りない」と表示される

### Requirement: 育成計画が使えないとき
システムは、育成対象のサーヴァントが設定されていないときは、品目ごとの要る・要らないの表示と要約を表示してはならず (SHALL NOT)、不足素材のみの操作を使えなくし、育成対象を設定するページへのリンクを表示しなければならない (SHALL)。育成計画の素材を読み込んでいる間は読み込み中と表示し、読み込みに失敗したときは失敗したことを表示して、どちらのときも要る・要らないを表示せず、操作を使えなくしなければならない (SHALL)。どの状態でも、交換回数の入力・全部交換・周回の内訳・品目名からの「欲しい／いらない」のポップアップ・「いらない品目」の畳みはこれまでどおり使えなければならない (SHALL)。

#### Scenario: 育成計画が未設定
- **WHEN** 育成対象のサーヴァントが1人も設定されていないとき
- **THEN** 品目に要る・要らないは表示されず、不足素材のみの操作は押せず、育成対象を設定するページへのリンクが表示され、全部交換・交換回数の入力・品目名のポップアップは使える

#### Scenario: 読み込みに失敗したとき
- **WHEN** 育成計画の素材の一部を取得できなかったとき
- **THEN** 失敗したことが表示され、品目に要る・要らないは表示されず、不足素材のみの操作は押せない

## REMOVED Requirements

### Requirement: 品目ごとの要る・要らない
**Reason**: 品目ごとの育成計画の状態の表示を、「欲しい」の品目だけに出し、伝承結晶と夢火の切り替えの記述を外した「欲しい品目の要る・要らない」に置き換えるため。
**Migration**: 状態の判定（「あと N 個」「足りている（交換不要）」「使わない」「計画の対象外」）は変えずに「欲しい品目の要る・要らない」へ移す。「いらない」の品目は `item-want-setting` の「いらない品目を表の最後に畳む」に従い、ラベルを出さない。

### Requirement: 不足素材のみ
**Reason**: 伝承結晶と夢火を在庫上限まで入れる扱いと、「必要」を選んだ計画の対象外の品目を在庫上限にする扱いをやめ、「欲しい」の品目の不足だけを埋める「欲しい品目の不足素材のみ」に置き換えるため。
**Migration**: 不足のある素材の割り当ての規則（交換所の元の順・1回の個数で割って切り上げ・在庫上限で打ち切り）は「欲しい品目の不足素材のみ」にそのまま移す。伝承結晶・夢火・計画の対象外の品目を在庫上限まで交換したいときは、交換回数を手で入れるか「全部交換」を使う。

### Requirement: 計画の対象外の品目の要る・要らない
**Reason**: 行ごとの［必要｜不要］の切り替えと、伝承結晶・夢火を既定で必要とする扱いを、品目ごとの「欲しい／いらない」の設定（`item-want-setting`）に置き換えるため。計画の対象外の品目を初期値で「不要」とする扱いと、切り替えが交換回数を変えず「不足素材のみ」でだけ効く扱いもなくなる。
**Migration**: 前の［必要｜不要］の保存値は `item-want-setting` の「品目ごとの欲しい・いらない」のとおりに読み、「必要」は「欲しい」、「不要」は「いらない」、保存の無い品目は「欲しい」になる。伝承結晶と夢火を在庫上限まで交換したいときは、交換回数を手で入れる。
