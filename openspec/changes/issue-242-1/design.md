# Design

## Context

交換所の周回計算の一覧（`components/events/EventShopList.tsx`）の今の作りは次のとおり。

- 「必要／不要」の切り替えは、育成計画が使えるときに、状態が「計画の対象外」の品目と、既定で交換する品目（伝承結晶とカルデアの夢火）の行にだけ出る（`RowPlanLabel` の `toggleable`）。sm 未満では、状態と切り替えを行の下の2段目（`RowPlanRow`）に置く（#240）
- 切り替えの役目は、「不足素材のみ」で回数を入れるときにその品目を含めるかを決めることだけ。入力欄は必要でも不要でも手で入れられ、切り替えは交換回数を変えない（`event-shop-roster-need` の「計画の対象外の品目の要る・要らない」）
- 選択は品目ごとにイベントをまたいで共通に端末へ保存する（`events/shopWantedItems`）。交換回数はイベントごとに保存する（`events/shopInputs/<イベント>`）
- 「全部交換」は在庫上限のある品目をすべて上限にする（`selectAllCurrenciesUpToLimit`）。「不足素材のみ」はすべての品目の回数を置き換え、計画の対象外で「不要」の品目には 0 を入れる。既定で交換する品目は、「不要」でも不足の分だけ回数を入れる
- 通貨ごとの選んだ交換の合計と必要量は `computeShopCurrencyNeeds(shop, counts, owned)` で出し、周回の内訳・合計・AP 予算・ボーナス礼装の比較はその必要量から出す

## Goals / Non-Goals

**Goals:**

- 「不要」の行に交換回数の入力欄を出さず、sm 未満でもその行を1段にする
- 画面に出ない回数が、通貨ごとの合計・必要量・周回数に入らないようにする
- issue の決めなければならないこと 1〜3 と、入力欄を隠す行の範囲を仕様に書く

**Non-Goals:**

- 要る・要らないの保存の形とキー、交換回数の保存の形を変えること
- 「不足素材のみ」の割り当ての規則を変えること
- 通貨ごとの「全交換の合計」（在庫上限のある品目をすべて交換するのに要る数。交換所全体の参考値）から不要の品目を除くこと。利用者の選んだ交換ではなく交換所の大きさを示す値なので今のまま出す
- 必要の行（入力欄を出す行）の2段目をなくすこと。必要の行は入力欄と切り替えの両方が要るので、今の2段のままにする

## Decisions

### 判断点

#### 1. 「全部交換」と不要の行（issue の1）

推奨: **A. 全部交換は不要の行の回数を変えない**。説明の文言を「不要にした品目を除き、上限のある品目をすべて上限まで」にする（切り替えを出していないときは今の文言のまま）。

| 案 | 不要の行に起きること | 見えない回数 | 必要に戻したときの回数 |
|---|---|---|---|
| **A. 不要の行を変えない（推奨）** | 保存値はそのまま | 計算に入れない規則（判断点3）で除く | 前に入れていた回数 |
| B. 不要の行を 0 にする | 保存値が 0 になる | 0 なので入らない | 0 |
| C. 今までどおり全品目を上限にする | 見えない保存値が上限になる | 計算から除くので合計には入らない | 上限（押した覚えのない回数が出る） |
| D. 押すと不要の品目も必要に切り替えて上限にする | 行が必要の行に戻り入力欄が出る | 無い | 上限 |

根拠: A は、全部交換が「要ると言った品目を全部」の意味になり、不要の行に手を付けないので、判断点3の「必要に戻すと前の回数が戻る」とも食い違わない。B は、全部交換を押すたびに、不要にしていた品目の前の回数が消える。C は、後で必要に戻したときに、押した覚えのない上限の回数が出る。D は、選択がイベントをまたいで共通なので、1回押すとほかのイベントでもすべての品目が必要になり、切り替えの意味がなくなる。A で取りこぼすのは、「全部交換」の名前のとおりに不要の品目まで含めたい使い方で、その場合は利用者が先に必要へ切り替える。

#### 2. イベントをまたぐ選択（issue の2）

推奨: **A. 今までどおり共通のまま**にする。「今回だけ数個交換したい」ときは、その品目を必要にして回数を入れる。

| 案 | 今回だけ数個交換するとき | ほかのイベントへの影響 | 保存の形 |
|---|---|---|---|
| **A. 共通のまま（推奨）** | 必要にして回数を入れる | その品目がほかのイベントでも必要になる（入力欄が出て、不足素材のみで在庫上限まで入る） | 変えない |
| B. イベントごとの選択にする | そのイベントだけ必要にする | 無い | 選択をイベントごとに持つ形に変え、前の選択の引き継ぎ先を決める |
| C. 共通の既定とイベントごとの上書きの2層にする | そのイベントだけ上書きする | 無い | 2層を持つ形に変え、切り替えがどちらを書くかを画面で示す |

根拠: A は保存の形も今の仕様（`event-shop-roster-need` の「別のイベントでも同じ選択を使う」）も変えず、呼符・聖杯のように毎回同じ選択をする品目を、イベントごとに選び直さずに済む今の利点を残す。ほかのイベントで必要になった品目は入力欄が出ているので、不足素材のみで在庫上限まで入ったことは行を見れば分かり、切り替え1回で戻せる。B は、毎回同じ選択をする品目を、イベントごとに選び直すことになる。C は、切り替えがイベントだけを変えるのか共通を変えるのかを画面で分けて示す必要があり、行を1段にしたい今回の目的と逆に、行の部品が増える。A で取りこぼすのは、今回だけの品目を必要にしたまま戻し忘れると、次のイベントの不足素材のみでその品目が在庫上限まで入ることだ。

#### 3. 回数を入れた後で不要にしたとき（issue の3）

推奨: **A. 保存値を残し、不要の間は計算に入れない**。必要に戻すと、残した回数が入力欄と計算に戻る。

| 案 | 切り替えたイベントの保存値 | ほかのイベントの保存値 | 必要に戻したとき |
|---|---|---|---|
| **A. 残して計算から除く（推奨）** | 残る（計算には入らない） | 残る（計算には入らない） | 前の回数が戻る |
| B. 切り替えたときに 0 にする | 0 になる | 残る。除く規則が無いと見えない回数が合計に入る | 0 |
| C. 回数が 1 以上なら不要にする前に確かめる | 確かめた後に 0 にするか残すかを選ぶ | B と同じ | 選んだとおり |

根拠: 選択はイベントをまたいで共通なので、あるイベントで不要にすると、回数を入れていたほかのイベントの行も隠れる。B で切り替えたイベントの回数を消しても、ほかのイベントの見えない回数は残るので、「計算に入れない」規則はどの案でも要る。A はその規則1つで済み、今の仕様の「切り替えは交換回数を変えない」もそのまま保つ。押し間違えて不要にしても、必要に戻せば回数が戻る。B は、押し間違えで入れた回数が消え、ほかのイベントの分は規則で除く必要があるので、規則が2つになる。C は、切り替えるたびに確かめが挟まり、ほかのイベントの回数を確かめる手段が無い。A で取りこぼすのは、不要の品目の回数が保存値に残り続けることで、画面からは見えない（不足素材のみを押すと今の規則で 0 になる）。

#### 4. 入力欄を隠す行の範囲（issue の本文の外で、仕様を書く中で見つけた点）

推奨: **A. 「不要」で、不足素材のみがその行に回数を入れない行だけ隠す**。計画の対象外の品目の不要と、不足の無い（「使わない」「足りている」）既定で交換する品目の不要が当たる。不足のある既定で交換する品目（「あと N 個」の伝承結晶など）は、不要でも入力欄を出す。

| 案 | 不足のある伝承結晶を不要にしたとき | 不足素材のみの規則 | 行が1段になる品目 |
|---|---|---|---|
| **A. 不足素材のみが 0 にする行だけ隠す（推奨）** | 入力欄が出る（今と同じ2段） | 変えない | 計画の対象外の不要と、不足の無い既定の品目の不要 |
| B. 不要の行はすべて隠し、不要の既定の品目は不足があっても不足素材のみで 0 にする | 入力欄が無く、伝承結晶を交換所で埋めない | 変える（不要＝交換しない） | 不要の行すべて |
| C. 不要の行はすべて隠し、不足素材のみは今のまま | 入力欄が無いのに、不足素材のみが不足の分の回数を入れる | 変えない | 不要の行すべて |

根拠: 今の仕様では、既定で交換する品目の「不要」は「交換しない」ではなく「在庫上限まで入れず、不足の分だけ入れる」を意味する。issue の「不要の品目には回数を入れない」は計画の対象外の品目には当たるが、不足のある既定の品目には当たらない。A は、この意味を変えずに、回数が入らない行だけを隠す。C は、不足素材のみが見えない行に回数を入れ、その回数を判断点3の規則で計算から除くので、伝承結晶の不足が交換所で埋まらなくなり、「あと N 個」と食い違う。B は、不要の伝承結晶で育成計画の不足を交換所から埋める今の使い方ができなくなる。A で取りこぼすのは、不足のある既定の品目の不要の行が2段のまま残ることで、当たるのは伝承結晶と夢火の2品目で、不足のあるときだけだ。

### 決めたこと

#### 不要の行の作り

- 不要の行では、入力欄のセルに入力欄の代わりに切り替えを置き、状態のラベル（「計画の対象外」「使わない」「足りている（交換不要）」）を品目名の下に置く。sm 未満の2段目は出さない。sm 以上でも同じ置き方にする（入力欄の列に切り替えがあり、品目のセルに状態がある）。sm 以上と sm 未満で置き場所を変えると、幅を変えたときに切り替えが別の列へ移るため
- 交換回数の列の幅は、切り替え（「必要」「不要」の2つのボタン。押せる範囲は 44px を保つ）が入る幅になる。375px で表に横スクロールが出ないこと（#240）は実装の後に実画面で確かめる。出るときは、切り替えのボタンの見た目の幅を詰める（押せる範囲は疑似要素で保つ今の作りに合わせる）
- まとめた行が不要の行のときは、品目名の下の通貨ごとの回数の内訳（`RowBreakdown`）も出さない。内訳は保存値の回数から出るので、出すと計算に入らない回数が画面に残り、行も1段に収まりにくくなる
- 不要の行の判定は、行の状態（`ShopItemStatus`）と選択と既定で交換する品目かどうかから出す。まとめた行（複数の通貨で交換できる品目の行）は、今までどおり行の最初の品目の状態と選択を使う（同じ品目なので選択のキーは同じ）

#### 計算から除く場所

- 交換回数の保存値（`counts`）は変えず、通貨ごとの必要量を出す前に、不要の行の添字の回数を除いた交換回数を作り、`computeShopCurrencyNeeds` に渡す。周回の内訳・合計・AP 予算・ボーナス礼装の比較は必要量から出るので、ここ1か所で揃う
- 「不足素材のみ」は今までどおりすべての品目の回数を置き換える。不要の行には今の規則で 0 が入るので、残していた回数はこの操作で 0 になる。これは「すべての品目の交換回数を置き換える」今の仕様のとおりで、変えない
- 育成計画が読み込み中・失敗・未設定のときは切り替えを出さないので、不要の行は無く、保存値をすべて計算に使う。読み込みが終わって切り替えが出ると、不要の行の回数が計算から外れる。今の作りは、端末の保存値（交換回数・所持数・選択）を読み終えれば、育成計画の素材を読み込んでいる間（状態が読み込み中）も計算結果を出すので、その間だけ不要の行の回数が合計に入る（Risks）

#### 全部交換の文言

- 切り替えを出しているときだけ、説明を「不要にした品目を除き、上限のある品目をすべて上限まで」にする。ボタンの名前「全部交換」は変えない。追加の文言は `t('kebab-key', '日本語')` にし、`locales/ja.json` と `locales/en.json` の両方に足す

## Risks / Trade-offs

- [交換回数の列が切り替えの幅に広がり、375px で横スクロールが出るおそれ] → 実装の後に 375px で確かめるタスクを置き、出るときは切り替えのボタンの見た目の幅を詰める
- [不要の行の回数が保存値に残り続ける] → 画面にも計算にも出ない。必要に戻すと出るので、押し間違えから戻せる利点と引き換えにする
- [必要にした品目がほかのイベントでも必要になる（判断点2）] → 入力欄が出るので行を見れば分かり、切り替え1回で戻せる
- [育成計画の素材を読み込んでいる間と、育成計画が読めた後に素材カタログ（育成計画で扱う素材の一覧）を読み込んでいる間は、不要の行の回数が合計に入り、読み込みが終わると合計が減る] → カタログを読み込んでいる間は、既定で交換する品目のほかは計画の対象外の品目に状態が出ないので、切り替えも出ず、入力欄が出て計算に入る。どちらも入力欄が出ている間だけのことで、読み込みが終われば仕様どおりの合計になる。読み込み中も選択の保存値から不要の行を決めて除く案は、状態（不足の有無）が分からないと判断点4の範囲を決められないので採らない
- [読み込みの間に全部交換を押すと、後で不要の行になる品目にも上限が入る] → 判断点1で採らなかった案 C と同じ状態で、後で必要に戻すと押した覚えのない上限が出る。読み込みの間は切り替えが無く全品目が全部交換の対象として見えているので、押した時点の画面とは食い違わない。読み込みの間だけ全部交換を押せなくする案は、育成計画を使わない利用者の全部交換も待たせるので採らない
