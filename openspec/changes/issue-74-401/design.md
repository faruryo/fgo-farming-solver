# Design

## Context

動機は proposal.md の Why のとおり。main（17b8ca7）の時点で、#74 の3項目はどれも残っている。

- 計算履歴の取得は3か所にある。推移グラフ（ダッシュボードと周回結果画面で使う）、直近の結果を返すフック（ダッシュボードの FarmingWizard・NearGoalSection・RecommendedQuest と、絆トラッカーが使う）、計算履歴ページ。どれもログイン状態を見ずに `GET /api/farming/history` を呼ぶ
- ソルバー実行後のスナップショット保存は、`/farming`（手入力）と `/material/result`（直接送信）が共有する送信処理から、ログイン状態を見ずに `POST /api/progress/snapshot` を送る
- 「計算履歴」へのリンクは、ナビゲーション・周回結果画面・ダッシュボードに常に出る
- ログイン状態は next-auth の `useSession` の `status`（`loading` / `authenticated` / `unauthenticated`）で分かる。`/farming` と `/material/result` は、公開設定のトグルのためにすでに `status` を読んでいる
- API は未ログインに 401 を返す。ただし開発環境（`NODE_ENV=development`）の `/api/farming/history` は、認証なしでモックの履歴を返す

## Goals / Non-Goals

**Goals:**
- 未ログインでは、計算履歴の導線を出さず、計算履歴の取得とスナップショット保存を送らない

**Non-Goals:**
- API 側の認証と 401 の応答は変えない
- 計算結果ページ（`/farming/results/[id]`）そのものの閲覧と公開設定は変えない
- 未ログインのユーザー向けに、端末内だけの計算履歴を作ることはしない

## Decisions

1. **判定は `status === 'authenticated'` のときだけ「ログイン」とする。** `loading` は未ログインと同じく、導線を出さず取得もしない。確認が終わって `authenticated` になったら取得する。`loading` 中に取得すると未ログインで 401 になり、導線を出すと確認後に消えてちらつくため
2. **スナップショット保存は、送信処理の呼び出し側がログイン状態を渡して決める。** 送信処理はコンポーネントの外の関数なので `useSession` を呼べない。`/farming` と `/material/result` はすでに `status` を持っているので、ログインしているかを引数で渡し、ログインしていなければ保存を呼ばない。送信処理の中で `getSession()` を呼ぶ案は、計算ごとにセッションの取得が1回増えるので採らない
3. **直近の結果のフックは、確認中は何も読まず、未ログインなら計算履歴の取得だけを飛ばす。** 確認中は読み込み中を返し続け、確認が終わってから一度だけ読む。確認中に端末の結果だけを読んで読み込みを終えると、FarmingWizard（読み込みが終わって件数が3件未満なら表示）がログインユーザーにも一瞬出て消えるため。確認後は、この端末に記録された結果の URL（`localStorage`）からの結果の読み込みを、ログイン状態に関係なく行う。公開結果は未ログインでも読めるので、ダッシュボードの直近の結果と絆トラッカーの予定周回数は、未ログインでもこれまでどおり出る。履歴の件数は 0 のままなので、FarmingWizard の表示条件（3件未満で表示）は今と同じ結果になる
4. **推移グラフは、表示する側が未ログインのとき描画しない。** グラフの中で取得を止めるだけでは、読み込み中の表示が残る。ダッシュボードと周回結果画面で、ログインしているときだけグラフとリンクを描画する
5. **計算履歴ページは、未ログインならリダイレクトせずにログインの案内を出す。** issue は「ログイン案内またはログイン画面（`/cloud`）へ誘導」としている。直接 URL を開いた人に、なぜ使えないかを伝えられるので、案内と `/cloud` へのリンクを出す方を既定にする。案内の文言は既存の翻訳キーの形に合わせて足す

## Risks / Trade-offs

- [ダッシュボードの見た目の回帰テストが変わる] Playwright の見た目のテストは未ログインで動くので、ダッシュボードの「計算履歴」リンクが消える。開発環境では履歴の API がモックを返すため、今は推移グラフも写っている可能性がある → 見た目のテストは CI で走らず、基準画像は macOS の手元で撮ったもの（`*-chromium-darwin.png`）だけなので、graph の後に呼び出し側が手元で走らせて差分を確かめる。差分が導線とグラフの消失だけなら、基準画像の更新は人が手元で行い、実装 PR の「人がやること」に書く
- [`useSession` を使うようになるコンポーネントやフックのテスト] 既存のテストに `SessionProvider` が無いと `status` が取れない → `next-auth/react` のモックを、既存のテスト（`components/farming/index.test.tsx` など）と同じ形で足す
- [開発環境で未ログインのとき、履歴のモックが見えなくなる] 開発者が履歴の画面を確かめるにはログインが要る → 許容する。本番と同じ条件で見えるほうが取り違えが少ない
