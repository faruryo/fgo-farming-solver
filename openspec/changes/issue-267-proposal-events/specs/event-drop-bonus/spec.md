## MODIFIED Requirements

### Requirement: ボーナスの入力
システムは、イベントページの交換所タブの周回計算に、交換所の通貨のうちボーナス礼装の ☆ と対応しない通貨（「ボーナス礼装の ☆ と通貨の対応の取り込み」の要件）ごとと、イベントポイントの品目（そのイベントにあるとき）の「1ドロップにつき +N」を入れる欄を設けなければならない (SHALL)。☆ と対応する通貨には、この欄を設けてはならず (SHALL NOT)、その通貨の +N は比較の表で選んだ行の編成から求めなければならない (SHALL)（「ボーナス礼装の枚数の比較」の要件）。通貨と ☆ の対応を持たないイベントデータ（取り込み直す前のデータ）では、すべての交換所の通貨を ☆ と対応しない通貨として扱わなければならない (SHALL)。値は 0 以上の整数とし、初期値は 0 とする (SHALL)。負の数・小数・数でない値は 0 以上の整数に直さなければならない (SHALL)。入れた値は、交換所の周回計算の入力の保存（event-shop-saved-inputs）に従い、イベントごとに端末に保存しなければならない (SHALL)。礼装の所持は、通貨ごとの「1ドロップにつき +N」の欄ではなく、ボーナス礼装の枚数の入力（「ボーナス礼装の枚数の入力」の要件）で入れなければならない (SHALL)。ボーナスの入力は「ドロップ増加礼装」の見出しを持つ1枚の枠にまとめ、上から、ボーナス礼装の枚数の入力、比較の表、通貨ごとの「1ドロップにつき +N」の欄の順に並べなければならない (SHALL)。見出しの近くには、何を入れると何が変わるかを1行で示さなければならない (SHALL)（例: ☆ ごとの欄があるとき「手持ちの礼装を入れると、枚数ごとの周回数と AP を比べ、選んだ編成で周回数を計算します」、無いとき「編成した礼装の 1ドロップにつき +N を入れると、1周の獲得量と周回数がボーナス込みになります」）。ボーナスをサーヴァントの効果として示してはならない (SHALL NOT)。

#### Scenario: 通貨とポイントの欄
- **WHEN** 交換所の通貨が3種類あり、イベントポイントの品目があり、通貨と ☆ の対応が1つも無いイベントを開いたとき
- **THEN** 3種類の通貨とイベントポイントの品目のそれぞれに、初期値 0 のボーナスの欄が表示される

#### Scenario: ☆ と対応する通貨の欄
- **WHEN** 交換所の通貨が金・銀・銅と盛り3種の6種類あり、☆5・☆4・☆3 がそれぞれ金・銀・銅の通貨に対応し、イベントポイントの品目があるイベントを開いたとき
- **THEN** 通貨ごとの +N の欄は盛り3種とイベントポイントの品目の分だけ、☆ ごとの欄と比較の表の下に表示され、金・銀・銅の通貨の欄は表示されない

#### Scenario: 見出しと説明
- **WHEN** 利用者が交換所の周回計算を開いたとき
- **THEN** ボーナスの入力をまとめた枠に「ドロップ増加礼装」の見出しと、入れると何が変わるかを示す1行が表示される

#### Scenario: ポイントの品目が無いイベント
- **WHEN** イベントポイントの品目が無く、通貨と ☆ の対応が1つも無いイベントを開いたとき
- **THEN** ボーナスの欄は交換所の通貨の分だけ表示される

#### Scenario: 不正な値
- **WHEN** 利用者がボーナスの欄に -3 や 2.5 を入れたとき
- **THEN** 値はそれぞれ 0 と 2 として扱われる

#### Scenario: 交換所のボーナスを開き直したとき
- **WHEN** 利用者があるイベントの交換所で、ある通貨のボーナスに 2 を入れたあと、ページを読み込み直したとき
- **THEN** その通貨のボーナスの欄は 2 のままで、1周の獲得量と周回数はボーナス込みで表示される
