## MODIFIED Requirements

### Requirement: 交換所の入力をイベントごとに保存する
システムは、イベントページの交換所タブの周回計算で利用者が入れた次の値を、イベントごとに端末に保存しなければならない (SHALL)。通貨とイベントポイントの品目ごとの「1ドロップにつき +N」のボーナス、ボーナス礼装の ☆ ごとの凸・無凸の所持枚数と、取り込んだデータにその ☆ の +N が無いときに入れた凸・無凸の「1ドロップにつき +N」、フレンドの礼装の ☆（「なし」を含む）、比較の表で選んだ行（合計枚数）、品目ごとの交換回数、通貨ごとの所持数。同じイベントの交換所を開き直したときは、保存した値を欄と計算に使わなければならない (SHALL)。保存した値を別のイベントの交換所に使ってはならない (SHALL NOT)。保存は端末だけとし、クラウド同期の対象に含めてはならない (SHALL NOT)。終わったイベントの保存値を自動で消してはならない (SHALL NOT)。利用者が値を変えるまでは、交換所を開いただけで端末に書き込んではならない (SHALL NOT)。保存値の無い欄の初期値は、今までどおり 0 とする (SHALL)。保存した値から出す必要量・周回の内訳・合計・AP 予算は、利用者が同じ値を手で入れたときと同じでなければならない (SHALL)。箱のあるイベントの箱計画の入力は、この保存の対象に含めてはならない (SHALL NOT)。

#### Scenario: 開き直しても残る
- **WHEN** 利用者が 80632 の交換所で、ある品目の交換回数に 3、ある通貨の所持数に 200、その通貨のボーナスに 2 を入れてから、ページを読み込み直したとき
- **THEN** その品目の交換回数は 3、その通貨の所持数は 200、ボーナスは 2 のままで、必要量と周回の内訳はそれらの値で表示される

#### Scenario: 別のイベントには混ざらない
- **WHEN** 利用者が 80632 の交換所で値を入れたあと、同じ通貨や同じ獲得物を並べる別のイベントの交換所を開いたとき
- **THEN** 別のイベントの交換所の交換回数・所持数・ボーナスは、そのイベントで入れた値（入れていなければ 0）で表示される

#### Scenario: ボーナス礼装の入力も開き直しても残る
- **WHEN** 利用者が ☆ と通貨の対応のあるイベントの交換所で、☆5（+N のデータあり）の凸の所持枚数に 1 を入れ、フレンドの礼装に「なし」を選び、比較の表で合計 1 枚の行を選んでから、ページを読み込み直したとき
- **THEN** ☆5 の凸の所持枚数は 1、フレンドの礼装は「なし」、比較の表は合計 1 枚の行が選ばれたままで、周回の内訳はその行の編成で表示される

#### Scenario: 開いただけでは書き込まない
- **WHEN** 利用者が一度も値を入れたことのないイベントの交換所を開き、何も変えずに閉じたとき
- **THEN** そのイベントの交換所の入力は端末に書き込まれていない

#### Scenario: 箱計画は保存しない
- **WHEN** 利用者が箱のあるイベントの箱計画で所持数やボーナスを入れたあと、ページを読み込み直したとき
- **THEN** 箱計画の欄は今までどおり初期値に戻る

### Requirement: 保存値を読むまで初期値を見せない
システムは、イベントページの交換所タブの画面で、端末の保存値から出す表示を、その保存値を読み終えるまで初期値（0、空、既定の選択）で表示してはならず (SHALL NOT)、読み込み中であることが分かる表示にしなければならない (SHALL)。対象は、周回計算の欄（交換回数・所持数・ボーナス・ボーナス礼装の ☆ ごとの入力・フレンドの礼装・比較の表で選んだ行）とそこから出す必要量・周回の内訳・合計・ボーナス礼装の比較、品目の「欲しい／いらない」の設定（`item-want-setting`。「いらない」の行を一覧から外して畳むことを含む）、育成計画と所持数から出す品目の状態、AP 予算のマスターレベル・黄金の果実の所持数とそこから出す内訳とする。保存値を読み終えたら、保存値（保存値の無い欄は今までどおりの初期値）で表示しなければならない (SHALL)。読み込み中は、利用者が欄を変えられてはならない (SHALL NOT)。保存値を読むことで端末に書き込んではならず (SHALL NOT)、「開いただけでは書き込まない」の決まりは読み込み中の表示があっても変わらない。サーヴァント扱いの品目だけの交換所の一覧のように、端末の保存値から出す表示の無い部分は、読み込みを待たずに表示してよい。

#### Scenario: 読み込み直しても 0 が見えない
- **WHEN** 利用者が 80632 の交換所で、ある品目の交換回数に 3、ある通貨の所持数に 200、その通貨のボーナスに 2 を入れてから、ページを読み込み直したとき
- **THEN** 保存値を読み終えるまで、その品目の交換回数・その通貨の所持数・ボーナス・必要量・周回の内訳は 0 として表示されず、読み込み中の表示になる
- **THEN** 保存値を読み終えると、交換回数は 3、所持数は 200、ボーナスは 2 で表示され、必要量と周回の内訳はそれらの値で表示される

#### Scenario: 保存値の無い端末
- **WHEN** 利用者が一度も値を入れたことのないイベントの交換所を開いたとき
- **THEN** 保存値を読み終えるまでは読み込み中の表示になり、読み終えると交換回数・所持数・ボーナスは 0 で表示される
- **THEN** そのイベントの交換所の入力は端末に書き込まれていない

#### Scenario: 育成計画と AP 予算も初期値を見せない
- **WHEN** 育成計画を設定し、マスターレベルと黄金の果実の所持数を入れたことのある利用者が、交換所のページを読み込み直したとき
- **THEN** 保存値を読み終えるまで、未設定のときの「育成対象を設定」のリンク、既定のマスターレベル、黄金の果実の 0 は表示されず、読み込み中の表示になる
- **THEN** 保存値を読み終えると、育成計画から出す品目の状態と、入れたマスターレベル・黄金の果実の所持数で表示される

#### Scenario: 読み込み中は入力で保存値を上書きしない
- **WHEN** 交換所の保存値を読み終える前に、利用者が交換所を操作しようとしたとき
- **THEN** 交換回数・所持数・ボーナスの欄は変えられず、保存値は読み込み前の値のまま残り、読み終えると保存値で表示される

#### Scenario: いらない品目を読み込み前に見せない
- **WHEN** 聖杯を「いらない」にしている利用者が、交換所のページを読み込み直したとき
- **THEN** 設定を読み終えるまで、聖杯の行が入力欄つきで一覧に出ることはなく、読み終えると聖杯は表の最後の「いらない品目」に畳まれている
