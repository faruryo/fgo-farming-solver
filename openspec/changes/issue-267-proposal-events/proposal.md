## Why

ボックス（ロト）のあるイベントのページでは、交換所の計算が箱計画の中の簡易な配分でしか動かない。この配分は交換所の品目の対価の通貨を見ずに、交換の対価をすべて箱を開ける通貨の必要量へ足すので、対価が別の通貨の交換所では周回数が誤る。ロトの無い交換所イベントには通貨ごとの交換所の計算（`EventShopList`）があるが、ボックスのあるイベントでは出ない（#267 の提案3）。また、イベントページの不足はサーヴァントの育成だけから出していて、育成計算機が足しているクラススコアの必要分が入らない。交換所の「足りない分だけ」とボックス計画の不足は、料理作成と違ってヘッダーの周回目的に追従しない（#267 の提案2）。

オーナーの決定（2026-11-16、#267 のコメント）: ボックスと交換所はタブを分けるなどしてしっかり分ける（上下に並べる案は採らない）。交換所の「足りない分だけ」とボックス計画の不足は、ヘッダーの周回目的に追従する。周回ポイントのシミュレータも要るが今回は作らない。

## What Changes

- イベントページの機能を、ヘッダーの下のタブ（「ボックス」「交換所」「料理作成」）に分ける。イベントが持つ機能のタブだけを出す。タブが1つしか無いイベントでは、タブの列を出さずに今の見出しのまま出す
- ボックスのあるイベントにも、交換所のタブとして、ロトの無い交換所イベントと同じ交換所の計算（`EventShopList`）を出す
- ボックス計画の中の簡易な交換所配分を外す。ボックス計画は箱の確定報酬と周回だけで計算し、結果の「交換所」の行、交換所の在庫上限の警告、「欲しい素材指定」の交換所の品目をなくす。交換所の計算は交換所のタブに一本化する
- 両方のタブがあるイベントは「ボックス」を開いた状態で表示し、開いたタブは URL のクエリに残す。タブを切り替えても、画面を開いている間はそれぞれのタブの入力を消さない
- イベントページの不足（ボックス計画の「育成ロスター」、交換所の品目ごとの要る・要らないと「足りない分だけ」、料理作成）に、クラススコアの目標の必要分を足す。サーヴァントの育成対象が無くてもクラススコアの目標があれば不足を出す
- 交換所の「足りない分だけ」と品目のラベル、ボックス計画の不足を、ヘッダーの周回目的に追従させる。「新規サーヴァントに備える」では料理作成と同じ実効不足（育成必要数と在庫基準の大きい方 − 所持数）を使う。「素材全体の効率を見る」では「今の育成」で計算し、そう注記する。不足を出す欄の近くに周回目的の表示を置く
- タブは機能の一覧から作り、あとから「ポイント」のタブ（#137 の周回ポイント）を足せる形にする。今回は作らない
- 交換所の各 capability の「ロトの無い交換所イベントの交換所」を「イベントページの交換所タブ」に読み替える

## Capabilities

### New Capabilities

- （なし）

### Modified Capabilities

- `event-planner`: イベントページのセクションをタブに分け、ボックスのあるイベントにも交換所のタブを出す。ボックス計画から交換所の配分を外し、不足にクラススコアと周回目的を反映する。
- `event-shop-roster-need`: 交換所タブの不足にクラススコアの必要分と周回目的を反映し、ボックスのあるイベントの交換所タブにも当てる。
- `event-shop-ap-budget`・`event-shop-efficiency`・`event-shop-remaining-import`・`event-shop-saved-inputs`・`event-shop-single-list`・`event-drop-bonus`・`event-shop-servant-exchange`・`item-want-setting`: 対象を「ロトの無い交換所イベントの交換所」から「イベントページの交換所タブ」へ読み替える（要件の中身は変えない）。
- `event-drop-bonus`: ロトのあるイベントの交換所タブでは、ボーナス礼装の「データの更新前」の表示を出さない。

## Impact

- `app/events/[id]/page.tsx`（交換所の AP 換算値・イベントポイントの品目をボックスのあるイベントでも読む）
- `components/events/EventHubClient.tsx`（タブ）、`components/events/EventPlannerClient.tsx`・`components/events/EventPlanResultCard.tsx`（交換所の配分を外す、周回目的の表示）、`components/events/EventShopList.tsx`（周回目的の表示と不足）
- `lib/event-plan.ts`（`allocateShop` と交換所の配分を使う逆算・育成インパクトの変更）、`hooks/use-roster-need.ts`（クラススコアの必要分）、locales
- KV・取り込み・D1 は変えない

**対象件数**（交換所のタブが新たに出るイベント）: ボックスのあるイベント5件中5件。交換所のタブが外れるイベントは0件。
- 対価の通貨がすべて箱の通貨と違う交換所: 4件（`80429` 風雲からくりイリヤ城、`80455` 雪原のメリー・クリスマス2023、`80549` インドラの大試練 など）。今の簡易な配分では対価を箱の通貨に足して周回数を誤っていた
- 対価がすべて箱の通貨の交換所: 1件（`80586` 最終物資補給作戦）

数えた方法: repo の `mocks/events.json`（取り込みの形の見本、ボックスのあるイベント5件）を、ロトと交換所の有無と、交換所の品目の対価の通貨が箱の通貨と同じかで数えた。本番の KV はこの作業では読まない取り決めのため数えていない。クラススコアと周回目的で不足に加わる素材の数は、利用者の端末の保存値で決まるため数えていない。

## 範囲外

- 周回ポイントのシミュレータ（「ポイント」のタブ）: #137
- ボックスと交換所をまとめた1つの周回計画（同じ通貨を両方で使う `80586` のようなイベントで、2つのタブの周回数を合算すること）
- ボックスのあるイベントのボーナス礼装の ☆ と通貨の対応の取り込み（今は交換所イベントだけ。ボックスのあるイベントの交換所タブでは、通貨ごとの +N の手入力になる）
