## MODIFIED Requirements

### Requirement: 解析結果のレビューと確定
システムは、抽出した所持数候補を一覧表示し、ユーザーが個別に確認・修正・除外したうえで確定操作を行うまで `posession` を更新してはならない (SHALL NOT)。レビュー各行は、編集中の提案値と現在の `posession` 値の差で増加・減少・変更なしに分類し、色・左縁の模様・符号テキストを同時に用いて区別しなければならない (SHALL)。提案値を数値化できない行、および信頼度が低い／矛盾ありの行は、増減分類より要確認として優先表示しなければならない (SHALL)。

#### Scenario: 候補一覧の表示
- **WHEN** 投稿されたスクリーンショットの解析が完了したとき
- **THEN** 認識されたアイテムごとに、アイコン・アイテム名・現在の `posession` 値・抽出された所持数候補が一覧表示される。

#### Scenario: 差分の表示
- **WHEN** 候補一覧が表示されたとき
- **THEN** 各候補は、アイテム名と、現在の `posession` 値から候補値への差分（変更前→変更後）が分かる形で表示される。

#### Scenario: 増加行の視認
- **GIVEN** 要確認ではなく、編集中の提案値が現在の所持数より大きい
- **WHEN** その候補が一覧に表示される
- **THEN** 行は増加として、背景色・実線の左縁・`+N` の符号バッジの3つで減少および変更なしと区別される。
- **THEN** 色だけを手がかりにしなくても増加と分かる。

#### Scenario: 減少行の視認
- **GIVEN** 要確認ではなく、編集中の提案値が現在の所持数より小さい
- **WHEN** その候補が一覧に表示される
- **THEN** 行は減少として、背景色・破線の左縁・`-N` の符号バッジの3つで増加および変更なしと区別される。
- **THEN** 色だけを手がかりにしなくても減少と分かる。
- **THEN** 減少の色は、エラー（確定不可・対応外ファイル）の色と同じにしてはならない (SHALL NOT)。

#### Scenario: 変更なし行の視認
- **GIVEN** 要確認ではなく、編集中の提案値が現在の所持数と等しい
- **WHEN** その候補が一覧に表示される
- **THEN** 行は変更なしとして、増加・減少よりコントラストを落として表示される。
- **THEN** 符号バッジは出さない。

#### Scenario: 要確認は増減より優先する
- **GIVEN** 矛盾あり、見切れのみ、または提案値を数値化できない候補がある
- **WHEN** その候補が一覧に表示される
- **THEN** 行は要確認として扱われ、増加・減少・変更なしのセクションには入らない。
- **THEN** 提案値を数値化できる場合は、要確認の印に加えて符号バッジも表示する。

#### Scenario: 確認優先の既定並び
- **WHEN** 候補一覧が表示されたとき
- **THEN** 行は 要確認 → 増加 → 減少 → 変更なし の順で並ぶ。
- **THEN** 増加同士・減少同士は、絶対変動幅が大きい行が先になる。
- **THEN** 変動幅が同じときは、アイテム名の昇順で安定する。

#### Scenario: 変更なしは折りたためる
- **GIVEN** 変更なしに分類される候補が1件以上ある
- **WHEN** 候補一覧が最初に表示される
- **THEN** 変更なしセクションは折りたたまれ、件数は見える。
- **THEN** 展開すると変更なしの各行を確認できる。
- **THEN** 折りたたんでいても、除外していない変更なし候補は確定時に提案値で上書きされる（値は変わらない）。

#### Scenario: 件数サマリと表示フィルタ
- **WHEN** 候補が1件以上あるレビュー画面が表示される
- **THEN** 要確認・増加・減少・変更なしの件数が一覧の上に表示される。
- **THEN** 表示を「すべて」「変更あり」「要確認」のいずれかに切り替えられる。
- **THEN** 「変更あり」では変更なし行が隠れ、要確認・増加・減少は残る。
- **THEN** 「要確認」では要確認行だけが残る。
- **THEN** フィルタで隠れた行も、除外していなければ確定対象のままである。

#### Scenario: 編集に追従する分類
- **GIVEN** 候補一覧が表示されている
- **WHEN** ユーザーがいずれかの候補値を編集し、増減の分類が変わる
- **THEN** その行の見た目・符号バッジ・所属セクション・並び・件数サマリが、新しい分類に合わせて更新される。

#### Scenario: 認識元クロップ画像のオンデマンド確認
- **GIVEN** 候補一覧に、要確認（信頼度が低い／矛盾あり／数量未確定）の候補がある
- **WHEN** ユーザーがその候補を展開操作したとき
- **THEN** その候補の抽出元となった元画像のクロップ（カード領域）が表示され、光学文字認識の結果と元画像を見比べて確認できる。
- **THEN** 要確認ではない候補では、クロップ画像は既定で表示されない。

#### Scenario: 候補値の個別修正
- **WHEN** ユーザーが一覧上のいずれかの候補値を編集したとき
- **THEN** 確定時にはユーザーが編集した値が採用される。

#### Scenario: 候補の個別除外
- **WHEN** ユーザーが一覧上のいずれかの候補を除外操作したとき
- **THEN** そのアイテムは確定操作の対象から外れ、`posession` の値は変更されない。

#### Scenario: 確定操作
- **WHEN** ユーザーがレビューUIで「反映する」を選択したとき
- **THEN** 除外されていない各候補の値で `localStorage['posession']`（Atlas ID キー）が上書きされる。
- **THEN** レビューUIは閉じ、通常の所持数編集 UI の表示にも即時反映される。

#### Scenario: キャンセル
- **WHEN** ユーザーがレビューUIで「反映する」を選択せずに閉じたとき
- **THEN** `posession` はいかなる変更も受けない。

#### Scenario: 認識結果ゼロ件
- **WHEN** 投稿されたすべてのスクリーンショットからアイテム候補が1件も抽出されなかったとき
- **THEN** レビューUIは「認識できたアイテムがありません」と表示し、確定操作は無効化される。
