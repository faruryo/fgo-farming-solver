# Proposal

## Why

#130（#170 の仕様、PR #187）で、手で入れたドロップ増加礼装のボーナス（「1ドロップにつき +N」）を、ロトの無い交換所イベントの周回数と AP に反映した。箱のあるイベントの箱計画は対象外とし（オーナーの判断、2026-10-26）、素のドロップ統計で解いたままなので、ボーナス礼装を編成して箱を開ける利用者には、実際より多い周回数と AP が出る（issue #173）。

## What Changes

- 箱のあるイベントの箱計画の入力の欄に、交換所と同じ見出し（「ドロップ増加礼装」）と値の扱いで、箱計画用の説明の1行を添えたボーナスの入力（「1ドロップにつき +N」）を足す。対象は箱を開ける通貨だけにする。箱計画の周回の計算は箱を開ける通貨だけを集める量として解き、交換所の配分に要る通貨も対価の品目を区別せず箱の通貨の量に足すので、交換所の対価の通貨のボーナスは結果に効かない（issue の「通貨ごと」は、結果に効く通貨ごととして読む）
- 入れたボーナスを、箱計画の周回の計算（箱を開けるのに要る周回数・合計 AP・AP 予算）に反映する。入力モード（育成ロスター・箱数・欲しいアイテム）によらず同じ値で解く
- 入力は交換所と同じ持ち方にする。同じ形（通貨の品目 → +N）の値を、画面を開いている間だけ持ち、保存しない。入力の部品と、ボーナスをドロップ率に足す関数は交換所と共用する
- 1周あたりのドロップ回数を持たないドロップ（取り込み直す前のデータ）には足さず、反映できない通貨を表示する。ドロップの統計が無く、1周あたりの獲得数を手で入れる箱計画では、ボーナスの入力を出さない
- ボーナスがすべて0のときは、今の箱計画と同じ結果を出す

## Capabilities

### New Capabilities
（なし）

### Modified Capabilities
- `event-drop-bonus`: 箱のあるイベントの箱計画でも、箱を開ける通貨のボーナスを入れて、箱を開けるのに要る周回数と AP に反映する要件を足す。既存の交換所の要件は変えない（`event-planner` は未 archive の change `issue-127-bug-events` が持つ capability なので、箱計画の側の要件もこの capability に足す）

## Impact

- `components/events/EventPlannerClient.tsx`（ボーナスの入力、ボーナス込みのイベントを周回の計算に渡す）
- `components/events/EventShopList.tsx`（ボーナスの入力の部品を共用できる場所へ出す。交換所の振る舞いは変えない）
- `components/events/EventPlanResultCard.tsx` は変えない（注記は計算結果のカードの直下に出す）
- `lib/event-plan.ts` の `applyDropBonus` はそのまま使う
- `locales` の events の文言（箱計画用の説明の1行と注記）
- データの取り込みと KV は変えない
