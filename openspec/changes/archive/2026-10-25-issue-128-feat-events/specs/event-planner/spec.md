## ADDED Requirements

### Requirement: ロトの無い交換所イベントの周回計画
システムは、ロトが無く交換所のあるイベントのイベントページで、交換所の品目ごとに交換する回数を選べなければならない (SHALL)。回数の初期値は0とし、在庫上限のある品目は上限を超えて選べてはならない (SHALL NOT)。在庫上限のある品目をすべて上限まで選ぶ操作を通貨ごとに提供しなければならない (SHALL)。在庫上限の無い品目は、利用者が回数を入れたときだけ数える (SHALL)。

システムは、通貨ごとに所持数を入れられなければならず (SHALL)、通貨ごとの必要量を「選んだ交換の対価の合計 − 所持数（0未満は0）」として表示しなければならない (SHALL)。必要量が1以上の通貨があり、イベントの周回クエストにドロップの統計があるとき、システムは通貨ごとの必要量をすべて満たす AP 最小の周回の内訳を、既存のソルバーで1回に求めて表示しなければならない (SHALL)。1周で複数の通貨が落ちるクエストは、それぞれの通貨の必要量に同時に効くものとして扱わなければならない (SHALL)。表示は、クエストごとの周回数、合計の周回数と AP、必要量が1以上の通貨ごとの見込み獲得量とする (SHALL)。必要量が1以上の通貨のうち、どの周回クエストのドロップの統計にも現れないものがあるときは、その通貨名と、周回では集められないことを示さなければならず (SHALL)、その通貨を満たしたかのような周回の内訳として示してはならない (SHALL NOT)。ドロップの統計にイベントのボーナス（礼装・サーヴァント）が含まれないことを、周回の内訳の近くに示さなければならない (SHALL)。

周回クエストにドロップの統計が無いときは、周回の内訳を出さず、ドロップの統計が無いため周回を出せないことを示さなければならない (SHALL)。選んだ交換が無い、または所持数で足りるときは、周回は不要であることを示さなければならない (SHALL)。箱のあるイベントのボックス計画の算出結果は、同一の入力に対して変わってはならない (SHALL NOT)。交換所の一覧の既存の表示（通貨ごとの全交換の合計、上限なしの表示、通貨名が無いときの ID の見出し）は保たなければならない (SHALL)。

#### Scenario: 1種類の通貨の交換を選ぶ
- **WHEN** 80632 で、武蔵うどんを対価にする品目を合計1,200個分選び、武蔵うどんの所持数を200と入れる
- **THEN** 武蔵うどんの必要量は1,000と表示され、武蔵うどんを1,000個集める AP 最小の周回の内訳（クエストごとの周回数、合計の周回数と AP）が表示される

#### Scenario: 複数の通貨を同時に集める
- **WHEN** 3種類の通貨それぞれに必要量があり、3種類が同時に落ちる周回クエストがある
- **THEN** 3種類の必要量をすべて満たす周回の内訳が1つ表示され、通貨ごとの見込み獲得量はそれぞれの必要量以上になる

#### Scenario: 上限まで選ぶ
- **WHEN** ある通貨のグループで「上限まで選ぶ」を押す
- **THEN** その通貨で在庫上限のある品目がすべて上限の回数で選ばれ、在庫上限の無い品目は0のままになる

#### Scenario: ドロップの統計が無い
- **WHEN** 交換所はあるが、周回クエストのドロップの統計がまだ無いイベントで交換を選ぶ
- **THEN** 通貨ごとの必要量は表示され、周回の内訳の代わりに、ドロップの統計が無いため周回を出せないことが表示される

#### Scenario: 周回では落ちない通貨がある
- **WHEN** 必要量のある通貨のうち1種類が、どの周回クエストのドロップの統計にも現れない
- **THEN** その通貨名と、周回では集められないことが表示され、ほかの通貨の周回の内訳はその通貨を除いた必要量で表示される。必要量のある通貨がすべてそうなら、周回の内訳は出さない

#### Scenario: 所持数で足りる
- **WHEN** 選んだ交換の対価の合計が、どの通貨も所持数以下である
- **THEN** 周回は不要であることが表示される
