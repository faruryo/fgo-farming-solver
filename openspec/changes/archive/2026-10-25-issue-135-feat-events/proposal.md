# Proposal

## Why

#128（実装 PR #162）で、ロトの無い交換所イベントでは品目ごとに交換する回数を選べるようになった。ただ、品目は元の順に並ぶだけで、どの品目から交換すると得か、どこで止めればよいかは分からない（issue #135、epic #129 の B1）。全部を交換しきるのは大変なので、どこで止めるかを判断できるようにしたい。#131 の調査で、素材の AP 換算値は既存の計算でドロップ表から出せることが分かり、2026-10-24 にオーナーが並べ方の方針を決めた（同日 17:01 のコメントで、欲しい／要らないの切り替えは作らないと変更）。

## What Changes

- ロトの無い交換所イベントの交換所で、AP 換算値のある品目（フリクエで落ちる素材）に、通貨1個あたりの価値（1回の交換で得る個数 × 素材の AP 換算値 ÷ 1回の対価）を「効率」として出し、通貨ごとのカードの中で効率の高い順に順位を付けて並べる
- 効率順の並びに「ここまで交換すれば効率が良い」区切りを出す。区切りは、その通貨1個をイベントの周回で集めるのに要る AP（通貨ごとに AP を分けない）を効率が下回る位置に置く
- AP 換算値の無い品目（伝承結晶・サーヴァントコイン・礼装・QP など）は、効率順の品目の前に交換所の元の順で並べる（最初に交換することが多いため）。区切りの線は効率順の品目の中に引く。欲しいか要らないかは、#128 の品目ごとの交換回数（0 なら要らない、1以上なら欲しい）で表し、別の切り替えは作らない
- 品目ごとの交換回数の入力・所持数・周回の内訳など #128 の表示と動きは変えない。並べ方は交換回数を変えない

## Capabilities

### New Capabilities
- `event-shop-efficiency`: ロトの無い交換所イベントの交換所の品目を、素材の AP 換算値による効率の順に通貨ごとに並べ、ここまで交換すれば効率が良い区切りを示す

### Modified Capabilities
（なし）

## Impact

- 前提: #128 の実装 PR #162 がマージ済みであること。画面は #162 の `components/events/EventShopList.tsx` と `EventHubClient.tsx` の上に乗る
- `app/events/[id]/page.tsx`（ロトの無い交換所イベントのときだけドロップ表を読み、交換所の品目の AP 換算値を渡す）
- 新しい純粋関数（品目の効率・並び・区切り）と、そのユニットテスト
- `components/events/EventShopList.tsx`（並べ方・効率・区切り）、`EventHubClient.tsx`（AP 換算値の受け渡しと、交換所だけのイベントの判定を共通の関数に置き換える）
- `locales` の events の文言
