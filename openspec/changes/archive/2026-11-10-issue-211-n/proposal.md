# Proposal

## Why

交換所の周回計算の一覧では、育成に足りない品目（「あと N 個」）が効率の順に紛れて並び、上から探さないと見つからない。「あと N 個」は交換所の残りとも読めるうえ、同じ行の赤い「交換所では N 個足りない」と並んで、何の数かを読み違えやすい。#225（PR #239）で交換所が1つの一覧になってから、通貨の所持数の入力は一覧の上、その通貨の選んだ交換と必要量は一覧の下に分かれ、何の所持数かが分かりにくい。判定が「足りている」「使わない」の行は、#218 で回数を入れられるようになっても薄い文字色のままになる。オーナーが 2026-11-10 に判断点A を A1、判断点B を B1 と決めた（#211 のコメント）。

## What Changes

- 品目の行から「交換所では N 個足りない」を消す。一覧の一番上の要約（「育成計画の不足 N 素材のうち、交換所で埋まるのは M 素材」）は残す
- 「あと N 個」を「育成にあと N 個」にする
- 「欲しい」の行を、判定が「育成にあと N 個」の行（上のグループ）と、それ以外の行（下のグループ）に分けて並べる。「効率順」「AP 換算なし」の見出しを出す決まりはグループごとに当て、グループの中の並びと順位の番号は今のまま。育成計画が使えないときは分けない
- 通貨ごとの所持数の入力を、一覧の上の段から一覧の下の通貨ごとのカードへ移す。カードの中は「所持数・選んだ交換・必要量」、その下に「全交換 N ＋上限なし N 品目」の順にし、一覧の上の「所持数」の段はなくす
- 判定が「足りている」「使わない」の行でも、交換回数が 1 以上なら薄い文字色にしない
- 「いらない」に切り替えたあとのフォーカスの「すぐ後の行」「すぐ前の行」は、上下のグループに分けた新しい並びで決める

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `event-shop-roster-need`: 「欲しい品目の要る・要らない」のラベルの文言を「育成にあと N 個」にし、回数の入った行を薄くしない決まりを足す。「交換所で埋まらない不足」から品目の行の「交換所では N 個足りない」をなくし、要約だけにする
- `event-shop-efficiency`: 「効率順の1つの一覧」の並びを、不足のある行の上のグループとそれ以外の下のグループに分け、見出しの決まりをグループごとに当てる
- `event-shop-single-list`: 「通貨ごとの所持数と必要量を品目の一覧の上と下に出す」を「通貨ごとの所持数と必要量を品目の一覧の下のカードに出す」に改名し、所持数の入力も一覧の下の通貨ごとのカードに出す決まりに改める。「交換所の品目を1つの一覧で並べる」と「複数の通貨で交換できる品目を1行にまとめる」から、品目の行（まとめた行を含む）に「交換所では N 個足りない」を出す決まりを外す。Purpose の同じ記述も直す
- `event-shop-servant-exchange`: 「品目がすべてサーヴァント扱いの交換所の一覧」が優先する要件の名前を、`event-shop-single-list` の改名後の名前（「通貨ごとの所持数と必要量を品目の一覧の下のカードに出す」）に揃える。振る舞いは変えない
- `item-want-setting`: 「交換所で切り替えたあとのフォーカスの移し先」の「すぐ後の行」を、グループに分けた並びで決める

## Impact

- `components/events/EventShopList.tsx`: 品目の行のラベル（`RowPlanLabel`）、行の文字色（`ShopRow`）、一覧の並びと見出し（`ShopTable`）、フォーカスの移し先の並び（`useFocusAfterWantedMove`）、所持数の入力（`OwnedInputs`）と通貨ごとのカード（`CurrencyNeeds`）
- `locales/ja.json`・`locales/en.json`: 「育成にあと N 個」の文言。使わなくなる「交換所では N 個足りない」のキー
- テスト: `components/events/EventHubClient.test.tsx`・`components/events/EventShopList.test.tsx` の文言・所持数の入力の場所・並びの検査
- 保存値（所持数・交換回数・欲しい／いらない）、必要量・交換回数・周回数の計算、効率の数値と順位の付け方、一番上の要約の数え方は変えない。対象になるデータの条件を変えない（並びと見た目だけの変更）ので件数は数えない
