# Proposal

## Why

イベントの交換所（例: /events/80632）で交換回数・所持数・ボーナスを入れてからページを読み込み直すと、保存した値が戻る前に一瞬だけ欄と必要量・周回の内訳がすべて 0 で表示される（#224）。#222 で交換所の入力を端末に保存するようにしてから目立つようになった。端末の保存値を読む共通の仕組みが、読む前の初期値をそのまま描いているためで、保存値を読むまでは 0 を見せないようにする。

## What Changes

- 端末の保存値を読む共通の仕組みが、保存値を読み終えたかどうかを呼び出し側に返すようにする。今の呼び出し側の振る舞いは変えない
- 交換所の画面で端末の保存値から出す表示（周回計算の欄と必要量・周回の内訳・合計・ボーナス礼装の比較、品目の「要る」、育成計画と所持数から出す品目の状態、AP 予算のマスターレベル・黄金の果実と内訳）は、保存値を読み終えるまで読み込み中の表示にし、初期値（0 や既定の選択）を見せない。読み終えたら保存値で表示する
- 読み込み中は欄を出さないので、保存値を読む前に利用者の入力で保存値を上書きすることはない。「開いただけでは書き込まない」の決まりは変えない
- 育成計画の総必要数を出す共通の仕組みは、育成計画の保存値を読み終えるまで「未設定」ではなく「まだ読んでいない」を返す。同じ /events/[id] の料理作成は、これを読み込み中として扱い、育成計画の未設定の案内が一瞬出るのも直る。ロト計画は今までどおり未設定と同じに扱い、振る舞いを変えない。AP 予算の欄はロト計画と共通の部品なので、ロト計画の AP 予算の欄も同じく直る
- 交換所以外で同じ症状が見える画面（/todo、/farming など7ルート、design.md の Context）は、この change では直さない

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `event-shop-saved-inputs`: 交換所の画面で、端末の保存値を読み終えるまで保存値から出す表示に初期値を見せない要件を足す

## Impact

- `hooks/use-local-storage.ts` の `useLocalStorage` の返り値に、保存値を読み終えたかを足す（既存の呼び出し側は今の2つの要素だけを使うので変えなくてよい）
- `components/events/EventShopList.tsx` の周回計算と品目の表を、読み終えるまで読み込み中の表示にする
- `components/events/ApBudget.tsx` の AP 予算の欄と内訳を、読み終えるまで読み込み中の表示にする（ロト計画も同じ部品）
- `hooks/use-roster-need.ts` が、育成計画の保存値を読み終えるまで新しい状態「まだ読んでいない」を返す（交換所・ロト計画・料理作成が使う。`components/events/EventPlannerClient.tsx` と `components/events/EventCraftSection.tsx` にその扱いを足す）
- 保存のキー・保存値の形・クラウド同期・API・計算の結果・文言は変えない
