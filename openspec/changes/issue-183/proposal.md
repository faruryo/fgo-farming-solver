# Proposal

## Why

絆トラッカーは、リザルト画面で見た1周の獲得絆から残り周回数を見積もるが、どの絆礼装を付けると獲得絆が増えるかは示さない。絆礼装の倍率・固定値・対象とコストを手で調べて組み合わせを考える手間を省くため、選んだサーヴァントの1周の獲得絆の合計が最も大きくなる絆礼装の組み合わせを提案する（#183、方針は issue の材料コメント issuecomment-6435122839）。

## What Changes

- 絆トラッカーに「礼装の提案」を足す。登録済みのサーヴァントから最大5体と周回クエストを選ぶと、マスターレベルのコスト上限に収まる範囲で、1周の獲得絆の合計が最大になる絆礼装の組み合わせと、どのサーヴァントに付けるかを示す
- 候補は所持に関係なく、イベント限定でないすべての絆礼装とする。同じ礼装は1枚までとし、同じ効果とコストを持つ別の礼装を言い換えの候補として並べる
- マスターレベルから編成コストの上限を導く
- Material Catalog に、サーヴァントのコストと、絆礼装の一覧（効果・対象・コスト）を足す

## Capabilities

### New Capabilities

なし

### Modified Capabilities

- `bond-tracker`: 絆礼装の組み合わせを提案する要件を足す
- `master-profile`: マスターレベルから編成コストの上限を導く要件を足す
- `material-catalog`: サーヴァントのコストと絆礼装の一覧を蒸留し、項目が欠けた既存カタログから取り直す要件を足す・変える

## Impact

- 画面: `/bond` に提案の表示を足す（ja/en の文言）
- データ: Material Catalog の更新ジョブが Atlas Academy の `nice_equip.json` も条件付きで取得する。カタログのキーとスキーマバージョンは変えない
- 既存の見積もり（残り周回数・必要AP・到達見込み）は変えない
