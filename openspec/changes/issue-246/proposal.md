# Proposal

## Why

交換所の周回計算で品目を「いらない」にすると、その行は表から外れて最後の「いらない品目」に移り、押した品目名のボタンが画面から消える。キーボードのフォーカスは行き先を失って body（ページの先頭）に落ち、キーボードやスクリーンリーダーで操作している人はどこにいたか分からなくなる。「いらない品目」から「欲しい」に戻したときも、押した名前が消えて同じことが起きる。#245（#242）のマージ判断で、オーナーがこの行き先を別 issue で決めると決めた（#246）。

## What Changes

- 交換所で品目を「いらない」にしたあと、フォーカスを、表でその行の次にあった「欲しい」の行の品目名へ移す。次の行が無ければ前の行の品目名、表に「欲しい」の行が残らなければ畳んだ「いらない品目」の見出しへ移す
- 「いらない品目」から「欲しい」に戻したあと、フォーカスを、表に戻った行の品目名へ移す。最後の1件を戻して「いらない品目」の畳みそのものが消えるときも同じ
- ポップアップで今と同じ設定を選んだとき（行が動かないとき）と、選ばずに閉じたときは、今までどおり押した品目名へフォーカスを戻す
- アイテム一覧（/items）は、切り替えても行が消えないので変えない

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `item-want-setting`: 交換所で「欲しい／いらない」を切り替えて行が表と「いらない品目」の間を動いたときの、キーボードのフォーカスの移し先の要件を足す

## Impact

- `components/events/EventShopList.tsx`: 品目名のポップアップ（`ItemWantPopover`）、表（`ShopTable`）、畳んだ「いらない品目」（`UnwantedRows`）。切り替えた行の行き先を覚え、行が動いて描き直したあとにその品目名（または見出し）へフォーカスを移す
- テスト: `components/events/EventShopList.test.tsx` か `components/events/EventHubClient.test.tsx` に、3つの場合の行き先の検査を足す
- データ・保存値・計算は変えない（対象になるデータの条件を変えないので件数は数えない）
